# 컨셉 이미지

구조·사용 장면을 그림으로 설명하는 것이 도움이 되거나 사용자가 요청한 경우 적용한다. 모든 결과에 이미지를 강제하지 않는다.

현재 실행 환경에서 실제 호출 가능한 이미지 생성 Tool·Skill·플러그인이 있는지 확인하고 해당 지침에 따라 사용한다. Skill 파일 발견이나 프롬프트 작성은 이미지 생성 성공이 아니다. Codex와 Claude는 공통 작성 기준을 사용하며 각 환경의 이미지 기능 가용성을 따로 확인한다. 자체 LLM·이미지 API, 인증키, 전역 플러그인이나 서버를 추가하지 않는다.

이번 기획의 불편·실제 사용 상황·제안 기능·사용자 행동·확인한 제품 조건·필요한 시점을 전달한다. 확인되지 않은 외형·치수·효과 수치나 제조사 로고를 꾸며 넣지 않는다. 실제 제공된 사진을 편집하면 출처와 참조 범위를 보존한다. 생성 이미지는 기획 설명이며 제조 완료·실제 제품 사진·효과 시험으로 설명하지 않는다.

Tool이 만든 실제 파일을 runtime-data/report-assets에 보관하고 열어 본문과 기능·동작·형태가 맞는지 검토한다. 의미를 바꾸는 오류는 해당 Tool로 수정한다. report_plan의 image 블록에 실제 path, 짧은 caption, source_ids 및 `generated:true`와 provenance(실제 도구/생성 기록/참조 출처)를 기록한다. 제공된 사진은 generated:false와 실제 출처를 유지한다. 렌더러는 파일을 삽입하고 생성 호출을 대신하지 않는다. 도표·코드 그림을 생성형 컨셉 이미지라고 부르지 않는다.

사용자가 이미지를 요청했지만 Tool이 없거나 실제 생성이 실패했으면 다른 자료집·보고서는 마치고 unfulfilled_requests에 해당 요청 문구와 관측한 이유만 남긴다. 이미지 요청이 없으면 기능 부재 안내·질문을 새로 넣지 않는다.
