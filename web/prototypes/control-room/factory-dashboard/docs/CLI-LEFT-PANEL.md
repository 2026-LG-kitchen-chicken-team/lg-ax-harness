# 왼쪽 CLI 작업 소식

기존 하네스 관찰 화면에 짧은 한국어 작업 창을 추가한다. 현재 작업 한 문장, 확인된 실행 중 Skill, 최근 작업 최대 3개를 표시한다. 코드·명령 본문·URL·로컬 경로는 이 창에 출력하지 않는다. 상세 기록은 기존 검사 패널로 연결한다.

실제 기록·연결 대기·연결 지연·모의 실행을 구분한다. 지침 조회나 CLI의 진행 보고만으로 Skill을 실행 중이라고 표시하지 않는다. 종료 결과 미확인·실패·취소도 성공으로 바꾸지 않는다. 같은 native 호출이 최근 작업과 호출 목록에 함께 존재할 때 한 번만 표시한다.

## 실제 확인: 2026-10-17

- 기존 하네스 URL의 읽기 서버에 통합본을 연결했다. 현재 대화의 실제 Codex rollout을 정상 관찰 프로그램으로 따라갔다. 화면 표시를 위해 가짜 사건이나 지연을 넣지 않았다.
- 설치된 venv Python으로 `evidence-retrieval/retrieve_reviews`와 `feature-comparison/retrieve_product_facts`를 직접 실행했다. 별도 검증 SQLite를 사용해 기존 기획 요청과 결과는 변경하지 않았다.
- 실제 등록 자료에서 B502S33 후기 발췌 10개와 공식 자료 4개를 조회했다. 두 명령 모두 exit 0이었다. 이는 저장 자료 조회 검증이며 새 웹 조사나 상품기획 완료, 독립 고객 수·자료 의미 품질의 인증이 아니다.
- 로컬 API를 250ms 간격으로 표본 관찰해 두 호출의 `running → completed` 전이를 실제 수신했다. 브라우저의 기존 하네스 화면에서도 왼쪽 창과 공식 자료 조회 완료 문장을 확인했다.
- 실제 Windows 로그의 `file:///C:/...` cwd를 처리하고 같은 시작·종료 호출을 연결하도록 보완했다. 원격 file 호스트·query·작업 폴더 밖 경로는 거절한다.

짧은 명령은 브라우저의 첫 조회 전에 종료될 수 있다. 그 경우 완료 이력을 표시하며 이미 끝난 작업의 실행 모션을 억지로 재생하지 않는다. 실제 명령의 연구원 움직임을 연속 영상으로 검증한 것은 아니다. 단일 file HTML과 로컬 native 읽기 서버의 관측 범위도 동일하다고 가정하지 않는다.

프런트엔드 전체 163개 검사와 Python native 관측 27개 검사를 통과했다. 이후 짧은 문장·중복 처리 보완은 해당 프런트엔드 검사로 재확인하며, 운영 화면 검증은 모의 동작과 별도로 위 범위만 주장한다.
