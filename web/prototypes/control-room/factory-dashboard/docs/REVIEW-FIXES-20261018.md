# 실제 Skill·병렬 실행 관측 보완

대상은 [최길웅의 실제 CLI 검사 보고](https://github.com/2026-LG-kitchen-chicken-team/lg-ax-harness/pull/27#issuecomment-6237442527)다. 최신 main `c4b5531`에서 시작해 PR #28과 기획자 화면 변경을 보존한다. 원본 연구원·배경 PNG, 여섯 Skill·선택 역할, 저장·기록·재생 기능과 업무 로직은 유지한다. 공개 Site나 다른 저장소, 사용자 CLI 설정은 변경하지 않는다.

## 변경

| 보고 항목 | 구현 |
|---|---|
| 11·13 병렬 | Bash의 백그라운드 접수 응답을 완료로 세지 않는다. 실제 task ID의 종료 알림·TaskOutput 결과와 대조해 각 호출을 독립적으로 닫는다. 서버·파일 보기·재생 막대가 같은 수명을 사용한다. |
| 17 실제 Skill | Python 진입점과 작업 이름을 검사한다. echo 안의 경로, Python 코드 문자열, 비실행 셸 옵션을 Skill 실행으로 승격하지 않는다. 여러 실행문을 묶은 셸은 단계별 시작 정보가 없으므로 여러 Skill을 동시에 켜지 않는다. |
| 18 승인 대기 | PermissionRequest 또는 permission_prompt 기록을 별도로 표시하고 해당 작업의 모션을 멈춘다. 명시 호출 ID를 우선 대조해 다른 병렬 명령은 계속 표시하며, ID가 없으면 같은 실행 주체·도구의 유일한 대기 호출만 연결한다. CLI에서 허용/거절할 것을 안내한다. 관찰기는 승인 결정을 출력하거나 권한을 바꾸지 않는다. |
| 19 취소·보류 | 관측된 interrupt·native 취소, 보류된 저장 결과, 자료 unavailable을 완료와 구분한다. 취소 표시는 OS 프로세스 종료 인증이 아니다. |
| 25 결과 | 실제 호출의 반환 IDs 또는 호출 전에 존재한 명시 입력 파일의 turn ID와 해당 DB 행을 대조한다. 같은 session/turn/request triple과 result version의 viewer delivery만 로컬 결과 화면으로 연다. 다른 최신 결과를 대신 붙이지 않는다. |
| 26 재생 | 작은 작업 소식도 재생 모드를 표시한다. 재생 슬라이더와 재생 화면에서 Home/End를 지원한다. |
| 28 이름표 | 대기·완료·취소·승인 대기·확인 필요를 초록 이름표 안에 표시한다. 실행 강조와 선택 상태는 별개다. |
| 30 작은 화면 | 메뉴가 열렸을 때 작업 펼침 버튼이 연구원을 가리지 않게 하고, 열린 상세와 하단 제어의 공간을 함께 확보한다. 최신 main의 기본 닫힌 패널 구성을 보존한다. |

짧은 명령의 실제 상태·조명·연구원은 종료 사건에 즉시 맞춘다. 확대된 공간의 배치만 최대 800ms 유지해 반복 축소·카메라 재배치를 줄인다. 05번 확대 시 중앙 AI와 간격을 확보하고 이미지의 일시 로딩 실패를 제한적으로 재시도한다. 읽기 서버 재시작의 새 조회 키는 같은 출처의 로컬 UI에서만 메모리로 갱신한다.

설치 파일의 경로·재분석 지점을 매번 검사하며, 동일 설치 기록과 파일 크기·수정/생성 시각·파일 ID가 같은 경우 해시 읽기를 재사용한다. 최대 30초 후 전체 해시를 다시 확인한다. native Claude 기록과 명시 DB 조회도 변경 지문으로 캐시한다. CPU 절감률은 측정한 값이 아니므로 주장하지 않는다.

## 데이터·접근 경계

Claude 보완 읽기는 관찰기가 고른 session의 public tool-use/result와 같은 작업 폴더의 cwd를 확인한다. 명령·출력·질문·추론 원문은 응답이나 Git에 추가하지 않는다. 일치하는 호출이 없는 native 기록을 새 업무로 붙이지 않는다. 업무 DB는 명시 IDs에 해당하는 행을 읽기 전용으로 확인하며 수정하지 않는다.

로컬 `/result`는 같은 공장 출처에서 여는 문서 요청만 받는다. public Site의 CORS 읽기는 허용하지 않는다. 설치 기록의 원본 viewer 지문과 현재 delivery를 확인한 뒤 메모리에서 단일 문서를 만들고, JSON의 HTML 문자와 script nonce를 처리한다. 토큰을 URL·디스크·결과 문서에 넣지 않는다.

승인 신호의 의미는 [Claude 공식 훅 문서](https://code.claude.com/docs/en/hooks#permissionrequest)를 따른다. 파일 보기에서 새 승인 기록을 받으려면 새 관찰기 훅 설치가 필요하다. 기존 설치 설정을 이 작업에서 자동 변경하지 않는다. 같은 로컬 읽기 서버는 기존 관찰기의 Claude 명령 판정을 선택된 native 영수증으로 보완할 수 있다.

## 검증과 남은 확인

- Python 합성 훅·native 영수증·읽기 서버·HTTP 접근 경계와 JS 상태/배치/연구원/재생 회귀 검사, 일반·office 빌드, 자산·생성 HTML 검사를 사용한다. 합성 자료의 두 개·세 개 병렬은 실제 모델 실행 증거가 아니다.
- 마지막 실제 사용자 CLI에서 새 업무를 실행하는 검증은 이전 사용자 지시에 따라 **보류**다. 길웅이의 기존 실측을 이번 수정본의 새 실측으로 바꾸지 않는다.
- 임의 helper, 동적 코드, 파이프라인, `sleep && Skill` 같은 복합 명령의 내부 Skill 시작 시각은 제공되지 않는다. 이 경우 일반 명령으로 보이며 임의 병렬 Skill 모션을 만들지 않는다. 실제 독립 Skill 명령의 백그라운드 수명과 구분한다.
- 취소·승인·최종 task 종료 신호가 원본에 없으면 현재 상태를 확정하지 않는다. 오래된 수신은 동작을 멈추고 확인 필요로 남긴다. file 모드는 설치 관찰기가 제공한 사건 범위를 따른다.
- 결과 보기에는 현재 binding·버전의 viewer delivery가 실제로 생성돼 있어야 한다. 없거나 다르면 연결 미확인 안내를 제공한다.
