# 실제 Skill 명령과 현재 작업 표시

후속 통합 검증: 왼쪽 CLI 작업 창을 기존 하네스 URL에 적용하고 실제 저장 자료 조회 두 건의 시작·종료를 관측했다. [왼쪽 창과 실제 확인 범위](CLI-LEFT-PANEL.md)를 최신 결과로 따른다. 아래 마지막 육안 모션 검증의 보류 범위와 실제 CLI 상태 전이 검증은 구분한다.

사용자 요청에 따라 기존 공장 이미지·배치·메뉴·저장 결과·기록 재생을 유지하며 로컬 읽기 연결의 표시를 수정했다. 업무 코드, 설치된 제품 파일, CLI 설정, 원문 로그와 DB는 수정하지 않는다. 마지막 실제 CLI 시연 검증은 사용자의 후속 요청으로 보류했다.

## 변경

- 관찰기가 선택한 동일 작업 폴더·세션·요청의 공개 native Tool 시작과 종료를 읽는다. `exec_command`의 명시적 Python Skill 진입점과 허용된 작업 이름을 대조한다.
- 코드모드의 리터럴 단일 명령과 리터럴 `Promise.all`/`allSettled` 명령 묶음을 지원한다. 조건 분기·동적 변수·임의 helper·명령 문자열 출력은 Skill 실행으로 추정하지 않는다. 지침 조회와 상태 확인 명령도 업무 Skill 실행과 구분한다.
- 확인된 Skill 이름과 작업별 구체적인 문장을 같은 상태에서 헤더·작업 패널·구역 강조·연구원 동작에 전달한다. 웹/브라우저/파일/셸 도구는 확인된 도구 종류로 설명하며 Skill로 승격하지 않는다.
- 여러 Skill 명령이 실제로 열려 있으면 기존 병렬 배치와 각 구역의 서로 다른 연구원 동작을 함께 사용한다. 선택한 노드는 실행 상태를 바꾸지 않는다.
- 명령 종료·실패·취소·오래된 수신은 동작을 멈춘다. 종료 코드가 없는 Tool 응답을 성공으로 인증하지 않는다. 설치 관찰기의 같은 명령 결과가 도착하면 임시 표시 projection을 원래 사건으로 교체하여 중복을 막는다.
- 이전 관찰기가 출력·읽기 명령 속 Skill 경로를 작업으로 분류한 경우, 실제 native 명령 진입점 확인을 우선한다. 원래 기록 파일은 고치지 않는다.
- 로컬 서버 화면의 조회 간격을 300ms로 줄였다. 짧은 명령은 첫 조회 전에 끝날 수 있으며 이때 현재 실행 모션을 억지로 재생하지 않는다. 이미 완료된 명령은 기록으로 보존한다.

## 검증 범위와 제한

Python native 메타데이터 검사와 프런트엔드 상태·배치·동작 검사에서 여섯 Skill, 2·3개 병렬 호출, 지침/행정 명령, 일반 브라우저 작업, 경로 예시, 요청 경계, 중복 제거, 종료·실패·취소·수신 지연을 확인한다. 시험 입력은 합성 메타데이터이며 실제 AI 업무 실행 증거가 아니다.

`file://` 단일 HTML은 기존 설치 관찰기 파일을 읽는다. native 원본을 추가로 읽는 이번 개선은 설정된 로컬 릴리즈 읽기 서버 경로에 적용된다. 원본 관찰기가 시작 사건을 제공하지 않는 file 보기까지 실시간 Skill 시작을 확인했다고 주장하지 않는다.

도우미의 현재 요청 결속은 기존 native ID 규칙을 유지한다. 부모 요청과 연결되지 않은 child는 실행 중인 Skill로 추정하지 않는다. LLM 내부 생각, 제품 문서 속 지시문, 명령 본문, 출력 원문, 인증 정보는 화면 응답이나 Git에 추가하지 않는다.

최종 실제 CLI 실행에서 구역 확대와 연구원 모션을 육안으로 확인하는 검사는 **사용자 요청으로 보류** 상태다. 합성 회귀 검사·빌드·정적 검토와 구분한다.
