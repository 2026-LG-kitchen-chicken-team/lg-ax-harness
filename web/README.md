# 팀원 웹 작업공간

하네스의 실제 근거·제품 대조·기획 결과·실행 이력을 시각적으로 보여줄 팀원 담당 영역이다. **웹 PM은 황대겸 한 명**이며 웹 설계·기술 선택·작업 배분·일정·리뷰·시연 화면을 지휘한다. 팀원과 개발 AI는 [웹 협업 지침](AGENTS.md)을 따른다. 현재는 착수 안내만 존재하며 웹 앱·package.json·서버·실시간 연결은 구현하지 않았다.

[영상 분석·화면·연결·인수 제안](../docs/plans/team-web-workspace.md)을 먼저 읽는다. 기술 후보는 React/TypeScript/Vite와 선택적 ECharts/React Flow이며 아직 채택하지 않았다. Python 위주 팀이라면 Streamlit과 비교한다.

제안하는 첫 범위는 기존 native 실행의 export 파일을 사용자가 선택해 불러오는 로컬 결과 탐색 화면이다. PM이 범위를 검토해 확정한다. 업무 실행은 기존 Codex/Claude Code/Gemini CLI가 담당한다. 화면 새로고침·탭 전환·재생이 새 업무/모델 호출을 만들어서는 안 된다. 실제 시간순 관찰 연결과 웹 질문 실행은 별도 단계다.

- 황대겸 웹 PM: 웹 범위의 우선순위·구조·기술·배정·리뷰·인수 결정. 세부 화면/라이브러리 제안은 PM이 검토해 확정한다.
- 웹 팀원 책임: PM이 배정한 `web/` 안의 화면·컴포넌트·표시용 변환·프런트엔드 검사.
- 메인 하네스 개발 책임: `product-tools/`, `skills/`, 업무/근거 계약·표시용 projection·native ID 연결·observer 통합/실제 인수. 웹 PM과 연결 변경을 조율한다.
- 실제 결과·DB·원문 로그·인증·개인 경로를 저장소/public 자산에 넣지 않는다. 새로운 합성 화면 시험자료는 명시적으로 표시한다.
- 실제 export/observer 스키마와 상태 구분을 먼저 합의한다. 임의의 성공/Agent/Skill 실행/메시지/근거 관계를 화면에서 생성하지 않는다.
- 별도 branch/checkout에서 작업하고 PR로 검토한다. 읽기 전용 권한의 팀원은 fork+PR 가능 여부를 확인한다. 다른 작성자의 변경을 되돌리지 않는다.

화면 원본은 업무에서 저장한 결과이며, 구조 검사 통과·저장 승인·최종 답변 완료·의미 품질 통과는 서로 다른 표시다. 파일을 불러온 첫 버전은 `저장된 실행 결과`로 표시한다.
