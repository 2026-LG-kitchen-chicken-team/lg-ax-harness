# 웹 개발 협업 지침

이 파일은 `web/` 작업에 적용하며 레포 루트 AGENTS.md의 공통 개발·근거·검증 지침을 함께 따른다.

## 책임과 지휘

- 사용자 지정 **웹 PM은 황대겸 한 명**이다. 웹 팀원과 이 영역을 작업하는 개발 AI는 PM이 정한 우선순위·작업 배정·리뷰 기준을 따른다.
- PM이 웹 요구·화면 흐름·프런트엔드 기술 선택·폴더 구조·파일별 책임·작업 순서·일정·리뷰/인수·시연 화면을 결정하고 팀원 작업을 조율한다. 웹 범위에 추가 PM을 두지 않는다.
- 이 지정은 웹 범위에 한정한다. 출품 Agent/Skill·공통 Tool·자료·상태·평가·수집기·출품 실행 방식의 변경은 메인 하네스 개발 작업과 조율한다.
- 메인 개발 AI는 PM의 웹 업무를 임의로 재배정하거나 독자적인 프런트엔드를 병렬 구현하지 않는다. 요청받은 계약·연결 지원과 검토를 수행한다.

## 착수와 실행 경계

1. [착수 안내](README.md)와 [영상·연결 검토](../docs/plans/team-web-workspace.md)를 읽는다. 제안된 화면/라이브러리를 이미 채택된 결정으로 취급하지 않는다.
2. PM이 선택한 첫 범위·기술·담당 파일·검사/완료 조건을 작업 기록/PR에 명시한다. 아래 공통 경계를 유지하는 웹 기술/화면 선택은 PM이 지휘한다.
3. 기존 실행 방식은 Codex 기준·Claude 후순위의 공통 업무 Skill/코드(Gemini 철회)다. 먼저 기존 결과 export를 읽는 화면을 제안한다. 웹 질문 실행·native 내부 호출 실행기·모델 API·공개 서버 운영은 별도 변경으로 메인 개발 작업과 결정한다.
4. 공유 계약·core 코드·의존성 변경이 필요하면 영향과 제안된 입출력/실제 검사 조건을 메인 개발 작업에 전달한다. 화면을 맞추려고 원본 결과·저장 상태·자료를 변경하지 않는다.
5. 팀원별 branch/독립 checkout을 사용하고 PR로 통합한다. 동일 checkout에 여러 작성자를 두지 않는다. 다른 작성자의 변경을 되돌리지 않는다. 저장소 읽기 권한의 변경을 이 문서로 가정하지 않는다.

## 표시와 검증

- 실제 제품·리뷰·근거·결과를 표시한다. 합성 화면 시험자료는 시험용임을 표시하고 실제 업무/효과의 근거로 사용하지 않는다.
- 구조 정의·지침 로딩·명령 매핑·실제 Tool 사건·저장 결과·기록 조회를 구분한다. 관측되지 않은 Agent/Skill 실행·메시지·내부 사고를 만들어내지 않는다.
- 저장 승인·최종 native 답변 완료·구조 통과·의미 품질 통과는 서로 다른 상태다. 보류·거절·오류·무효화·부분 관측을 숨기지 않는다.
- 미측정 사용량은 미측정이며0이 아니다. 캐시/생각 토큰은 각각 입력/출력의 일부이고 누적 snapshot을 합산하지 않는다.
- 새로고침·탭 전환·기록 재생·다운로드는 업무/모델 호출을 만들지 않는다. 관찰·렌더링을 위한 추가 모델 호출·프롬프트·로그 문맥을 넣지 않는다.
- 원문 실행 로그·DB·자격증명·개인 설정/경로를 Git·public 자산에 넣지 않는다. 표시용 데이터와 원문 HTML/링크를 검증한다.
- 완료 보고/PR에는 실제 표시 데이터의 출처·버전, 실행한 검사/exit code, 화면과 원본의 일치, 남은 제약을 기록한다. 목업·계획·코드 검사를 실제 AI 실행/시연 인수로 설명하지 않는다.
