## 판정

실행·최종 전달/저장·독립 의미 검토를 분리한다. 의미7축(목적/제약, 정확 모델/버전, 불편→기능→제안, 출처 의미, 미확인/보류, 최종·저장 정합, 실행/검증 계획)을0–2로 채점한다. 정상 기획은12/14 이상·적용 축0 없음·중대 오류0일 때 통과다. 미선택 모델 등 미적용 축은N/A로 공개하며 적용 점수/가능 점수를 함께 쓴다.

중대 오류는 원문·사양·출처·효과 창작, 다른 모델/이전 제품 전이, 기존 기능의 신규 제안, 외형의 내부 전환, 미확인 안전 승인, 제약 위반, 단일 후기 일반화, 과거 이력 삭제/잘못된 연결/무효 재사용, 최종·저장 내용 불일치다. 보류만 하면 자동 통과하는 방식은 아니다. 알려진 기능·치수는 답하고 모르는 부분을 한정해야 한다.

50문항을 여러 번 조정해 통과율만 높이지 않는다. 최초 실패·timeout·not_run과 수정 후 별도 실행을 보존한다. 모델·코드·자료·질문·runner의 동결 지문, 실제 CLI ID·최종 원문·저장/export·시간을 비공개 원본에 남기고 공개 보고에는 비식별 요약만 넣는다. 같은 native 대화 누적 사용량은 마지막 값만 합산하며 후속 증가분은 동일 ID·단조 누적일 때만 계산한다. 실패·미측정을 포함하고 청구를 추정0으로 바꾸지 않는다.

## 제약

동시2·입력당420초·최대50 CLI입력·자동 재실행0. 후속의 부모가 전달·저장 검사를 통과하지 못하면 새 세션으로 대체하지 않고 not_run으로 남긴다. 제공사 인증/크레딧/usage limit 거부가 관측되면 이후 작업을 중단하고 사유와 이미 소비한 호출을 보존한다. 외부 웹/API와 서브에이전트는 이 회귀에서 호출하지 않는다. 테스트 대상은 저장된 실제 자료·단일 상품기획 Agent·필요 Skill이다. 웹 수집/자동 서브에이전트/Tool 장애에 대한 통과율로 해석하지 않는다.

## 실제 실행 기록

[동결v6.0의50개 실행·의미 검토·이력·토큰](../validation/regression50-20261011.md)을 따른다. 제품군 이름만의 입력을 반영한v6.1은 별도[일반입력10개](family10.md)로 검증한다. 두 버전을 하나의 최신60개 통과로 합산하지 않는다. 원본50개를 최신코드로 다시 실행하려면 변경된 입력 범위와 기대 행동을 별도 버전으로 검토·동결해야 한다.

원본frozen runner/report는 동결 지문을 유지한다. 실제 기록 감사는regression_audit.py/family_audit.py를 사용한다. 원본byteSHA 검사는 유지하고 WindowsCRLF 기록만LF로 정규화해 동결 질문 전체를 비교한다. 그 외 질문·protocol·지문 변경은 거부한다. 감사는 모델을 호출하지 않는다.
