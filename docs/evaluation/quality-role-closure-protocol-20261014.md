# M 단계: 품질·예외·선택 역할 인수

2026-10-14 사용자가 품질/예외 마감과 서브에이전트 실제 기여 확인을 승인했다. 길웅의 PR10·11 인수는 이후 연결 단계로 구분한다. 기존 L2 14입력과 누적91입력의 기록을 보존하며 새 코드 결과로 재표기하지 않는다.

## 실행 전에 정한 범위

- 새 소스 M1을 고정하고 Codex Astra/low와 유료 Claude Desktop Code Opus5.5/높음에 같은 자료·업무를 적용한다. 새 모델 탐색은 하지 않는다.
- 실제 L2 원문219개(후기 발췌87·공식 사실132), 세 제품군/9모델의 본문·모델·문서·관측 메타데이터를 변경 없이 재사용한다. 제품군별 선택 원문은 냉장고56, 전자레인지82, 식기세척기81이다. 신규 웹 조사·고유 고객219명·시장 대표성으로 설명하지 않는다.
- 환경별 정상 미사용 냉장고 요청, 같은 대화 후속, 동일 요청의 선택 역할 진단, 실제 미확인 치수·효과 요청, 접근 실패, 작업 중 취소를 준비한다. 예상 부모 입력12회, 상한14회다. 여분2회는 관측된 결함 또는 실패한 인수의 필요한 후속에만 쓰며 무조건 반복하지 않는다.
- 부모 업무 동시 실행1, 자동 재발송0. 발송 전에 전역 장부를 예약하고 불확실한 발송도 보존한다. 이전 누적91에 이번 실제 발송 수만 더한다.
- 업무 시계1800초와 마지막90초 수집 종료/최종 전달 준비를 유지한다. 안전상한이며 성능 목표가 아니다. 자료 폭을 줄이거나 후속·자식 생성으로 기존 시계를 연장하지 않는다.

## 입력과 판정

정상·후속은 원문/AI 판단, 정확 모델·시점·조건·긍정 평가·반례, 전체 자료 전달/검토 범위, 현재 저장/검토/최종 답변/refs의 동일 버전을 확인한다. 미확인 자료는 조건부안 또는 보류 이유와 직접 출처를 전달해야 한다. 검증 계획은 전체 분모·실패/중단/미확인 처리·조건 통제·잘못된 조언·품질 비저하를 살펴본다. optional 계획 필드의 구조 진단은 의미나 효과 자동 인증이 아니다.

선택 역할 진단은 같은 냉장고 입력/자료에 공식자료 조사자, 후기 조사자, 근거 검토자의 실제 native 생성·반환·미검토 범위·메인 반영을 확인한다. 부모 단독과 역할 진단의 차이를 기록하되 한 쌍의 시간 차이를 일반적 속도 우위로 확대하지 않는다. 자식은 읽기 전용이고 부모만 등록/저장한다. 자식별180초는 실제 spawn 응답 시각부터 계산하며 전체 마감/최종90초 안에서 더 짧게 제한한다. 설치/자기 작성 장부를 실제 실행으로 세지 않는다.

접근 실패는 예약된 `.invalid` URL을 이용한 명시적 오류 fixture다. 실제 접근 결과를 보존하며 LG 사이트의 실제 HTTP 실패나 시장 조사로 설명하지 않는다. 실패 이유는 간단히 전달하고 HTTP 상태를 관측하지 않았다면 임의 생성하지 않는다.

취소는 실제 실행에서 연결된 미종료 turn을 확인한 뒤 공통 cancel_turn과 소유 native process/GUI Stop의 결과를 각각 기록한다. turn 없는 조사 request는 존재하지 않는 취소 API로 처리하지 않는다. 저장·등록의 late-write 차단, 감사 기록, 실제 프로세스/GUI 중단과 backend 청구 범위를 구분한다. 예외 처리 통과는 상품기획 해결 완료가 아니다.

원 입력·원문·DB·native 로그·설정 사본은 Git 제외 격리에 보관한다. 공개 기록에는 소스/자료/로그 지문, 실제 명령·판정·시간·관측 usage 범위와 역할 결과를 남긴다. 숨은 추론은 검토하지 않는다. 코드·원문·실행 결과의 독립 검토와 실제 종료를 확인한 뒤 인수한다.

## 웹 인수

PR10/11의 최신 고정 head를 인수하고 현재 저장 결과→기획자 화면→보고서 HTML의 동일 버전·출처·전체 자료와 관찰 이벤트를 확인한다. 팀원 디자인을 재작성하지 않는다. 렌더링/관찰은 일반 코드로 수행하며 시각화를 위한 모델 호출을 추가하지 않는다. 메일은 하네스 작업과 연결 확인을 마친 후 사용자에게 초안을 보여준다.
