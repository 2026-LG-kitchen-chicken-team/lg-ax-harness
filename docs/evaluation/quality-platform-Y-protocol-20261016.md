# Skill 최소 비교와 실행 환경 인수 Y

2026-10-16. 사용자 승인 범위는 OSS 검토 뒤 필요한 최소 방법 보완, 실제 웹/보고서 연결, 세 제품군과 다른 제품군의 실행, Codex·Claude GUI/CLI 구분, 설명서 질문 개선이다. 촬영은 하지 않는다. 이 문서는 실행 전에 보존한 비공개 preparation/질문/예약 조건을 옮긴 실행 계약이다. 공개 사전등록이나 통계적 우월성 시험으로 설명하지 않는다.

## 유지하는 제품 계약

- 개발용 역할6·Skill9와 출품 메인1·업무Skill6·선택역할3을 구분한다. 플랫폼·모델 API·필수 MCP를 새로 추가하지 않는다.
- 기존 main `3c0e4e5c90f4a02d1ccff00fda17cb082ac72b9e`를 A로 동결한다. 업무 입력과 데이터에 특정 정답·제품별 답안을 넣지 않는다.
- 출품 기본 catalog는 빈 상태다. 비교용 실제 등록 자료는 별도 폴더이며 설치·심사 ZIP에 포함하지 않는다.
- 저장된 현재 결과와 선택 원문 전체를 공통 코드의 웹·보고서에 전달한다. 기본 `report:false`, 모델의 HTML/PDF/DOCX 생성은 요청하지 않는다.
- 1800초는 안전상한이며 성능 목표가 아니다. 마지막90초 전달 예산을 유지하고 시간 때문에 조사·본문 범위를 줄이지 않는다.
- 정책 거절·권한 요청·중단은 우회하거나 자동 재전송하지 않는다. native end_turn/프로세스 exit0만으로 업무 성공이라 판정하지 않는다.

## 업무 Skill 후보 B

[knowledge-work-plugins](https://github.com/anthropics/knowledge-work-plugins/tree/33eeda1e8fd856455b05479d13a0f85b5f803744)의 상품기획 방법 중 **결정을 바꿀 핵심 가정→반증 관측→최소 첫 시험→결과별 결정**만 독립적으로 다시 작성한다. 플러그인 원문·프로그램·MCP를 통째 설치하지 않는다. 외부 서비스 연결과 자료 접근권도 새로 확보한 것으로 보지 않는다.

B의 변경 범위는 `concept-writing`·`review-and-revise` 지침과 manifest뿐이다. 기존 `assumptions`와 `validation_plan`을 사용하고 스키마·Tool·역할 수·모델 기본값을 바꾸지 않는다. 이미 있는 원문/불편 분류 규칙을 중복해서 추가하지 않는다.

## 자료와 입력

같은 실제 등록 자료219개(후기 발췌87·사실132), 정확 모델9개를 사용한다. 냉장고56·전자레인지82·식기세척기81개 전체 본문을 제품군별로 전달하고 `selected/registered/delivered`와 의미 검토를 따로 확인한다. 이 건수는 고유 고객·전체 웹 문서·시장 대표성이 아니다.

비교 입력은 세 제품군의 일반 상품기획 요청과, 냉장고 설명서 조언을 이해 실패로 바꾸고 여러 발췌를 고객으로 세도록 유도하는 예외 입력이다. 후자는 잘못된 전제를 정정하는지를 확인한다. 처음 예약 순서는 FR A/B, DW B/A, MW A/B, 예외 B/A의4쌍8회다. 새 context·새 session/request/turn을 사용하며 과거 실패나 보완 실행을 같은 성공률에 합치지 않는다.

실행기는 Claude CLI의 구독 인증, 모델 `claude-opus-5-5`, 요청 effort medium으로 고정한다. 백엔드 실제 effort가 반환되지 않으면 unknown을 유지한다. 외부 MCP·추가 Agent·온라인 수집을 제외해 지침 차이를 분리한다. 각 job은 독립 경로이며 GUI 검증과 병행하므로 실행 시간·캐시 차이를 모델 속도 순위나 절감률로 해석하지 않는다. 실행 순서·동시성 변경이 있으면 결과 기록에 남긴다.

## 판정과 중단

우선 원문 귀속·직접 경험/중립 관측·모델·후기 조건·고유 고객 수·현재 저장/최종 전달·원문 누락을 확인한다. 이후 각 정상 입력을 아래4축0~2점으로 독립 검토한다. 0은 없음/결정과 무관함, 1은 일부 작동, 2는 구체적인 관측과 실제 결정으로 연결됨이다.

1. 가정이 틀렸을 때 제안을 철회·축소·변경하는가.
2. 가설과 대안 설명을 구별하는 관측인가.
3. 최소 첫 시험을 택한 이유가 있는가.
4. 지지·반박·미확인 결과별 후속 결정이 있는가.

조건부 기획이나 향후 시험을 미실행했다는 이유만으로 실패시키지 않는다. 단어·절 제목을 많이 썼다고 가점하지 않는다. 정상3쌍 중2쌍 이상에서 실질 개선되고 나머지에 실질 퇴행이 없으며, 중대한 의미 오류·자료/전달 퇴행·예외 입력 퇴행이 없을 때만 B를 채택한다. 그렇지 않으면 기존 구현을 유지한다. 권한/정책·예산·모델 이용 불가·중대한 실행 결함이면 해당 실제 상태와 미실행 분모를 보존한다.

## 네 환경과 신규 제품군

Codex GUI/CLI, Claude GUI/CLI의 로그인·실행기·모델/effort·현재 권한·실제 tool·저장·전달을 각각 기록한다. 기존 GUI 작업 폴더/권한을 사용한 시험과 ZIP 새 폴더 첫 설치 인수를 구분한다. 한 환경 성공을 다른 환경 성공으로 확대하지 않는다.

별도 Claude GUI 입력은 전자레인지 실제82본문 업무와 빈 catalog의 **인덕션 신규 조사**다. 신규 조사는 공식 모델 확인→다양한 실제 후기/조건→원문/시점 등록→같은 요청 기획 경로를 확인한다. 기존 세 제품의 근거를 새 제품에 붙이지 않으며 출처 수·실패·남은 조사 범위를 보존한다. 웹/보고서의 같은 결과 연결과 실제 브라우저 육안/키보드 검수도 별도 판정이다.

원문 실행 로그·계정·개인 경로·DB·자료 본문은 Git/배포에 넣지 않는다. 검증 결과에는 재현 가능한 코드·입력 지문·native ID·관측 사용량과 한계를 남긴다. 사람 대비 절감률·실물 개선 효과·촬영·최종 접수는 이번 완료 조건이 아니다.
