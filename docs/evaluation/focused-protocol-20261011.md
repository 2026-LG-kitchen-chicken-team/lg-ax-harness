# 최신 계약·웹·근거·비교의 제한된 재검증

2026-10-11 KST. 사용자가 남은 작업1/2/3/6을 요청했다. 팀원이 로컬에서 만든 웹은 사용자의 후속 지시에 따라 이번 분석에서 제외한다. 기존 [12입력 시험](../validation/seven-task-progress.md)은 종료한 기록으로 보존한다.

새 단계는 제품 v5.4 source를 동결한 뒤 최대9입력/동시2/입력당420초/자동 재시도0으로 수행한다. 실패와 timeout도 슬롯을 소비한다. 동일 질문 반복은 통과할 때까지 재실행하는 규칙이 아니다. 새 코드 수정이 필요하면 이미 시작한 결과는 보존하고 후속 별도 계획을 세운다.

CLI는 기존 개발 평가 helper를 쓰며 출품 폴더·ZIP에는 들어가지 않는다. 제품 모델 실행 방식은 기존 Codex의 인증/모델이다. 자체 모델 API 프로그램·provider 전환·유료 구독·사용량 reset은 추가하지 않는다. 소스 지문·실제 CLI/모델/effort·진입 질문·실패·저장 결과·final과 usage 관측 범위를 기록한다. 이번 질문은 알려진 회귀/진단 사례로, 독립 미사용 평가·미래 심사 분포 표본으로 설명하지 않는다.

원문 보존과 반환 preview 크기는 분리한다. 전체 페이지/도구 목록/코드를 반복 출력하지 않고 필요한 문단만 읽는다. 작은 preview에 없는 문자열을 원문 부재라고 판단하지 않는다. Code 검사는 source 구조/상태 계약 검사이고 정확한 주장 의미는 독립 원문 검토로 확인한다.

실패·수정·후속 포함 관측 input/cache/output/reasoning을 집계한다. cache는 input의 일부이고 reasoning은 output의 일부다. 동일 세션의 latest cumulative를 한 번만 집계하며 timeout은 종료 전 부분 관측으로 표시한다. 호출 backend 전체·청구·제품 귀속 현금 비용·사람 활동 시간은 근거 없으면 unknown이다. 실제 사람 측정은 기존 팀 회신이 필요하며 AI가 복원하지 않는다.

완료 판단은 실제 final→pointer→SHA→export→현재 DB·질문/조건/자료/코드 freshness 대조와 원문 의미를 함께 사용한다. 비교2회 평균은 작은 비맹검 표본이며 캐시 초기화/개발 동시 사용/순서 효과를 통제하지 못한다. 총 토큰·시간·품질·공수 우위는 관측 범위와 실제 근거에 한해 판단한다.

## 시작 후 발견한 평가 결함

web의 동결 case는 max_concepts=1이지만 최종 실행 질문에서 그 조건을 누락했다. 실제 저장 기본값3과 다르므로 원래 실패를 유지한다. 최종 제안 수가0이라는 이유로 상한1의 입력 계약까지 통과로 바꾸지 않는다. 실제 요청·저장 기본값을 기준으로 하는 재검사는 별도 진단이며 신규 native 실행이나 원래 case 통과가 아니다. clean-geometry는 공통 prompt에 제약 JSON을 포함하므로 이 누락 사례와 구분한다.

평가 실행기·final 판독기의 실패 보존/분류 수정은 제품 source 동결과 분리한다. 시작 marker의 runner 지문과 수정 시점·검사 지문을 보존하며, 이미 종료한 원본 result는 덮어쓰지 않는다. 비최종 web metadata의 id 중복은 원문에 남기고, 이벤트 분류 type/item의 중복과 critical final의 모든 중복 필드는 거부한다.
