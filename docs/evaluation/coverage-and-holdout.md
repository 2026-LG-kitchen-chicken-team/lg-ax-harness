# 질문 범위와 미사용 평가

이 문서는 새 내부 평가 설계다. 공식 심사 문제 수·자동 채점 방식·모든 환경의 지원을 확정하지 않는다. 질문 후보 수백 개를 준비하는 것 자체가 과적합은 아니다. 개발 중 본 질문과 답안에 맞춰 지침을 계속 고치고 그 질문만 다시 평가하면, 모델 가중치를 학습하지 않아도 처음 보는 요청에 대한 성능을 과대평가할 수 있다.

현재 공개 J01–J18과 실제 자료 R01–R06, 기존 S05 결과는 개발에 노출된 사례다. 이를 미사용 평가라고 부르지 않는다. 실제 실행 범위·실패는 [pilot](../validation/s05-pilot.md), [후속](../validation/s05-followup.md), [보강](../validation/s05-hardening.md)을 따른다. 이번 기록 체계 작업에서는 새 업무 AI 입력을 실행하지 않았다.

## 질문 수보다 유형·자료·실패 조건

| 유형 | 바꿀 조건 | 확인할 행동 |
|---|---|---|
| 모델 선택과 정상 상품기획 | 제품·대상·제약, 상세 불편을 입력하지 않은 요청 | 해당 모델의 실제 원문에서 불편을 찾아 기존 기능과 남은 부담을 연결 |
| 자료 부족·긍정·상충 근거 | 후기 수·사용 맥락·반대 의견 | 수량을 채우기 위한 불편 조작 없이 한계·필요 입력·보류 설명 |
| 모델·설명서·자료 버전 | 다른 모델, 새 문서, 같은 버전의 지문 변경 | 정확한 scope 적용, 무효화·재검토·변경 이유 유지 |
| 기존 기능·기능 부재 주장 | 이미 있는 기능, 미기재, 기능이 해결하지 못하는 부담 | 기존 기능을 신규 제안으로 포장하거나 전체 해결로 확대하지 않음 |
| 물리 조건·제안 효과 | 하드웨어 금지, 외형/내부 치수, 청소·수납 조건 | 확인되지 않은 배치·내부 치수·시간 절감·시장 수요를 확정하지 않음 |
| 후속·조건 변경·재접속 | 추가 질문, 같은 요청 키, 늦은 결과, 이전 turn 재개 | 제약 갱신, 유효 결과만 재사용, 수정·비용·이력 보존 |
| 조회·도구·실행 오류 | timeout, 권한, 장애, 취소, 저장/export 불일치 | 실제 오류와 미관측을 전달하고 상한·멱등성·저장 차단 준수 |
| 출처 신뢰·자료 속 지시 | 가짜 출처 요구, 원문 삽입 지시, 합성 통계 | 원문 의미 검토, 자료 지시의 권한 승격 금지, 합성 결과의 시장 일반화 금지 |

표는 전체 심사 입력을 보장하는 목록이 아니다. 후보 풀은 유형 × 자료 조건 × 표현 × 후속 조건으로 넓힐 수 있지만 전체 조합을 전부 모델에 실행하지 않는다. 알려진 결함·업무 영향·빠진 유형을 기준으로 먼저 실행할 사례를 고른다. 표현만 바꾼 질문은 같은 사례 그룹으로 분류한다.

업무 품질 평가에는 실제 제품·리뷰를 쓴다. 새 합성 자료는 계약·오류 주입 시험으로 표시한다. 합성의 성공을 실제 상품기획 근거·효과로 설명하지 않는다. 오류 문장만 입력했다고 Tool 장애가 주입된 것은 아니므로 실제 주입·관측 근거도 기록한다.

후보 질문 수, 독립 원문 그룹 수, 모델 scope 수, 실제 AI 입력 수, 반복 실행 수, backend 모델 호출 수를 각각 센다. 수백 후보가 수백 실행·수백 독립 사례를 뜻하지 않는다. 네이티브 실행 전 평가 묶음·시간/호출/지출 상한·중단 조건을 정하며 현재 300,000원 예산과 미측정 청구를 고려한다. 이 문서는 수백 회 유료 실행을 승인하거나 시작한 기록이 아니다.

## 개발·회귀·미사용 평가 분리

| 묶음 | 용도 | 관리 원칙 |
|---|---|---|
| 개발 | Agent·Skill·Tool 수정과 디버깅 | 사례와 검토 기준을 보면서 개발 가능 |
| 회귀 | 이미 확인한 성공·실패가 다시 발생하는지 검사 | timeout·수집 실패·내용 결함을 지우지 않음; 수정 후 새 시도 연결 |
| 미사용 평가 | 구현 동결 후 처음 보는 요청·자료로 일반화 확인 | 개발자가 질문·근거·평가 결과를 보고 튜닝하지 않은 묶음 |

관리자는 각 사례에 `case_group_id`, 원문 그룹·자료 지문, 모델/문서 버전, split, 질문·조건·기대/금지 행동, 노출·실행 이력, 동결한 구현 commit을 남긴다. 같은 원문·대화 계열·바꿔쓰기 질문은 같은 split에 둔다. 미사용 평가는 구현 동결 전에 다른 팀원이 신규 질문·독립 원문 묶음과 기준을 정하고 지문을 고정한다. 특정 콘셉트나 완성 답안을 정답으로 외우게 하지 않는다.

미사용 질문·기준·답안은 개발 AI가 읽는 checkout과 출품 설치물 밖의 별도 평가 보관 위치에서 관리한다. 이는 운영 절차이며 파일 접근을 강제로 막는 보안 장치라고 주장하지 않는다. 공유 레포에는 접수·검토한 결과와 노출 이력을 남긴다. 개발 AI가 결과를 읽거나 이를 보고 수정했다면 그 사례는 이후 회귀 묶음으로 옮기고 새 미사용 묶음을 준비한다. 결과를 반복 확인하거나 실패를 제외하며 동일 묶음을 미사용으로 재평가하지 않는다.

추가로 조건을 유지한 바꿔쓰기는 근거·제약·업무 상태가 유지되는지, 모델/버전/제약을 실제로 바꾼 요청은 관련 결과만 적절히 달라지는지 비교한다. 답변 문장의 동일성이나 무작위성 제거를 요구하지 않는다.

## 환경별 결과 비교

Codex·Claude Code·Gemini CLI의 실제 OS·CLI 버전·관측 모델/추론·권한/신뢰·자료/설치 지문을 [팀 실행 보고서](team-test-records.md)에 기록한다. 같은 질문·자료·source commit을 맞춰 비교하고 달라진 설정을 표시한다. 환경에 따라 도구 접근과 출력 표현은 달라질 수 있으므로 동일 문장 대신 공통 업무 계약 충족을 평가한다.

각 환경의 설치/Skill 발견, 첫 입력, 후속, 자료 부족, 오류/복구, 저장/export, 사용량 관측을 따로 판정한다. 파일 설치·doctor와 한 번의 성공 답변만으로 전체 native 지원을 인수하지 않는다. 개발 하네스 Claude 인수 D06b와 출품 S02/S03·품질 S05도 별도다. 사용자가 팀원 실행을 보고했으나, 이번 체계 작성 시점에는 개별 결과를 아직 접수·검토하지 않았다. 확인 후 [환경별 색인](../validation/team-runs/index.md)을 갱신한다.

## 평가·출력·오류의 연결

실행 종료 상태, 업무 저장 상태, 내용 검토 판정을 분리한다. 실제 답변·저장/export·관측 Agent/Skill/Tool·명령/exit와 원문 의미를 대조한다. `exit 0`, source ID 존재, 모델의 `supported/accepted` 자기보고만으로 정답 처리하지 않는다. 근거 있는 `held/needs_input`은 기대 행동을 충족할 수 있고, 최종 답변이 없으면 그대로 기록한다. 실제 지시문 전달이 미확인인 시험은 방어 통과로 처리하지 않는다.

결함은 자료/원문, 모델 판단, Tool·권한, 상태/저장, 실행 시간, 수집/관측으로 분류하고 최초 결과 → 검토 → 수정 commit → 새 재시험을 연결한다. J17 정상 대조 timeout과 최초 수집 오류도 회귀 근거로 유지한다. 수집 복구가 원래 업무 실패를 성공으로 바꾸지 않는다.

사용량은 관측된 수정·재시도·실패·하위 호출까지 포함하며 미측정은 0으로 바꾸지 않는다. 캐시 입력/추론 토큰이 총 입력/출력의 부분 값인지 실제 카운터 정의를 확인해 중복 합산을 피하고, 세션 누적·차이·단일 turn 범위를 명시한다. 실행/준비/독립 검토/사람 활동 시간을 분리한다. baseline은 동일 자료·환경·질문·의미 기준으로 비교하고 성공만 골라 절감률을 발표하지 않는다.

당장 할 일은 팀원이 이미 실행한 결과 접수·검토, 빠진 환경/유형 확인, 드러난 결함 수정·회귀 검사다. 이후 미사용 묶음과 제한된 반복 평가를 수행한다. 이번 문서·양식 구축이 미사용 품질 평가 통과를 의미하지 않는다.

## 2026-10-11 제한된 신규 표현 평가

구현 수정 전 자체 U13/U14 두 질문을 동결했다(SHA256 `808842466d871abcc4eea61733bc6c1ab327fa51e3b1e29d0a349b06fc27fcd9`). 같은 기존 실제 원문에서 발생률 과장·조건 변경·치수/효과 창작을 실제 native로 검사했고 각각 전달 계약 통과·의미14/14를 확인했다. 신규 독립 원문/비노출 개발자/미래 심사 분포 시험은 아니다. U14가 요청한 긍정·이전 제품 청소 원문은 저장 자료에 없어 unknown 처리만 검증했다. 현재 개발 AI가 질문·결과를 읽었으므로 앞으로 회귀 묶음이며 미사용 평가로 재실행하지 않는다. 원문·실패/버전·노출 한계는 [최신 검증](../validation/seven-task-progress.md)을 따른다. 수백 개 실행이나 합성 리뷰를 실제 심사 성공 보장으로 사용하지 않는다.
