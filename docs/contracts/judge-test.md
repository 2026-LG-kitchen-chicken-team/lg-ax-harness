# LG AX 상품기획 에이전트 사용설명서

**실제 사용자의 불편을 찾아, 근거가 연결된 상품기획으로 발전시키세요.**

냉장고·전자레인지·식기세척기에 대해 평소 말하듯 요청하면 AI가 실제 후기와 공식 자료를 조사하고, 기존 기능을 비교해 개선안을 작성합니다. 진행 상황은 대시보드에서, 완성된 기획과 출처는 기획자 웹과 보고서에서 확인할 수 있습니다.

이 세 제품군은 검증·시연의 대표 사례입니다. 다른 제품도 제품명과 원하는 업무를 자연어로 요청하면 같은 조사·기획 절차로 진행합니다. 필요한 모델 식별과 자료 범위는 대화에서 정합니다.

> **처음 사용하시나요?** 준비물을 확인한 뒤 **3. 처음 켜기 → 4. 첫 상품기획 만들기 → 5. 결과 읽기** 순서로 따라오세요. 원클릭 실행으로 준비를 마쳤다면 부록의 수동 설치를 다시 할 필요가 없습니다.

## 1. 제품 알아보기

### 이런 일을 요청할 수 있습니다

| 하고 싶은 일 | 요청 예시 | 받는 결과 |
|---|---|---|
| 제품의 사용 불편 찾기 | “냉장고의 실제 사용 불편을 조사해줘.” | 후기·공식 자료의 출처와 조건을 연결한 불편 분석 |
| 개선할 방향 정하기 | “이미 제공되는 기능과 비교해 개선안을 제안해줘.” | 기존 기능 비교와 상품기획 초안 |
| 기획 구체화하기 | “앞의 안을 사용자 행동 세 단계로 구체화해줘.” | 앞선 기획과 연결된 후속 결과 |
| 기획 읽고 검토하기 | “핵심 근거와 다음 검증 방법을 정리해줘.” | 기획자 웹·별도 보고서·원문 및 출처 |

질문은 **Codex 또는 Claude Code**에 입력합니다. 이 하네스는 선택한 AI가 조사·분석·기획·검토·저장을 수행하도록 지침과 도구를 제공합니다. 기획자 웹은 저장된 결과를 읽는 화면입니다.

처음 설치한 자료 저장소는 비어 있습니다. 첫 업무에서 실제 자료를 조사하므로 제품코드나 상세 불편을 미리 준비하지 않아도 됩니다. AI가 필요한 제품 범위나 조건을 되물으면 그 대화에서 답해주세요.

## 2. 사용 전 준비

### 준비물 확인

| 준비물 | 확인할 내용 |
|---|---|
| 심사위원용 ZIP | 파일 이름이 `lg-ax-judge-`로 시작하는 ZIP을 받습니다. 소스코드 ZIP은 일반 사용에 필요하지 않습니다. |
| 사용할 AI 하나 | Codex 또는 Claude Code 중 본인이 사용할 수 있는 환경을 고릅니다. 두 가지를 모두 설치할 필요는 없습니다. |
| 본인 계정과 이용 한도 | 선택한 AI와 모델을 사용할 수 있어야 합니다. Claude 앱은 **Code 탭**을 사용할 수 있는 유료 계정이 필요합니다. |
| 인터넷과 웹 브라우저 | 프로그램 준비, AI 연결, 실제 자료 조사에 사용합니다. 결과 화면도 브라우저로 엽니다. |
| uv | 이 제품에 필요한 Python과 실행 환경을 준비하는 도구입니다. 없으면 시작 파일이 설치 여부를 묻습니다. |

하네스 사용에 별도 LLM API key·필수 MCP/플러그인·개발 저장소·Node/npm은 필요하지 않습니다. **AI 실행기 자체의 설치 준비물**은 아래 공식 안내를 따릅니다. uv가 제품용 Python 3.12를 준비하므로 이미 설치된 다른 Python을 지울 필요가 없습니다.

- Codex 사용자: [공식 CLI 설치 안내](https://learn.chatgpt.com/docs/codex/cli). 이 ZIP의 Codex 시작 파일은 CLI를 사용하므로 앱을 선택해도 CLI가 필요합니다.
- Claude 앱 사용자: [공식 Desktop 설치 안내](https://code.claude.com/docs/en/desktop-quickstart). 앱의 Code 기능에는 별도 Claude CLI 설치가 필요하지 않습니다.
- Claude 터미널 사용자: [공식 Claude Code 설치 안내](https://code.claude.com/docs/en/setup). CLI가 없으면 시작 파일에서도 설치 여부를 묻습니다.
- uv를 직접 준비하려면 [공식 uv 설치 안내](https://docs.astral.sh/uv/getting-started/installation/)를 따릅니다.

### 구성품 확인

압축을 푼 **맨 바깥 폴더**를 이 설명서에서는 ‘ZIP 루트’라고 부릅니다. 아래 이름이 보이면 올바른 위치입니다.

| 파일·폴더 | 용도 |
|---|---|
| `README.md` | 지금 읽는 사용설명서 |
| `start_codex_cli.cmd` / `start_codex_gui.cmd` | Windows에서 Codex 터미널 / 앱 시작 |
| `start_claude_cli.cmd` / `start_claude_gui.cmd` | Windows에서 Claude 터미널 / 앱 시작 |
| 같은 이름의 `.sh` 파일 4개 | macOS/Linux 터미널에서 시작. 이 배포본의 GUI 시작 안내는 macOS용입니다. |
| `codex/` / `claude/` | 각 AI가 사용하는 작업 폴더. 지침·Skill·도구·결과 화면이 들어 있습니다. |
| `judge.py` / `bundle-manifest.json` | 설치 준비와 배포 파일 무결성 확인 |

Codex와 Claude의 작업 기록은 각각의 폴더에 저장됩니다. 한쪽의 대화나 결과가 다른 쪽에 자동으로 이어지지는 않습니다.

## 3. 처음 켜기

**아래 과정은 Windows 기준입니다.** macOS/Linux 시작 명령은 부록 A에 있습니다. 이 배포본의 직접 설치·실행 검사는 Windows에서 진행했습니다.

### ① 새 폴더에 모두 압축 풀기

ZIP을 문서 폴더 등 원하는 위치에 **모두 압축 풀기**로 풉니다. ZIP 미리보기 안에서 실행하지 말고, 이전 버전이나 다른 Git 저장소 안에 덮어쓰지 마세요.

**보이는 것:** `README.md`, `judge.py`, `codex`, `claude`와 시작 파일들. **다음:** 사용할 시작 파일 하나를 고릅니다.

### ② 사용할 AI와 화면 선택하기

| 원하는 사용 방식 | 더블클릭할 파일 | 시작 후 확인할 것 |
|---|---|---|
| Codex 터미널 | `start_codex_cli.cmd` | Codex 대화 입력창과 별도의 작은 실행 관찰 창 |
| Codex 앱 | `start_codex_gui.cmd` | 앱 또는 설치 안내, 작업 폴더 안내와 실행 관찰 창 |
| Claude 앱 | `start_claude_gui.cmd` | Claude 앱과 Code/Local/폴더 선택 안내, 실행 관찰 안내 |
| Claude 터미널 | `start_claude_cli.cmd` | Claude Code 대화 입력창 또는 로그인 안내, 실행 관찰 안내 |

처음에는 필요한 파일을 내려받는 준비 메시지가 표시됩니다. **설치 질문에 `y`를 입력하면 안내된 공식 설치가 진행**되고, 원하지 않으면 `N` 또는 Enter로 종료할 수 있습니다. 소요 시간은 네트워크와 PC에 따라 달라집니다. 완료 전 같은 파일을 여러 번 실행하지 마세요.

**보이는 것:** 설치·점검 결과와 작업 폴더 경로. **다음:** 로그인과 폴더 선택을 마칩니다. 준비에 실패하면 마지막 오류를 확인하고 7절로 이동하세요.

### ③ 로그인하고 올바른 작업 폴더 열기

**Codex를 선택한 경우**

1. 로그인 화면이 나오면 본인 계정으로 로그인합니다.
2. 터미널 시작은 `codex` 폴더에서 자동 실행됩니다. 앱 시작은 표시된 경로를 확인하고 **ZIP 안의 `codex` 폴더**를 프로젝트로 선택합니다. Windows에서는 앱이 열린 뒤 폴더를 직접 열어야 할 수 있습니다.
3. 앱에서는 모델과 추론 수준도 확인합니다. 이 배포본의 Codex CLI 기본값은 **GPT-6.1 Sol / medium**입니다. 앱 설정이 CLI 옵션과 자동으로 같아지는 것은 아닙니다.

**Claude를 선택한 경우**

1. 본인 계정으로 로그인합니다. 터미널 인증과 Desktop 앱 인증은 별개입니다.
2. 앱에서는 **Code → Local → ZIP 안의 `claude` 폴더**를 선택하고 새 대화를 시작합니다. 이미 해당 폴더가 열린 경우 선택된 경로만 확인합니다. 일반 Chat 탭에서는 이 하네스를 실행하지 않습니다.
3. 앱에서 **Opus 5.5 / 추론 중간**을 확인합니다. Claude CLI 시작 파일도 같은 배포 기본값을 사용합니다. 모델이 목록에 없다면 계정에서 이용 가능한 모델과 현재 선택값을 확인하고 사용 기록에 남깁니다.

**보이는 것:** 선택한 AI의 대화 입력창과 올바른 작업 폴더. **다음:** 첫 접근 승인을 확인합니다. ZIP 루트에서 시작했다면 대화 중 폴더만 이동하지 말고 `codex` 또는 `claude` 폴더에서 새 세션을 여세요.

### ④ 필요한 접근 승인하기

AI는 작업 폴더에 결과를 저장하고 공개 웹 자료를 읽습니다. 폴더 신뢰·파일/명령·웹 접근 요청이 나오면 **대상 폴더와 작업을 확인한 뒤** 승인합니다. 시작 파일이 함께 실행한 관찰 프로그램은 저장된 현재 결과를 읽어 화면을 준비하고 기본 브라우저로 열기를 요청합니다. 이 경로는 AI 실행기의 자동 실행 설정 승인 여부와 별개입니다.

Codex CLI에서는 `/permissions`로 권한을, `/hooks`로 자동 갱신 설정의 신뢰 상태를 확인할 수 있습니다. 앱은 해당 권한·프로젝트 설정 화면을 확인합니다. Claude는 폴더 신뢰와 실행 중 권한 요청을 처리합니다. 시작 파일이 로그인이나 이 승인을 대신하지는 않습니다.

**보이는 것:** 승인 대기가 해소되고 대화 입력이 가능한 상태. **다음:** 4절의 첫 질문을 입력합니다. 진행이 막혔다고 전체 접근으로 일괄 전환할 필요는 없습니다.

> **준비 완료:** 원클릭 실행을 마쳤다면 부록 A의 수동 설치는 생략하세요. 실행 관찰 프로그램은 대시보드와 결과 화면을 연결하므로 작업하는 동안 열어둡니다. 앱을 사용하는 경우 시작 안내가 있는 터미널을 닫지 마세요.

## 4. 첫 상품기획 만들기

### 준비 상태 확인하기

아래 문장을 **AI 대화 입력창**에 붙여넣습니다. 터미널의 운영체제 명령 입력칸이나 결과 웹에는 넣지 않습니다.

```text
상품기획은 아직 시작하지 말고 설치된 지침과 Skill, 로컬 파일·저장소 실행 준비와 공개 웹 조회 가능 여부를 확인해줘. 권한이 필요하면 정상 절차로 요청해줘.
```

**보이는 것:** 준비 결과 또는 추가 승인·오류 안내. 첫 질문 기록이 생기면 실행 대시보드의 자동 열기를 시도합니다. **다음:** 준비 결과를 확인하고 실제 업무를 요청합니다.

### 첫 기획 요청하기

```text
냉장고의 실제 사용 불편을 여러 후기와 공식 자료에서 조사하고, 기존 기능을 고려해 개선할 상품기획을 제안해줘. 핵심 근거와 출처, 다음 검증 방법도 함께 정리해줘.
```

제품코드를 알고 있다면 제품명 대신 넣어도 됩니다. 조사 범위가 있으면 사용 대상·시장·조건을 자연어로 덧붙이세요.

**보이는 것:** 조사·분석 과정, 필요한 추가 질문, 완료 후 기획과 출처. 자료량·사이트 접근·모델에 따라 시간이 달라집니다. **다음:** 저장된 결과를 5절의 화면에서 확인합니다.

### 이런 일도 부탁해 보세요

제품명에서 출발해 **실제 불편을 찾고, 이미 있는 기능을 대조하고, 시험할 수 있는 기획으로 발전**시키는 데 활용하세요. 처음부터 제품코드나 상세 불편을 준비할 필요는 없습니다. 아래 질문은 그대로 붙여넣거나 상황을 바꿔 사용할 수 있습니다. 생활 장면은 조사 관점이며 실제로 불편이 있었는지는 후기와 공식 자료로 확인합니다.

| 하고 싶은 일 | 처음 시작할 때 입력할 예시 |
|---|---|
| 냉장고 앞에서 생기는 작은 마찰 찾기 | 냉장고에서 재료를 찾고 정리하는 과정을 살펴봐줘. 실제 후기에서 어떤 순간에 불편을 겪는지 조사하고, 기존 기능까지 확인해 기획할 만한 문제를 찾아줘. |
| 퇴근 후 한 끼를 데우는 과정 살펴보기 | 퇴근 후 한 끼를 데우는 상황을 기준으로 전자레인지를 조사해줘. 조작부터 음식 꺼내기와 청소까지 살펴보고, 실제 경험이 뒷받침하는 개선 기회를 제안해줘. |
| 이미 있는 기능과 새 기획 구분하기 | 식기세척기의 실제 사용 불편을 찾아줘. 이미 있는 코스나 설명서 안내로 해결되는 부분과, 그래도 남는 문제를 나눠서 개선안을 제안해줘. |
| 부품을 늘리지 않는 기획 찾기 | 냉장고에 새 센서나 부품을 추가하지 않는 조건으로 개선안을 찾아줘. 실제 불편과 기존 기능을 먼저 확인하고, 안내나 사용 흐름으로 개선할 수 있는 안이 있는지 검토해줘. |
| 큰 용기를 쓰는 사람의 조건 확인하기 | 큰 도시락 용기를 쓰는 사람을 위한 전자레인지 기획을 검토해줘. 들어가는 크기와 꺼내는 동작에 어떤 정보가 필요한지 조사하고, 내부 치수가 확인되지 않으면 확인이 필요한 부분을 알려줘. |
| 다른 키친 제품으로 시작하기 | 이번에는 인덕션을 조사해보고 싶어. 실제 사용 후기와 공식 자료에서 기획할 만한 불편을 찾아줘. 어떤 제품 범위부터 볼지 정하는 데 필요한 정보가 있으면 먼저 물어봐줘. |

### 이어서 발전시키기

아래 질문은 관련 조사·기획이 있는 **같은 대화**에서 사용하세요. AI가 앞선 근거와 기획을 이어받아 새 요청을 처리합니다.

| 하고 싶은 일 | 같은 대화에 입력할 예시 |
|---|---|
| 근거가 분명한 한 안을 구체화 | 앞 기획에서 근거가 가장 분명한 한 안을 골라 구체화해줘. 사용자가 언제 시작해서 어떤 행동을 거쳐 끝내는지, 도중에 막히면 어떻게 돌아오는지 설명해줘. |
| 처음 쓰는 사람을 위한 사용 흐름 | 앞선 개선안을 처음 쓰는 사람도 이해할 수 있게 다듬어줘. 꼭 필요한 조작과 안내를 정리하고, 구현 순서와 아직 확인해야 할 가정을 붙여줘. |
| 같은 제품군의 두 모델 비교 | 앞서 조사한 같은 제품군의 두 모델을 비교해줘. 같은 항목과 사용 조건으로 기능을 대조하고, 어느 모델에서 확인된 불편인지 구분해서 기획 방향을 정리해줘. |
| 우리 기획에 불리한 근거도 살펴보기 | 이 개선안이 필요하지 않을 수도 있는 사례를 찾아줘. 만족한 후기나 다른 사용 조건과 비교해서 적용 대상을 다시 살펴보고, 필요하면 앞선 기획을 수정해줘. |
| 만들기 전에 시험할 방법 정하기 | 이 안이 실제로 도움이 되는지 어떻게 시험할지 계획해줘. 기존 방식과 같은 과제로 비교하고, 실패하거나 중단한 경우와 오히려 나빠지는 경우도 판단할 수 있게 해줘. |
| 판단에서 원문·보고서까지 따라가기 | 지금 저장된 기획에서 가장 중요한 판단 하나를 골라 설명해줘. 연결된 원문과 아직 확인되지 않은 부분을 함께 짚고, 기획자 웹과 보고서를 어디서 확인하는지도 알려줘. |

자료를 얻지 못했거나 제품을 식별할 수 없으면 AI가 이유와 다음 질문을 전달할 수 있습니다. 답변의 조사 범위·출처와 실제로 확인된 내용을 함께 읽어주세요.

### 특정 Skill을 직접 사용하고 싶을 때

평소에는 자연어로 요청하면 됩니다. Skill은 특정 업무에 필요한 작업 지침이며, 이름을 지정하는 방법도 제공합니다.

| 업무 | Skill 이름 |
|---|---|
| 저장한 근거 조회 | `evidence-retrieval` |
| 웹에서 실제 자료 수집 | `web-evidence-collection` |
| 불편과 요구 정리 | `needs-structuring` |
| 기존 기능 비교 | `feature-comparison` |
| 상품기획 작성 | `concept-writing` |
| 결과 검토·수정 | `review-and-revise` |

Codex는 `$evidence-retrieval` 뒤에 요청을 적거나 CLI의 `/skills`에서 선택합니다. Claude는 `/evidence-retrieval`처럼 호출합니다. 예를 들어 Codex에는 `$feature-comparison 앞서 조사한 모델의 기존 기능과 개선안을 비교해줘.`라고 요청할 수 있습니다.

공식 자료 조사자·후기 조사분석자·근거 검토자라는 **선택 서브에이전트 3개**도 있습니다. 메인이 필요할 때 일을 나눠 맡기므로 모든 질문에서 세 역할이 전부 실행되는 것은 아닙니다.

## 5. 화면과 결과 읽기

| 화면 | 어디에서 보는가 | 언제 무엇을 확인하는가 |
|---|---|---|
| AI 대화 | 선택한 Codex 또는 Claude Code | 질문 입력, 추가 질문 응답, 접근 승인, 최종 답변 |
| 실행 대시보드 | 브라우저의 `runtime-data/agent-office/index.html` | 첫 질문 이후의 도구·Skill·서브에이전트 실행 기록 |
| 기획자 웹 | 브라우저의 `runtime-data/visual-viewer/index.html` | 결과 저장 후 기획·근거·출처를 항목별로 읽기 |
| 별도 보고서 | 기획자 웹의 **보고서 보기** | 검토된 현재 기획을 보고서 형식과 차트로 읽기 |

위 경로는 선택한 `codex/` 또는 `claude/` 폴더 안에 있습니다. 예를 들어 Codex의 기획자 웹은 `codex/runtime-data/visual-viewer/index.html`입니다. 처음부터 결과 파일이 모두 있는 것은 아니며 준비·실행·저장 과정에서 생성됩니다.

### 진행 상황 확인하기

Claude는 프로젝트 자동 갱신 설정이 허용되면 첫 질문 때 대시보드 열기를 시도합니다. Codex는 켜둔 관찰 프로그램이 새 세션 기록을 찾으면 열기를 시도합니다. 기본 브라우저나 권한 설정 때문에 열리지 않으면 해당 파일을 직접 열거나 부록 B에서 경로를 확인합니다.

대시보드는 **실시간**으로 시작합니다. 첫 기록 전에는 대기 안내가 나타나며, 예시와 과거 기록 재생은 직접 선택한 경우에만 표시합니다. 기록은 약 1초 간격으로 읽으며 실제 사건이 있어야 새 내용이 나타납니다. 이 화면은 실행 기록을 보여주는 것으로, 모델 내부 생각을 표시하지는 않습니다.

### 완성된 기획 읽기

AI가 검토한 현재 결과를 저장·내보내고 해당 작업을 마치면, 실행 관찰 프로그램이 기획자 웹과 보고서 데이터를 준비한 뒤 기본 브라우저로 열기를 요청합니다. 자동으로 열리지 않았다면 위 파일을 직접 엽니다. 첫 저장 전에는 결과를 기다리는 안내가 나타납니다. 읽기를 다시 시도하는 동안에는 마지막으로 정상 표시된 결과를 유지합니다. 갱신 안내의 **다시 불러오기**를 누르면 바로 재시도할 수 있습니다.

기획자 웹의 `index.html`은 같은 폴더의 `view-data.js`와 함께 사용합니다. HTML만 다른 폴더로 복사하면 자료를 읽을 수 없습니다. 파일 하나로 공유할 때는 **보고서 보기 → 보고서 파일 저장**으로 내려받은 HTML을 보관하세요. 자료를 읽지 못하면 부록 B의 화면 연결 진단부터 실행합니다.

1. 현재 결과가 방금 요청한 제품·업무인지 확인합니다.
2. 불편 분석과 개선안을 읽고 연결된 원문·출처를 펼쳐봅니다.
3. **보고서 보기**를 눌러 기획을 보고서 형식으로 확인합니다.
4. 보완하고 싶은 내용을 AI 대화에 요청하고, 새 결과가 저장된 뒤 화면을 다시 확인합니다.

보고서를 읽는 동안 새 기획이 저장되어도 현재 보고서의 내용은 바뀌지 않습니다. 새 결과 안내에서 **최신 보고서 보기**를 누르면 새 기획으로 전환합니다. 보고서 준비에 문제가 있으면 **보고서 다시 열기**를 누르거나 **업무 화면으로** 돌아가 결과를 계속 읽을 수 있습니다.

결과 화면과 보고서·차트는 일반 코드로 구성하며 이를 그리기 위한 별도 모델 호출은 없습니다. 기본 결과는 웹과 HTML 보고서이며 PDF·DOCX 생성은 기본 절차에 포함하지 않습니다.

## 6. 다시 사용하기와 보관

| 상황 | 해야 할 일 | 이어지는 상태 |
|---|---|---|
| 같은 기획 계속하기 | 같은 대화에 후속 요청을 입력합니다. | 앞선 업무와 연결된 새 결과를 저장합니다. |
| 앱을 닫았다 다시 작업하기 | 기존 작업 폴더를 열고 실행기의 대화 기록에서 원래 대화를 선택합니다. Codex 관찰 재연결은 부록 B를 따릅니다. | 기존 대화 문맥과 저장 자료를 이어서 사용합니다. |
| 새 기획 시작하기 | 같은 엔진 폴더에서 새 대화를 시작하고 대상 제품·목적을 말합니다. Codex 관찰 창도 새 세션을 기다리도록 다시 시작합니다. | 새 요청을 시작하며 이전 파일은 그대로 남습니다. |
| 작업 중단하기 | AI의 중지 기능으로 먼저 작업을 멈추고 상태를 확인합니다. | 관찰 창만 닫아서는 AI 업무가 취소되지 않습니다. |
| 사용 종료하기 | 답변·저장을 확인한 뒤 앱을 닫거나 CLI에 `/exit`를 입력합니다. 앱용 시작 터미널이나 직접 켠 관찰 프로그램은 Ctrl+C로 종료합니다. | 저장 결과는 작업 폴더에 남습니다. 관찰 종료는 AI 취소와 다릅니다. |

저장 결과와 내보내기 파일은 선택한 엔진 폴더의 `runtime-data/`와 `runtime-data/exports/`에서 확인합니다. 실행기 자체의 대화 기록과 제품의 결과 파일은 서로 다릅니다. 다른 PC로 옮길 때 결과 파일만으로 원래 대화가 자동 복구되지는 않습니다.

**업데이트할 때는 새 버전을 별도 폴더에 풉니다.** 기존 폴더는 작업을 종료한 상태에서 보관하고, 이전 대화를 이어갈 때는 이전 폴더를 사용합니다. 새 버전은 처음 준비 과정부터 시작합니다. 이전 `runtime-data`·DB를 새 버전에 임의로 덮어쓰거나 자동 이전된 것으로 가정하지 마세요.

결과를 공유하려면 필요한 보고서·내보내기 파일을 확인해 전달합니다. 작업 폴더 전체에는 조사 자료와 실행 기록이 있으므로 공개 업로드 전에 내용을 확인하고, 계정·인증 파일은 공유하지 않습니다.

## 7. 문제가 생겼을 때

| 증상 | 먼저 확인 | 다음 조치 |
|---|---|---|
| 시작 파일이 안 보임·바로 닫힘 | ZIP 내부 미리보기에서 실행했는지, 전체 파일을 풀었는지 | 새 폴더에 모두 풀고 알맞은 `.cmd`를 실행합니다. 오류가 있으면 마지막 메시지를 남깁니다. |
| `uv` 또는 Codex 명령을 찾지 못함 | 해당 프로그램 설치 여부 | 2절의 공식 안내로 설치한 뒤 새 터미널 또는 시작 파일을 다시 엽니다. |
| Claude CLI를 찾지 못함 | 앱용과 터미널용 중 무엇을 선택했는지 | 앱 사용자는 `start_claude_gui.cmd`를 사용합니다. 터미널 사용자는 안내된 CLI 설치를 진행합니다. |
| 로그인·이용 한도·모델 오류 | 선택한 실행기의 계정과 모델 이용 가능 여부 | 본인 계정으로 로그인하고 제공사 화면에서 이용 상태를 확인합니다. 다른 실행기의 로그인으로 대신되지 않습니다. |
| Claude가 일반 대화만 함·Skill이 안 보임 | Code/Local 및 작업 폴더 | `claude` 폴더를 선택한 새 Code 세션으로 시작합니다. Codex도 `codex` 폴더에서 시작합니다. |
| 권한 요청에서 멈춤 | 요청 대상과 화면의 승인 대기 | 필요한 작업인지 확인하고 정상 승인합니다. 조직 정책 차단이면 해당 관리자에게 확인합니다. |
| 샌드박스·Python 실행 오류 | 준비 화면의 마지막 오류, `sandbox.status` | 부록 B의 진단을 실행합니다. `sandbox.status`가 실패라면 그 오류를 기록합니다. 전체 접근으로 자동 우회하지 않습니다. |
| 웹 자료를 가져오지 못함 | 실패한 URL, HTTP 상태 또는 실제 오류 | AI에 접근 실패 범위와 대체 공식 자료를 확인하도록 요청합니다. 로그인·차단·사이트 장애를 구분합니다. |
| 대시보드가 열리지 않음·멈춤 | 첫 질문을 보냈는지, Codex 관찰 창이 켜져 있는지, 프로젝트 자동 갱신 승인이 됐는지 | 해당 HTML을 직접 열고 실시간을 선택합니다. Codex 재연결은 부록 B를 따릅니다. |
| 결과 웹이 자동으로 안 열림 | 시작 안내의 관찰 프로그램이 계속 실행 중인지, 현재 결과가 저장·내보내기 됐는지 | 부록 B에서 관찰을 다시 연결합니다. 브라우저 열기가 차단됐다면 표시된 결과 파일을 직접 엽니다. |
| 결과 웹이 비어 있음·자료를 읽을 수 없음·이전 결과가 보임 | 올바른 엔진 폴더인지, `index.html`과 `view-data.js`가 함께 있는지 | 부록 B의 화면 연결 진단 후 수동 갱신을 실행합니다. 원래 저장 자료는 지우지 않습니다. |
| 배포 파일 변경·누락 오류 | 압축을 완전히 풀었는지, 배포 파일을 직접 바꿨는지 | 기존 작업 폴더를 보관하고 공식 ZIP을 새 폴더에 다시 풉니다. 기존 기록을 지우지 않습니다. |
| Windows 다운로드 보안 경고 | 공식 배포본과 파일 이름, 조직 정책 | 신뢰할 수 있는 배포본인지 확인한 뒤 Windows가 제공하는 정상 실행 절차를 따릅니다. 조직에서 차단한 설정을 임의로 해제하지 않습니다. |

문의할 때는 **배포 버전, 운영체제, Codex/Claude와 앱/터미널 구분, 모델·추론, 입력한 질문, 오류 문구, 발생 단계, 화면 표시 여부**를 함께 남기면 확인이 쉽습니다. 캡처에서는 계정과 개인 정보를 가려주세요.

## 부록 A. 수동으로 준비하고 실행하기

**원클릭 실행을 마쳤다면 이 부록을 실행하지 않아도 됩니다.** 시작 파일을 사용하기 어렵거나 실행 단계를 직접 확인할 때만 이용합니다. 명령은 AI 대화가 아닌 **터미널**에 입력합니다.

### A-1. 준비만 직접 하기

2절의 공식 안내로 uv와 선택한 실행기를 설치한 뒤, **`judge.py`가 있는 ZIP 루트**에서 터미널을 엽니다. Windows에서는 폴더의 빈 곳에서 마우스 오른쪽 버튼 → 터미널에서 열기를 사용할 수 있습니다.

```powershell
uv run --no-project --python 3.12 python judge.py check
uv run --no-project --python 3.12 python judge.py setup --engine codex
```

Claude 사용자라면 두 번째 줄 **대신** 아래를 실행합니다.

```powershell
uv run --no-project --python 3.12 python judge.py setup --engine claude
```

`check`는 배포 파일을 확인하고, `setup`은 선택한 엔진의 실행 환경·자동 갱신을 준비합니다. `준비 완료`가 표시되면 아래에서 실행 방식을 하나만 선택합니다.

### A-2. Codex 수동 시작

**터미널 1 — ZIP 루트에서 실행 관찰 시작.** AI 세션보다 먼저 켜두며 후속 질문까지 관찰합니다.

```powershell
uv run --no-project --python 3.12 python judge.py observe --engine codex --keep-following --open
```

**터미널 2 — ZIP 루트에서 실행.** Windows CLI를 사용하는 경우 아래 순서로 진행합니다. 로그인 상태가 아니라면 `codex login`으로 먼저 로그인합니다.

```powershell
cd codex
codex login status
uv run python product-doctor.py --check-sandbox
codex --search --sandbox workspace-write --ask-for-approval on-request --config 'windows.sandbox="mxc"' --model gpt-6.1-sol --config 'model_reasoning_effort="medium"'
```

Windows 진단에서 `sandbox.status`가 `passed`이면 업무용 venv Python의 실행 검사를 통과한 것입니다. 선택 진단 `sandbox.uv_run`만 실패한 경우와 구분합니다. 실제 오류의 자세한 설명은 ZIP 안의 `codex/docs/contracts/runtime-access.md`에 있습니다.

macOS/Linux CLI에서는 위 Windows 진단과 `windows.sandbox` 옵션을 사용하지 않습니다. `codex` 폴더에서 아래를 실행합니다.

```bash
uv run python product-doctor.py
codex --search --sandbox workspace-write --ask-for-approval on-request --model gpt-6.1-sol --config 'model_reasoning_effort="medium"'
```

앱을 쓰려면 CLI 시작 명령 대신 **ZIP 루트의 터미널 2**에서 아래를 실행하고 3절의 폴더·모델·권한을 확인합니다.

```powershell
codex app codex
```

### A-3. Claude 수동 시작

앱 사용자는 준비 후 Claude 앱의 **Code → Local → `claude` 폴더**를 직접 선택하면 됩니다. CLI 설치나 아래 AI 시작 명령은 필요 없습니다. 자동 결과 연결을 사용하려면 별도 터미널의 **ZIP 루트**에서 관찰을 먼저 시작합니다.

```powershell
uv run --no-project --python 3.12 python judge.py observe --engine claude --keep-following --open
```

터미널 사용자는 **ZIP 루트**에서 아래 순서로 실행합니다. 미로그인이라면 첫 실행에서 본인 계정으로 로그인합니다.

```powershell
cd claude
claude auth status
claude --model claude-opus-5-5 --effort medium
```

직접 CLI를 시작할 때도 위 관찰 명령을 별도 터미널에서 먼저 실행하면 결과를 자동으로 연결합니다. 프로젝트 자동 갱신은 보조 경로로 유지합니다. 설치 전에 열어둔 대화라면 새 Code 세션에서 시작하세요.

### A-4. macOS/Linux 시작 파일 사용

ZIP 루트에서 터미널을 열고 사용할 명령 **하나만** 실행합니다. 이 방식은 준비도 함께 하므로 A-1을 먼저 실행할 필요는 없습니다.

```bash
bash start_codex_cli.sh
# 또는
bash start_claude_cli.sh
```

이 배포본의 macOS 앱 시작은 아래 중 하나를 사용합니다. Linux에서는 위 CLI 경로를 사용합니다.

```bash
bash start_codex_gui.sh
# 또는
bash start_claude_gui.sh
```

## 부록 B. 경로 확인과 수동 갱신

### 화면 파일의 정확한 경로 확인

**ZIP 루트**에서 사용할 엔진 하나를 지정합니다. 출력은 파일 위치 안내이며, 아직 생성되지 않은 파일도 경로는 표시될 수 있습니다.

```powershell
uv run --no-project --python 3.12 python judge.py paths --engine codex
# Claude라면 --engine claude
```

### Codex 관찰 창을 닫았거나 이전 대화를 다시 열었을 때

새 세션을 시작할 때는 A-2의 관찰 명령을 **먼저** 실행합니다. 이미 시작한 최신 세션에 다시 연결하려면 **ZIP 루트**에서 아래를 실행합니다. 최신 세션이 원래 이어가려던 대화인지 출력된 정보를 확인하세요.

```powershell
uv run --no-project --python 3.12 python judge.py observe --engine codex --latest --open
```

이 명령은 최근 세션의 기존 기록부터 읽고 이후 갱신을 관찰합니다. 끝낼 때는 Ctrl+C를 누릅니다.

### 결과 웹을 직접 갱신하고 열기

**선택한 엔진 폴더(`codex` 또는 `claude`)**의 터미널에서 실행합니다. Claude 폴더라면 마지막 값을 `claude`로 바꿉니다. 검토·저장·작업 종료를 확인한 현재 결과로 화면을 다시 만듭니다.

```powershell
uv run python web/prototypes/visual-viewer/watch.py generate --harness . --engine codex
```

준비가 끝났다는 결과가 나오면 `runtime-data/visual-viewer/index.html`을 브라우저로 직접 엽니다. 이 수동 명령은 브라우저를 자동으로 열지 않습니다. 아직 작업 중이거나 현재 검토 결과가 없으면 대기 상태를 알리고 마지막 정상 화면을 유지합니다.

### 화면 연결 진단

**선택한 엔진 폴더**에서 아래를 실행합니다. Claude 폴더라면 마지막 값을 `claude`로 바꿉니다. 현재 저장 결과와 화면 파일·데이터 형식·연결 상태를 확인하며 새 상품기획이나 웹 조사를 시작하지 않습니다.

```powershell
uv run python web/prototypes/visual-viewer/watch.py diagnose --harness . --engine codex
```

아직 기획을 저장하지 않았다면 먼저 AI 업무를 마칩니다. 저장 결과가 있는데 화면 파일이 없거나 연결이 다르면 위 수동 갱신으로 다시 만듭니다. 오류가 계속되면 진단 결과와 배포 버전을 전달하세요. 원래 저장 자료는 지우지 않습니다.

### 실행 환경 진단

선택한 엔진 폴더에서 `uv run python product-doctor.py`로 로컬 준비 상태를 확인합니다. Windows Codex의 실제 sandbox 진단은 `uv run python product-doctor.py --check-sandbox`입니다. AI가 **Windows Codex sandbox 안에서 업무 Tool을 실행할 때**는 제품의 `.venv/Scripts/python.exe`를 사용하도록 지침이 설정돼 있습니다. 이는 바깥 터미널의 준비 명령과 구분합니다.

상세 권한·오류 안내는 ZIP 안의 `codex/docs/contracts/runtime-access.md` 또는 `claude/docs/contracts/runtime-access.md`에서 읽을 수 있습니다. Codex CLI 명령의 의미는 [공식 명령 안내](https://learn.chatgpt.com/docs/developer-commands)를 참고하세요.
