# 후보 선택과 편집 가능한 업무 초안

## 업무 결과의 선택 필드

표시 역할을 나눈다. 비교 요약은 무엇을 하는 안인지, reason은 선택 근거, tradeoff는 결정을 바꾸는 조건을 담는다. 공통 조사 범위·효과 미측정 설명은 전체 조건에 모으고 여러 칸에 반복하지 않는다. 제안의 핵심 조건과 초안의 확인 입력은 유지한다.

`result.planning_decision`은 `{summary,selected_concept_ids,comparisons}`다. summary는1~1000자, selected_concept_ids는 현재 concepts ID의 중복 없는0~3개 배열이다. 비교만 요청하면 선택을 비워도 된다. comparisons는 현재 후보마다 정확히 한 번 `{concept_id,reason,tradeoff}`를 담는다. reason과 tradeoff는 각각1~1000자다. 실제 차이와 선택 조건을 짧게 적으며 시장 우선순위·매출 인증으로 쓰지 않는다. 후보가 없으면 두 배열은 비어 있다.

`concept.work_draft`는 `{title,columns,rows}`다. title은1~200자, columns는 중복 없는1~6개 제목(각1~100자), rows는1~20행이며 각 행의 셀 수는 열 수와 같다. 각 셀은1~1000자의 실제 편집 가능한 내용이고 초안 하나는32KiB 이하다. 전체 result128KiB·입력256KiB 상한도 그대로다. 표는 요구사항/업무 흐름/질문표/양식 등 요청에 맞는 내용이며 제품별 고정 답안이 아니다. 빈 양식이나 “다음에 작성한다”는 지시만으로 실제 초안을 대신하지 않는다.

일반 구체화 요청에서는 착수안 하나를 기본으로 작성하고, 사용자가 지정한 안·복수 구체화·비교만 요청을 우선한다. 최대 후보 수를 채우려고 약한 안을 추가하지 않는다. 비교만 요청에는 work_draft가 없어도 된다. 구버전은 두 필드 없이 읽는다. 이 필드의 존재·개수만으로 기획 유용성을 인증하지 않는다.

## 근거와 검토

두 필드는 메인 AI가 같은 작성·검토 턴에서 작성하는 업무 결과다. renderer·일반 코드가 추천/초안/새 사실을 생성하지 않는다. work_draft는 해당 concept의 source_ids·requirements·assumptions와 함께 검토한다. 새 관측 사실이 필요하면 현재 근거 참조에 포함한다. 후기 기반 예시·AI 설계·실제 관측 사실·내부 확인 입력을 섞지 않고, 모르는 담당자·기한·효과를 사실로 채우지 않는다. 회사의 승인 양식으로 위장하지 않는다.

사용자 읽기는 제안과 한 문장 설명 → 고객 문제 → 의미 있는 후보 차이 → 실제 초안 → 다음 행동이다. 일반 면책·ID·JSON·검사 배지를 본문마다 반복하지 않는다. 정확 모델·지원 조작·치수·안전처럼 행동에 영향을 주는 조건은 해당 내용 가까이에 남긴다. 충분한 원문·반대 경험·전체 출처·검토/조사 기록은 보존한다.

## 범위·저장·복구

새 요청에서 constraints 생략 시 hardware_allowed는true다. 이는 하드웨어·서비스·UX 아이디어를 조건부 검토할 수 있다는 뜻이며 실제 기기 조작·제조 권한이 아니다. 명시false·제외항목과 후속inherit는 유지한다. 물리 적합성을 단정하려면 기존 geometry 검토와 정확 모델·내부 치수 근거가 여전히 필요하다. 외형 치수로 대신하지 않는다.

planning_decision/work_draft는 canonical result 내부여서 기존 검토 packet→저장 후보→current result→export→web payload에 함께 보존된다. 본문 변경은 같은 turn의 새 검토·저장 버전으로 한다. 같은 버전 prepare_web_result는 복구이며 본문 편집 수단이 아니다. 이전 버전·출처/검토 이력을 덮어쓰지 않는다. planner_insights에는 기존 제목·한 문장 요약만 두며 실제 초안을 숨겨 검토를 우회하지 않는다.

completion JSON에도 저장된 planning_decision/work_draft를 그대로 포함한다. 사용자 답변은 선택 이유와 제안을 짧게 전달하고 실제 초안은 웹·보고서에서 읽는다. 별도 화면용 모델은 호출하지 않는다. 미측정 시간·토큰 절감률을 주장하지 않는다.
