## 변경과 검증 범위

결과 웹의 자동 생성·열기를 사용자 시작 런처가 관리하는 일반 코드 관찰 프로그램으로 연결했다. Codex Stop 훅의 폴더별 신뢰와 독립적으로 새 export를 감지한다. 새 모델 API·서버·프론트 디자인·외부 서비스 의존성은 추가하지 않았다. 기존 훅은 보조 경로이며 신뢰 승인을 자동 처리하지 않는다.

관찰은 안정된 export, 현재 저장 버전·검토·자료 지문·웹 binding과 workflow 종료를 확인한 뒤 기존 builder를 사용한다. 손상·중간 쓰기·미검토 결과는 마지막 정상 화면을 대체하지 않는다. 공유 열기 상태로 훅과 관찰의 중복 창 요청을 줄인다. GUI 실행 명령이 먼저 반환해도 관찰은 유지하며 사용자가 시작 터미널에서 Ctrl+C로 끝낸다. CLI 종료 시에는 자신이 시작한 관찰 자식만 정리한다.

Windows venv에서는 런처 PID와 실제 Python worker PID가 달라지는 재현 사례를 확인했다. 시작 준비는 PID 일치 대신 매 실행의 무작위 token·engine·명시적 ready 상태를 대조하도록 수정했다. 새 venv의 실제 자식 프로세스 생성·종료와 회귀검사를 통과했다.

수동 복구도 `watch.py generate --harness . --engine codex`(Claude는 `claude`)로 통일했다. 이 명령은 검토·작업 종료 확인 후 생성하며 브라우저를 자동으로 열지 않는다. 성공 후 같은 폴더의 `runtime-data/visual-viewer/index.html`을 직접 연다. 과거 `viewer.py open`의 이력 builder 경로는 현재 결과의 안전한 갱신 경로와 구별한다.

기획자 웹은 `index.html`과 같은 폴더의 `view-data.js`가 필요하다. 일반 export와 web-result JSON은 sidecar 스키마가 아니다. 보고서 보기에서 내려받는 `kitchen-harness-result.html`은 별도 공유용 단일 HTML이다. 기본 경로에서 `report.html` 파일이 생성된다고 안내하지 않는다.
