# S05 보완 비교·추가 입력 검증

2026-10-10. [최초 pilot](s05-pilot.md)의 baseline 출력 계약을 보완하고 후속 실행을 수행했다. 평가 도구는 개발 전용이며 출품 설치물에 넣지 않는다. 실제 코드·자료·질문을 고정한 신규 Temp 작업 폴더에서 기존 로그인 Codex를 사용했다. 기존 출품 설치 폴더와 DB는 변경하지 않았다.

## 추가 실행

확장 평가 실행기는 exit0으로 종료했다. 개별 CLI는 응답14개가 exit0이고, 나머지1개는 의도한5초 deadline에서 timeout(exit1)으로 보존됐다. 자동 재실행·미실행 turn은 없다. 이번 보완6회와 합쳐 실제21개 입력이며 추가 모델 시험은 하지 않았다.

| 실제 입력 | 조건 | 답변/저장 및 구조 |
|---|---|---|
| R01/R04 | 단일 Agent 선호 명시2회 | completed/held, 저장 일치·구조 통과 |
| R02 기존 탈착 기능 중복 | 제품/일반 | 둘 다 held. 제품 통과, 일반 unused_evidence 실패 |
| R03 상충 의견 | 제품/일반 | 비교 결론과 concept 보류/기획 가설을 구분. 둘 다 구조 통과 |

응답14개의 구조 계약은12개 통과·일반2개 실패다. 실패 사유는 이미 안내한 unused ref 금지 규칙에 어긋나는 출처를 evidence_refs에 남긴 것이다. 실패를 제거하거나 모델을 다시 호출해 덮어쓰지 않았다. 의미상 타당한 보류와 JSON 계약 실패를 구분한다. 이 부분 검사 차이도 소표본의 결과이며 전체 품질 우위 입증이 아니다.

제품 응답9개 모두 실제 후보 저장·최종 JSON 일치다. R06 제품은 native ID `01a122d9-492a-7ba0-9ded-a9090af17f0b`와 업무 session을 유지하고 두 turn을 만들었다. 이전 turn valid=0/새 turn valid=1, 두 후보 payload/검토/키 보존, 각 revision=0/result_version=1이다. 변경 입력으로 최초 후보를 다시 만든 것이며 실패한 같은 turn의 수정 횟수를 초기화한 검증이 아니다. 일반은 `01a122ce-f3f5-7ad2-970b-eb7dab4a76f6`에서2턴·Tool0건으로 재개됐다. 양쪽 누적 usage는 재개 전후 차이로만 계산했다.

명시한 단일 Agent 선호와 옵션을 함께 사용한15개 입력 모두 관측 위임 호출0건이다. 실행 중인 Agent에게 필요한 원문 검토를 직접 맡긴 관측이며 Tool 제거/권한 차단 증명이 아니다. 앞선 옵션 단독 실패는 그대로 유지한다.

지시문 시험은 정상 업무 자료와 분리한 **test_only 합성 파일**을 읽게 했고 데이터 지문을 유지했다. 실제 반환 근거 속에 숨긴 공격·넓은 공격 유형에 대한 방어를 입증하지 않는다. 오류 주입은 wrapper의 상태 쓰기 전 실패여서 공통 invocation 장부의 기술 재시도 상한·모델 backend 재시도 검증과 구분한다. deadline 시험은 평가 실행기가 소유한 프로세스 종료이며 출품 업무 cancel API/취소 저장·backend 중단 완료가 아니다.

독립 AI 원문 검토는 익명 Z1~Z7/W1~W5/V1~V2의14개 질문·이전 답변·원문·설명/JSON을 대조해 각각12/12, 중대 오류 없음으로 보고했다. 코드 구조 실패2개도 이 의미 검토에 포함했다. 첫 packet의 설명 누락을 수정한 뒤 설명/JSON 차원을 다시 검토했으며 원본 출력은 바꾸지 않았다. 검토자가 저장·accepted/supported 자기보고를 점수 근거로 쓰지 않았고 arm/usage/code를 주지 않았지만 문체로 운영 조건을 추정할 수 있다. 사람 심사·다른 모델 검토·시장 신규성·원문 진위·실물 적용·일반화 검증을 대신하지 않는다.

source/trace/native ID·선언한 주입 외 설치 지문·같은 원문 묶음·실제 호출 수 감사는 exit0이다. 확장 관측 입력3,846,163/캐시3,458,944/출력162,438/reasoning52,289와 **각 필드 미측정1회**를 기록했다. 보완6회 포함 이번 관측 입력6,563,539·출력234,217과 미측정1회다. 이는 서로 다른 시험 전체의 관측 합계이며 전후 효과율·전체 청구액으로 쓰지 않는다. 개발 부모/리뷰 사용량은 별도 미측정이며 이 합계에 임의로 더하지 않는다.

## 검사·보존 범위

제품82개·평가18개·개발 체계22개 일반 회귀는 프로젝트 잠금환경 Python3.12.14에서 실제 exit0이다. 제품 manifest/개발 doctor, 새 ZIP 재현 검사도 exit0이다. 시스템 Python3.14.7에서 먼저 수행한 검사와 선언 환경을 구분해 잠금환경으로 재확인했다. 누적 관측 누락·다른 UUID·카운터 감소를0으로 채우지 않는 경계, 실제 wrapper 오류1회 후 정상 호출, 별도 공격 파일과 업무 자료 분리, 원본/기존 archive 보호·사적 파일 제외를 포함한다. 일반 코드 회귀는 native 업무 품질 평가와 구분한다.

원문 prompt/trace/SQLite/최종 출력과 동결 소스는 Git 제외 `.harness/s05-repeat-20261010` 및 `.harness/s05-extended-v3-20261010`에 보존했다. 보완6회 runner SHA는 `98cf05fc39d518f859ec0b5fa342fa595e76465517a78b68d78cfe7cc5b78021`, 확장 runner SHA는 `e2f8d1a3ef0b8f6b649f478026031492b0e1c1449ba1aeee7ef140d083ca13e1`이다. 실행 당시 helper도 사본으로 보존했다. 이후 소스의 감사/실패 관측 보강을 과거 실행 당시 기능으로 설명하지 않는다.

작업 장부의 task 인수·개별 검사 receipt·전체 complete gate·native 세션 종료는 별도다. 부모 `/root`가 현재 turn에서 실행 중인 상태를 임의로 idle/close로 바꾸지 않는다. 실제 complete 관측은 Git 제외 `.harness/s05-followup-completion-observation.json`에 보존하며 본문의 검사 exit0을 장부 전체 완료 통과로 바꾸지 않는다.

인간 공수는 [측정 절차](../evaluation/human-effect-protocol.md)의 실제 기록이 필요하다. [자료 후속 조사](../data/s01d2-followup.md)에서 청소 불편·내부 치수를 확보하지 못했고 해당 물리 설계 확정은 보류한다. Claude/Gemini는 [파일 준비 검사](portable-product.md)만 통과했다. 전체 심사 품질·효과·최종 제출은 미완료다.
