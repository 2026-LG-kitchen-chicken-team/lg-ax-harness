## 1. 구현한 변경

- 자발적 선택·예상한 제약과 직접 부정 경험을 함께 보존하고, 불편의 존재와 제품 결함·개선안 채택을 구분한다.

## 4. 자동 갱신·관찰 수집

실제 입력 전에 프로젝트 로컬 viewer/관찰기를 설치했다. 업무 실행 중 root가 viewer build/open/hook이나 trace importer를 직접 실행하지 않았다. 독립 공개 명령 감사에서 N1 Codex42개·Claude38개 shell 명령 중 해당 직접 호출0개를 확인했다. N2의 추가 감사 범위는 JSON을 따른다.

- Codex 결과 갱신은 정상 신뢰 절차로 활성화한 Stop 훅이다. 별도 실제 rollout follower에서는173사건·요청2·종료2를 관측했고 F 실제 종료 후 follower만 정리했다. follower는 Codex native 훅이나 기록 가져오기와 다르다. 관찰기 정리의 종료 코드와 업무 A/F의 exit0도 구분한다.
- N1 Claude는 native hook 수신107사건·요청2·종료2다. SessionStart1, UserPromptSubmit2, PreToolUse51, PostToolUse49, PostToolUseFailure2, Stop2이며 열린 Tool 호출0이다. 타임스탬프는 hook 수신 기준이다. 보관 snapshot 검사와 현재 화면 재생을 구분한다.
- N2 Claude는105사건·요청2·종료2이며 Tool50개가 모두 반환됐다. 공개 shell 명령 A24/F8개에서 viewer/관찰기 직접 호출0개다. native Skill 도구 호출과 두 SKILL.md의 명시 읽기는 공개 감사에서 미관측이다. Read6개의 대상은 중간 dump·완료 본문 등이므로 간접 소비/자동 주입 여부는 미확인이다. 설치·실행 코드 호출과 Skill 본문 소비를 같은 증거로 세지 않는다.
- Claude 관찰 기록에는 명령에 따른 Skill 매핑42개와 관측65개가 있다. 이 매핑은 의미 독해 인증이 아니다. native session→업무 DB의 직접 결속은 해당 관찰 파일에서 `unverified_native_session`이며, 현재 업무 결과 일치는 별도의 저장/웹 파일 감사로 확인했다.

이번 N은 부모 단독이다. 제품은 메인1·업무Skill6·선택 역할3을 유지하지만 이번 사건에 실제 자식 실행은0이다. 과거 M2의 세 역할 반환/반영 기록을 이번 N 실행처럼 표시하지 않는다. 구조 정의·실제 실행·기록 재생을 나눠 시연 자료에 사용한다.

자동 생성 파일의 현재 binding·본문·출처·내보내기 정보·후속 갱신은 검사했다. 그러나 자동 접근 검토가 로컬 `file://` 화면을 거절했고 사용자의 실제 열림 확인도 받지 못했다. `opened_sessions` 기록만으로 브라우저가 열렸다고 판정하지 않는다. 다른 브라우저/HTTP로 차단을 우회하지 않았다. 새 N 화면의 렌더링·클릭·확대·인쇄 시각 검수는 미실행이며 이전 M2 화면 검수를 대신 쓰지 않는다.

## 5. 코드 검사·시간·토큰 해석

제품 검사443개(1개 skip), 웹116개, N1/N2 자산55파일, 개발 validate가 실제 exit0다. N2는 두 Skill 지침과 manifest만 바뀌어 자산/설치/지문을 재검사했고, 제품/웹 코드를 바꾼 것처럼 전체 검사를 재집계하지 않았다. receipt 경로·입력 SHA·결과 SHA는 JSON에 있다. 푸시한 `d53312f`의 원격 CI 두 실행은 GitHub가 계정 결제/지출한도 사유로 네 job 모두 시작하지 않았다고 반환했다. 두 사유 중 무엇인지는 확인하지 않았다. 이는 제품 검사 실행 실패와 다르며 로컬 통과로 원격 CI를 통과 처리하지 않는다.

위 시간은 실제 해당 업무의 native 종료 관측값이다. 모델의 HTML/PDF/DOCX/XLSX·이미지 제작/레이아웃 검수를 기본 업무에서 제외하고 일반 코드가 정형 결과를 그렸다. 나머지 시간을 전부 순수 추론으로 귀속하거나 이 표만으로 일반 최적 모델/추론 수준을 확정하지 않는다.

관측 usage는 JSON의 원필드와 범위를 따른다. Codex F는 A 누적값을 빼 해당 입력 차분을 사용했다. cached input은 input의 부분집합이며 reasoning output도 output에 다시 더하지 않는다. Claude는 해당 turn의 고유 assistant 메시지 ID별 input/cache creation/cache read/output 합을 나눠 보존했다. raw input만을 전체 입력으로 쓰거나 cache를 중복 합산하지 않는다. 부모 관측량과 backend 전체 청구는 다르며, 청구·절감률·사람 공수 절감률은 계산하지 않았다.

관찰/화면 갱신은 일반 코드로 처리했고 별도 시각화용 모델 호출은 관측하지 않았다. 이는 추가 모델을 써서 화면을 생성하지 않는 구현 근거이며, 전체 업무 토큰이 기준선보다 몇% 줄었다는 실험 결과는 아니다.

## 6. 증거 보존과 다음 경계

원질문·본문·native 로그·DB·인증·프로젝트 로컬 설정은 Git 밖 `LG-AX-web-neutral-N-20261015`에 보존한다. 공개 기록에는 SHA·판정·관측 수치·검사 범위만 남긴다. 회복 준비 중의 설치 로그명 충돌·예비 준비 실패는 입력 전 오류로 보존하고 새 설치 기록을 분리했다. N2 A의 UI 관측시각 수기 오기는 별도 실제 관측/전송 receipt로 정정했으며 원래 receipt와 실제 native 시계는 바꾸지 않았다.

변경 담당 두 worktree의 필요한 ignored 검사/장부 증거를 외부에 바이트 그대로 보존한 뒤 관리 도구로 archive했다. 원문·개인 설정·의존성 환경은 커밋하지 않는다.

평가 helper가 보관을 위해 옮긴 N2 F의 최종 runtime77파일은 동일 GUI 작업 폴더로 바이트 그대로 복원했다. 이는 원래 최종 답변의 파일 경로를 유지하는 정리이며 자동 열림/렌더링 증거가 아니다. 원래 archive와 불변 snapshot은 그대로 보존했다.
