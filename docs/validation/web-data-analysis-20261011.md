# 팀 웹의 기본 자료 선택 논의 검토

2026-10-11. 사용자 제공 카톡·스크린샷과 현재 저장소 코드로 판단했다. 사용자는 웹 구현이 아직 원격에 올라오지 않았다고 확인했다. 웹팀이 개발 중이라는 상태를 유지하며 실제 실행 코드·자료 연결 경로는 미검토다. 아래 제안은 채택 결정이나 구현 완료가 아니다.

## 확인된 사실

- 기본 자료는 새 하네스 저장소에 작성한 것이다. 웹팀이 선택창을 만들었다는 카톡과 구분한다. `models.json`에는 모델·제품군·사양 식별 정보가 있고 실제 리뷰·사실 근거는 `sources.jsonl`에 있다. 미리 작성한 AI 최종 답변을 뜻하지 않는다.
- v3는 냉장고3모델·후기6발췌·사실19개다. 스크린샷의 S836GBB122/B502S33/T876MQQ012는 **모두 냉장고**이며 냉장고·전자레인지·식기세척기 각각의 모델이 아니다.
- 현재 기본 경로는 `product-tools/product_tools/contracts.py`의 `data/business/lg-kitchen-v4`다. v4는 위3냉장고에 MWJ25E 전자레인지·DUBJ2EA 식기세척기를 추가한5모델·8후기·26사실이다. v3는 과거 기록으로 보존한다.
- 자료 재생성 스크립트는 기록한 원문 발췌·사실을 재현한다. 최신 웹을 자동 조사하는 crawler가 아니다. [v3 조사 기록](../data/real-research.md)·[v4 근거와 한계](../data/kitchen-v4.md)를 따른다.
- 현재 Agent·외부 조사 Skill은 **저장 자료 우선, 부족하거나 최신 확인이 필요하면 조건부 외부 조사**다. `skills/web-evidence-collection/SKILL.md`는 충분한 저장 자료가 있으면 외부 조사하지 않도록 한다. 대겸이 기대한 요청마다 새 조사와 차이가 있다.
- 현재 `import_evidence`는 `dataset.check_scope`로 기존 등록 모델을 확인하고 새 catalog에도 기존 `dataset.models`를 복사한다. 등록 모델에 근거를 추가하는 경로이며 임의 새 모델을 자동 발견·등록하는 범용 경로가 아니다. 고정 목록 문제는 화면 선택창만 바꿔 해결되지 않는다.

## 아직 확인할 수 없는 사항

스크린샷의3모델은 v3 전체와 v4 냉장고 목록에 모두 해당한다. 화면만으로 v3 사용·v4 제품군 필터·예전 설치본 여부를 확정할 수 없다. 웹 질문이 기존 Codex 실행기를 호출하는지, 다른 모델 API를 호출하는지도 원본 없이 판단할 수 없다.

웹 질문 입력창 자체는 모델 API 사용의 증명이 아니다. 기존 실행기의 Skill·상태·근거 계약을 유지하는 연결도 가능하다. 별도 모델 실행을 추가했다면 인증·권한·Skill 로딩·취소·사용량·저장/응답 연결을 실제 코드로 검토해야 한다.

기존 [웹 착수 범위](../../web/README.md)와 [공유 계약](../contracts/team-web-kitchen.md)은 저장 결과 탐색을 첫 후보로 두고 웹 질문 실행을 별도 단계로 둔다. 팀원이 질문 입력을 구현했다는 보고는 범위가 확대된 상태이며 잘못된 구현이라고 단정하지 않는다. PM 황대겸의 소유 범위를 유지한다.

## 원인과 영향

논점은 자료가 누구에게서 왔는지와 자료를 언제 조사할지를 함께 말한 데 있다. **자료는 하네스에서 왔다**는 설명이 맞다. 저장 자료를 초기 업무 기본값으로 둔 현재 설계 역시 내가 구현한 책임 범위다. 웹 선택창은 팀원 구현이며 저장 자료 사용 정책과 별개의 결정이다.

저장 근거는 출처·관측일·문서 버전·당시 결과의 재현·후속 질문·회귀 검증에 필요하다. 하지만 관측일을 숨기거나 등록5모델만으로 임의 모델·제품군 전체를 조사했다고 표시하면 기능을 과장한다. 이 프로젝트의 현재 제한은 등록 자료 범위이며 실제 최신 조사·새 모델 자동 등록까지 완료한 것이 아니다. 검토한 공식 제출 안내는 이 고정 자료 목록을 필수로 요구하지 않는다.

## 제안 — 미채택

1. 사용자에게 제품군 또는 모델과 업무 요청을 받는다. 데이터 버전 선택은 재현/검토 화면에서만 필요할 때 노출한다.
2. 새 업무에서 최신성이 필요한 항목과 자료 부족을 판단하고 필요한 실제 조사를 수행한다. 임의 모델 지원에는 정확 모델 등록·문서 연결·근거 검증 경로를 먼저 추가해야 한다.
3. 조사 결과의 URL·원문 위치·관측일·모델·문서 버전을 저장한다. 같은 조건의 후속 요청은 검증한 근거를 재사용하며 조건·자료 변경은 새 버전으로 남긴다.
4. v3/v4는 알려진 자료의 회귀·재생 자료로 보존한다. 모든 대화마다 동일 페이지를 다시 조사하도록 강제하거나 `models.json`을 삭제하지 않는다.
5. 웹 원본이 도착하면 PM과 실제 입력→실행기→Skill/Tool→저장→화면 흐름을 대조한다. 저장 결과 재생과 새 AI 실행, 과거 자료와 이번 조사 자료를 표시한다.

이 제안은 현재 Codex 중심 실행 선택을 바꾸거나 자체 모델 API를 채택한 결정이 아니다. 현재 제품군 입력 보완도 등록된 사례 범위를 넓혀 받는 기능이며 자동 최신 조사·임의 모델 지원과 구분한다.
