# S05 첫 실제 입력 평가 결과

2026-10-10. [평가 방법](../evaluation/s05-native-pilot.md), [6개 질문](../../evals/judge/s05-cases.json), [개발 평가 코드](../../evals/runner/native_eval.py). 출품 코드는 모델 호출기를 추가하지 않았다. 기존 설치 폴더·상태와 사용자 전역 설정을 변경하지 않고 새 Temp 폴더6개에서 실행했다.

## 결과와 해석

실제 자료의 정상 기획(R01)·치수 부족(R04) 두 사례를 개선 전·후·강한 일반 프롬프트로6회 실행했다. CLI6회 모두 exit0이고 timeout/실행 실패는 없었다. 제품4회는 최초 후보0에서 저장되었고 최종 JSON과 실제 저장 result/assessment가 일치했다. 각 요청/turn/candidate가1개였고 설치 파일·동결 소스의 지문 변화가 없었다. baseline2회는 Tool을 호출하지 않았다.

별도의6출력 익명 원문 검토에서 목적·제약/모델 범위/불편→기능→제안/출처 의미/미확인·상충·보류/답변·JSON상태 각각2점으로6출력 모두12/12였고 중대 의미 오류는 발견되지 않았다. 이 검토는 독립 AI 평가자의 저장 발췌·factual_summary 대조이며 인간 심사, 실제 제품 측정, 원사이트 실시간 재검증이 아니다. 출력 스타일·상대 파일명은 남아 있어 완벽한 눈가림 실험으로 주장하지 않는다. 심사 품질 우위는 입증되지 않았다.

baseline2회는 구조 계약 검사를 통과하지 못했다. R04는 사용자 요구를 source_ids=[]인 pain에 넣었고, R01은 root assumptions를 문자열 대신 객체 배열로 작성했다. **첫 비교 프롬프트가 이 두 제약을 명시적으로 설명하지 않은 한계도 확인했다.** 제품 조건은 설치 계약에서 상세 규칙을 읽을 수 있었다. 따라서 이 실패를 하네스의 답변 정확성 우위 근거로 쓰지 않는다. 후속 평가 코드의 중립 양식을 보완했지만 보완판 baseline은 아직 실제 재실행하지 않았다. 기존 실패 기록은 보존했다.

## 변경과 검사

- open_request_bundle: 정확한 모델 scope의 근거를 한 번 반환하고 원문 중복을 줄였다. 조회/바이트 잘림·누락 ID를 밝히고 stale/실패/취소/수정 소진 상태의 handle을 유지한다.
- 저장 자체의 구조·assessment 검사를 이용해 선행 validate/review/get_turn을 조건부로 줄였다. 원문 의미 검토와 최초0/수정1/2·실패 후보 기록은 유지한다. 누락/null assessment도 유효 후보이면 저장 transaction에서 실패를 기록한다.
- 짧은 저장 양식을 추가했다. 내부 필드 추론을 위한 소스 읽기와 긴 Windows JSON 명령을 줄일 목적이며 모든 토큰 감소를 이 하나의 변경 효과로 분리하지 않는다.
- 개발용 평가 도구는 소스/자료/프롬프트 지문, native ID, 종료/중단, 실패·미측정, 누적 차이, 원문 결과를 기록한다. 후처리 실패도 이미 관측한 usage/native ID를 지우지 않고 전체 미측정 합계를0으로 바꾸지 않는다.

실제 일반 코드 검사: 제품 회귀79개, 개발 평가 경계9개, asset 지문/링크 검사와 실제6회 결과·설치/소스 지문 감사. 모두 exit0이다. 평가 경계 검사에는 실제 stub child의 실패·timeout 종료도 포함되며 이것을 제품 AI 품질 검사로 세지 않는다. 현재 PC의 일반 검사 Python3.14와 설치 업무의 uv 환경을 구분한다. 코드 리뷰에서 발견한 동결 파일 목록 반환형, stale bundle handle, 웹 Tool 판정, 후처리 usage 보존 문제를 수정했다.

## 증거와 남은 작업

원문은 Git 제외 `.harness/s05-live-20261010/`의 prepared/started/results/audit JSON, 각 native trace·final·prompt, runner-executed.py와 runner-inputs.json에 남겼다. 실제 runner를 실행한 뒤 양식/실패 보존을 보완했으므로 실행 당시 원본을 별도 보존했다. Temp 실행 폴더는 prepared.json에 있으며 자동 삭제하지 않았다. 익명 packet·맵·독립 리뷰도 별도 기록한다.
