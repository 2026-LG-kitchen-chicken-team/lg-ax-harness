# 기획자가 비교하고 다음 작업을 시작하는 결과 화면

2026-10-18. 사용자가 승인한 후속 작업 세 가지를 구현했다. AI가 작성한 짧은 제안명·요약을 실제 저장 경로에 연결하고, 웹·보고서의 비교와 후속 질문을 보완하며, 세 제품군의 새 실제 기획 결과와 화면 상태를 검사했다. 촬영·외부 유료 API·새 프레임워크·모델 기본값 변경은 없다.

## 결과와 구현

기존 화면은 짧은 제안명과 요약을 읽을 수 있었지만, 정상 업무 Tool에는 이를 작성·보관·전달하는 연결이 없었다. `save_and_export`와 `prepare_web_result`가 선택적인 `planner_insights`를 받아 같은 결과 버전에 저장하도록 연결했다. 작성은 기존 상품기획 턴에서 수행하고 화면 렌더러는 모델을 호출하지 않는다.

- 제안 카드는 **짧은 제안명 → 요약 → 기획 배경 → 다음 행동** 순서다. 다음 행동은 담당 역할·입력 자료·완료 산출물을 작성하도록 Skill에서 안내한다.
- 제안 비교표는 저장된 후보의 요약과 시작할 작업을 함께 보여준다. 화면 코드가 순위·효과·채택 결론을 만들지 않는다.
- 제안별 후속 질문 복사와 직접 선택 가능한 질문 본문을 제공한다. 세션·질문·결과 버전·모델·자료 버전을 포함해 다른 작업과 섞이지 않게 한다.
- 자료 범위는 등록 후기·제품자료·모델·관측일로 표시한다. 제안별 인용 수와 전체 조사량을 구분하며, 이를 독립 고객 수나 시장 대표성으로 표시하지 않는다.
- 저장 관리·전체 조사·개발 진단은 접힌 상세로 옮겼다. 원문·적용 조건·하드웨어/내부 치수 조건·실제 실패 안내는 보존한다.
- 보고서는 같은 제목·요약·배경·다음 행동을 사용하고 제안의 전체 작동 설명을 기본으로 펼친다. 인쇄에서도 전체 제안 설명과 필요한 조건을 보존하고 조사 전량은 선택 부록으로 둔다.
- 이전 결과에 표시 문구가 없으면 긴 원문을 본문에 그대로 표시한다. 긴 문장을 제목으로 만들거나 화면에서 임의 요약하지 않는다.

`planner_insights`는 현재 결과 ID·길이·형식을 검사하고 코드가 전체 binding을 붙인다. 다른 질문·버전의 표시 문구는 사용하지 않으며 같은 버전의 기존 파일을 다른 내용으로 덮어쓰지 않는다. 표시 파일 실패는 이미 수락한 기획 저장을 되돌리지 않고 별도 오류로 반환한다. 같은 버전으로 복구할 수 있다. 요약 300자 절단도 제거해 말미 조건이 사라지지 않게 했다.

## 새 실제 AI 기획 3건

GPT-6.1 Sol / medium / Codex CLI로 새 격리 폴더에서 제품군당 한 번 실행했다. 기존에 관측한 실제 공개 자료 219객체(후기87·제품자료132)를 byte 그대로 복사하고 각 제품군의 등록 본문 전량을 사용했다. 새 온라인 조사나 실제 원페이지의 최신 재관측은 아니다. 답안·기획 제목을 제공하거나 제품별 분기 코드를 추가하지 않았다.

| 제품군 | 선택·전달 자료 | 실제 관측 시간 | 새 AI가 작성한 제안 |
|---|---:|---:|---|
| 냉장고 | 56객체: 후기23·제품자료33 | 383.578초, 약6분24초 | 소음 상담 약속 이어보기 / 냉동 보관 요구 먼저 확인 |
| 식기세척기 | 81객체: 후기38·제품자료43 | 353.875초, 약5분54초 | 세척 후 결과 점검 / 내 식기 배치 연습 |
| 전자레인지 | 82객체: 후기26·제품자료56 | 410.375초, 약6분50초 | 시간설정 경로 확인 / 디자인과 비용의 선택 확인 |

세 실행 모두 process exit0, 요청 재발송0, 저장·표시 문구·웹 데이터의 같은 버전 연결과 입력 코드/자료 불변을 확인했다. 실행 중 일반 명령의 비정상 종료는 각각4·2·3회 있었고 Agent가 복구한 뒤 완료했다. 첫 시도부터 오류가 전혀 없었다는 뜻은 아니다. 세 업무는 같은 기기에서 병렬 실행한 각1회이므로 모델 우위·평균 시간·절감률의 비교 근거가 아니다.

**버전 범위:** 실제 AI 업무는 `4a6ecd8eb4155a557ab85dcb6d8a11bb1be96506` 설치본에서 실행했다. 그 저장 결과를 최종 소스 `0fbbd1eaaa9d0714e07576d6492ead682b4db593`의 렌더러로 다시 표시했다. 이후 변경은 중복 지침 축약과 화면 표현·생성 자산이다. 지침 축약본에서 새 전체 native 업무를 다시 실행한 것으로 합산하지 않는다. 핵심 표시 저장 코드는 동일하며 최종 Codex·Claude 지침 로더와 설치 경로는 코드 검사에서 확인했다.

독립 검토자는 여섯 제안의 인용 등록 원문20객체와 기존 기능 사양1객체를 읽고 출처·요약·조건·다음 행동을 대조했다. 이 범위에서 수정할 P1/P2 의미 결함을 찾지 못했다. 전체219객체의 의미 인증이나 실제 서비스 중복 조사 완료를 뜻하지 않는다. 현재 하드웨어 추가 금지 조건의 결과는 안내·서비스·구매 판단 지원 기획이며, 새 하드웨어 구현이나 효과가 입증된 제품으로 소개하지 않는다.

## 화면으로 확인한 동작

최종 빌드의 새 로컬 전용 읽기 서버를 데스크톱 브라우저로 검사했다. 세 제품군의 실제 저장 export·웹 결과·insights는 SHA와 전체 binding이 일치하며 단일 HTML에도 같은 결과를 담았다.

| 확인 과업 | 실제 관측 |
|---|---|
| 제안 이해·비교 | 세 제품군의 짧은 제목·요약·배경·다음 행동 표시. 비교표의 두 번째 제안 링크로 해당 카드 이동 |
| 근거 찾기 | 식기세척기 제안에서 후기 본문과 URL 펼침. 보고서 근거11 클릭 후 부록이 열리고 같은 원문으로 이동 |
| 후속 요청 | 복사 성공 안내와 직접 선택 가능한 질문 본문 표시. 결과 식별정보와 `translate=no` 확인 |
| 웹 → 보고서 | 세 제품군의 같은 제안명·요약·조사 범위 연결. 내부 렌더러 설명은 일반 보고서에서 감춤 |
| 첫 결과 대기 / 읽는 중 | 각각 다른 문구와 로딩 표시. 실제 AI 작업의 가상 진행률을 만들지 않음 |
| 최초 읽기 실패 | HTTP/내부 파일명 대신 복구 안내·다시 불러오기 표시 |
| 기존 결과가 있는 상태의 읽기 실패 | 마지막 정상 기획안을 보존하고 새 결과 읽기 실패만 안내 |
| 정상 복구·새 결과 수신 | 실패 안내 해제. 열어둔 보고서는 이전 결과임을 표시하고 ‘최신 보고서 보기’로 전환·알림 해제 |

대기·지연·HTTP503·저장 결과 교체는 제어한 UI 시험이다. 새 외부 장애·실제 온라인 재조사가 아니다. 정상 결과 탭의 JavaScript error/warn은 미관측이다. Browser Use의 가상 클립보드는 OS 복사 값을 읽지 못해 외부 앱 붙여넣기까지 확인하지 않았다. 직접 선택 가능한 질문 본문을 함께 제공한다.

사용자 로컬 검토 폴더 `LG-AX-planner-decision-AF-20261018/preview/{fridge,dishwasher,microwave}/result.html`에는 새 실제 기획3건을 담았다. 화면 캡처14장은 같은 폴더의 `screenshots/`에 보관한다. 원문·DB·원시 native 로그·개인 파일 경로는 Git에 넣지 않는다.

## 검사와 사용량

최종 소스의 관련 전체 검사864개 중862통과·2환경제외, 실패0, 각 명령 exit0다. 제품525개 중 선택 잠금 의존성 설치1제외, 웹193개 중 Windows symlink1제외, 평가146개 통과다. 프로덕션 빌드도 exit0다. 기존 잠금 의존성을 물리 복사해 빌드했으며 새 설치/다운로드 성공으로 기록하지 않는다. manifest 선언71파일과 앱 원본44파일·생성 HTML을 byte 대조했다. 검사 receipt와 로그·입력 SHA는 동반 JSON에 기록했다.

초기 검사에서 지침 중복으로 로더 응답 상한65536바이트를 넘었다. 보호 상한을 키우거나 원문을 자르지 않고 설명 중복을 줄였고, 두 실행기 로더19검사 및 최종 전체 검사에 통과했다. 생성 도중의 첫 웹 검사1실패는 격리 검사와 최종 동결본에서 재현되지 않았다. 빌드 junction 의존성 열거 오류는 기존 잠금 의존성의 물리 복사로 해결했다. 처음 실패한 기록은 보존했다.

관측된 부모 terminal snapshot 합계는 input9,143,371, cached input8,662,784, output56,779, reasoning output5,344토큰이다. cache는 input의 일부, reasoning은 output의 일부이므로 합산하지 않는다. 전체 backend 청구·child 중복은 unknown이다. 캐시 비율을 하네스 절감률로 제시하지 않으며 새 화면 렌더링 모델 호출은0이다.

## 남은 인수 범위

- 실제 기획자가 제안을 고르고 수정 지시를 보내는 짧은 사용 확인. 화면이 뜬다는 검사와 실제 업무 편의 평가는 다르다.
- 새 Claude AI 업무, Codex GUI·Claude GUI, OS별 자동 열기 및 모바일·인쇄 쪽수는 이번 AF 작업에서 새로 실행하지 않았다. 기존 인수 기록을 이번 결과로 합산하지 않는다.
- 기획 요약에는 일부 감사 문체가 남을 수 있다. 정확성을 유지하면서 작동 방식·사용자 가치 중심으로 다듬는 품질 개선 후보이며 현재 데이터로 완성 효과를 확정하지 않는다.
- PR30의 변경을 검토한 뒤 통합 버전으로 심사위원 ZIP을 빌드·검사·배포한다. 이번에는 PR 후보를 갱신하고 main·기존 릴리스 ZIP은 교체하지 않는다.

이 기록은 기존 [AE 화면 사용성 검사](planner-usability-AE-20261018.md)의 후속이다. 이전 실행 수와 이번3건을 같은 최종 버전 회귀 분모로 합치지 않는다.
