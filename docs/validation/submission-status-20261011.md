## 남은 작업과 완료 조건

**내부 제작·제출 작업**

1. **제출 문서 정합성 정리.** submission/README의 v0.1.0 안내·자동 소스 설명, demo-plan의 이미 수행한 항목을 통째로 pending 처리한 내용, runbook의 오래된 비교/시연 근거를 v0.2.3·v5.5 완료 범위에 맞춘다. 수행한 기록·보존 실패·새 미완료를 구분한 최종 콘티/발표 주장 목록이 완료 기준이다.
2. **별도 관찰 화면 확인·30초 실제 녹화.** Agent/Skill/Tool을 혼동하지 않고 실제/정의/재생·부분 사용량·미측정·실패/누락을 읽을 수 있는지 확인한다. 새 역할 그래프나 UI 프레임워크는 공식 필수가 아니다. 검증한 실행 화면/관찰 창을 녹화해 음성·자막·가독성·내보내기를 확인한다.

**외부 증거/접근이 필요한 보완**

- **효과:** 팀원의 실제 사람 활동시간·원본 산출·수정 부담·귀속 가능한 사용량/청구를 받아 같은 자료/완료 기준으로 검토한다. 공식은 기대효과/확인 방법을 요구하므로 측정이 없으면 가설/측정계획으로 설명하고 확정 절감률을 쓰지 않는다.
- **범용 지원:** Claude/Gemini에 대한 설치 사본 제공과 실제 native 업무 지원을 구분한다. 해당 지원을 주장하려면 인증 가능한 환경에서 발견·정상·보류·후속·저장/export·usage 원본을 인수한다. 현재 미인수는 실험/지원 목표로 명시한다.
- **범위를 넓힐 새 근거:** 청소/내부 치수 관련 제안을 확정하려면 정확 모델의 신규 실제 원문/실측 근거가 필요하다. 현재 조사 단계는 종료했으며 해당 근거가 없는 제안은 보류한다.
- **일반화 품질:** 별도 담당자가 개발자 비노출의 독립 원문·질문 묶음을 보관하고 구현 동결 후 사전 상한을 둔 한 묶음을 평가하는 별도 인수가 필요하다. 현재 알려진4입력/새 표현을 수백 심사 질문의 일반 성공률로 쓰지 않는다. 공식 숨은 문제 수·자동 채점 방식은 미확인이다.
- **운영진 안내:** 실제 파일 제출 마감/경로/파일명·영상 규격·변경 공지·가산점 확정 방식이 필요하다. 공개10월21일은 심사일이며 팀 제안서의10월20일 계획을 공식 파일 제출 마감으로 확정하지 않는다.

이 감사는 수정 마감에서 닫은 절별 출처·경험/선호/기대·평가 제약 전달을 다시 미완료로 세지 않는다. 현재 제품 시험판 배포는 유지하며, 이번 감사 문서 작성만으로 새 제품 릴리스를 발행하지 않는다.
