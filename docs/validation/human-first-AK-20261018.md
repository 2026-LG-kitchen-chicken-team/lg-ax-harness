# 기획자가 선택하고 바로 작업하는 결과로 개편

2026-10-18. 사용자 승인 1~5번을 구현했다. 후보 비교·착수안 선택·실제 업무 초안, 사람 중심 Skill 문체, 결과 웹·보고서, 진행 대시보드, 현재 결과의 완료 연결을 함께 수정했다. 기존 원본 checkout의 팀 작업은 변경하지 않고 독립 worktree에서 통합했다. 촬영·새 릴리즈·최종 네 환경 비교는 이번 범위에 포함하지 않았다.

## 달라진 사용 흐름

| 항목 | 구현한 동작 |
|---|---|
| 기획 결과 | AI가 후보별 선택 이유와 고려점을 비교하고, 먼저 추진할 안과 수정해 쓸 실제 초안을 작성한다. 단순히 나중에 초안을 만들겠다는 작업 목록으로 끝내지 않는다. |
| 작성·검토 Skill | 핵심 설명과 조건을 간결하게 쓰고, 반복 진단·포괄적 경고는 줄인다. 판단을 바꾸는 실제 조건, 구현 단계와 검증 계획은 보존한다. |
| 결과 웹 | 선택 이유 → 후보 비교 → 제안의 전체 작동 설명 → 실제 초안을 우선 보여준다. 저장 관리·전체 원문·조사·진단은 필요한 상세에서 확인한다. |
| 보고서 | 같은 저장 결과와 버전을 사용한다. 선택 이유·고려점·실제 초안을 담고, 전체 조사 원문은 선택 부록으로 둔다. 핵심 적용 조건은 본문과 인쇄에서 유지한다. |
| 진행 화면 | 주요 상태 하나와 필요한 행동을 먼저 보여준다. 실제 팩토리·Agent·Skill 흐름은 유지하고 CLI·내부 정보 패널은 기본으로 닫는다. 가상 진행률이나 추정 완료 시간을 만들지 않는다. |
| 완료·자동 열기 | 현재 요청의 native 종료, 연결된 역할의 반환 이후 메인 종료, 같은 저장 결과·웹 버전을 함께 확인한 뒤 결과 열기를 요청한다. 취소·중단·미반환 역할을 완료로 표시하지 않는다. |

비교와 초안은 화면 코드가 만들어 넣는 답변이 아니다. 기존 상품기획 AI가 선택적 `planning_decision`과 `concept.work_draft`를 작성하고 공통 Tool이 검토·저장·export·웹·최종 답변으로 전달한다. 계약과 제한은 [planning-drafts.md](../contracts/planning-drafts.md)에 있다. 기존 결과는 새 필드 없이도 읽는다. 기본적으로 한 안을 구체화하되 명시적인 비교 전용·복수 선택 요청을 존중한다.

새 요청에서 이유 없이 하드웨어 제안을 제외하던 기본값을 허용으로 바꿨다. 사용자가 명시한 금지·후속 상속·제외 조건, 치수·안전·기존 기능 대조는 유지한다. 하드웨어 제안 허용은 실물 제작이나 기기 제어 권한을 뜻하지 않는다.

## 새 실제 업무 실행

GPT-6.1 Sol / medium / Codex CLI로 격리 설치에서 냉장고 상품기획을 한 번 실행했다. 새 질문은 실제 사용 후기에서 후보를 비교하고 착수안과 수정 가능한 초안을 요구했다. 기존 AF 실제 등록 자료 **56객체 전량(후기23·제품자료33)**을 사용했다. 새 온라인 수집, 독립 고객56명, 시장 대표성 평가로 계산하지 않는다.

| 관측 항목 | 결과 |
|---|---|
| native 실행 | **341.658초, 약5분42초**, process exit0, 질문 재발송0 |
| 작성 결과 | 후보2개 비교, 착수안1개, **8행의 접수·인계·연락 약속 기록 초안** |
| 대안 | 효율 개선의 하드웨어 제안도 작성하되 추가 기술·사업 입력 조건을 유지 |
| 저장·전달 | completed, 결과 version1, export·웹·insights의 현재 binding 일치 |

실행 소스는 `9425978`, 최종 표시 소스는 `5ae52a2b3f6afd919f4af136e6fdf729a3f5ee5a`다. 이후 변경은 조건 보존 지침·로더 receipt 재사용 검사·표 배치·복사 실패 처리·생성 자산과 검사 기대값 수정이다. 최종 표시 소스로 같은 실제 저장 결과를 다시 렌더링했으며 이를 새 native 실행으로 합산하지 않는다. 일반 명령의 실패 후 복구가 있었으므로 처음부터 모든 명령이 오류 없이 끝났다는 주장도 하지 않는다.

OS의 기본 브라우저 열기 요청 성공과 브라우저 화면 검수는 별도 근거다. observer의 `display_verified:false`는 그대로 보존했고, 부모가 최종 로컬 화면을 별도로 확인했다. 이번 한 번의 실행을 평균 속도·모델 우위·절감률·전 환경 보장으로 확대하지 않는다.

## 실제 화면 확인

추가 모델 호출 없이 읽기 전용 localhost 화면을 조작했다. 실제 업무 진행 화면, 현재 요청 완료 후 기획안 링크, 새 기획안의 선택 이유와 실제 초안, 웹→같은 결과 보고서→웹 연결을 확인했다. 수정 질문 복사는 성공 안내를 표시했다. 복사 API 실패·무응답 때에는 선택 가능한 질문 본문으로 전환하도록 코드 검사를 추가했다.

마지막에는 검수 서버 연결을 끊었다. 이미 읽은 기획안은 그대로 유지되고 “새 결과를 불러오지 못했어요. 최근에 확인한 저장 결과를 보여드리고 있어요.”와 재시도 버튼이 나타났다. 내부 HTTP·파일 오류를 사용자에게 나열하거나 AI 업무 실패로 바꾸지 않았다. 이 장애는 제어한 화면 검사이며 실제 외부 조사 장애가 아니다.

기존 AF 식기세척기·전자레인지 실제 저장 결과의 호환 표시도 확인했다. 이 두 제품은 이번 새 native 실행이 아니다. 새 실제 결과의 단일 HTML과 화면 캡처12장은 로컬 비공개 검토 폴더 `LG-AX-human-first-AK-20261018`에 보관한다. 원문·DB·native 원시 로그·개인 경로는 Git에 올리지 않는다.
