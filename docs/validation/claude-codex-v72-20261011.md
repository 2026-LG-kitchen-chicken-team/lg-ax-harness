# v7.2 Codex·Claude 실제 실행·지연 검토

2026-10-11 최신 동결본에서 Codex·Claude 각각 4입력/3대화를 실제 실행했다. 8입력 모두 당시 저장 상태·원질문·최종 영수증·export를 대조했고 보호 소스는 변하지 않았다. **전달 성공은 모든 기획 해결이나 의미 품질 통과가 아니다.** 기획 초안 2건, 기획 보류 5건, 기획 turn 이전 조사 보류 1건이다. 공식 심사 문제나 미사용 평가가 아니며 과거 50/10입력과 합산하지 않는다. [사전 계약](../evaluation/claude-codex-v72.md) · [지문·관측값 JSON](claude-codex-v72-20261011.json).

## 바뀐 구현

공통 Tool의 bundle 응답에 현재 handle/version을 반영한 **빈 candidate_template**과 작성 상한 result_limits를 추가했다. 빈 status는 유효하지 않으며 내용·근거·평가는 AI가 작성한다. 반복적인 양식/코드 재독해를 줄이려는 변경이며 특정 질문의 정답·제품 선택 분기를 추가하지 않았다. 기존 키와 충돌하면 사용하지 않은 접미사를 선택하고 최초/수정 한도는 유지한다. stale·종료·소진 상태에는 새 양식을 제공하지 않는다.

Agent에는 전체 원질문 보존, 보유 발췌/전체 원문 구분, 근거 없는 안내 발견성 문제를 확정하지 않는 지침과 조사·첫 저장·최종 전달 시간 배분을 보완했다. 지침의 시간 목표는 원격 실행을 강제 종료하는 프로그램 제한이 아니다. Codex는 평가 transport의 로컬 시간 상한420초를 설정했다. Claude는 prompt의420초 예산과 collector의2초 주기 시간초과 판정이며 자동 UI/native backend 강제중단을 구현한 것은 아니다. 이번 실제 입력은 모두 예산 안에 종료했고 자동 재실행은0회다. timeout 시 UI Stop/원격 종료 인수는 이번 실행에서 미실시다.

Claude native JSONL을 직접 검사하는 평가 도구를 추가했다. main session·원래 prompt·실제 end_turn 최종 텍스트를 확인하고, 스트리밍 중복·동일 message ID usage·sidechain을 구분한다. 숨은 추론을 공개하지 않고 가짜 Codex 이벤트로 바꾸지 않는다. 기존 Codex native 증명 경로는 유지한다. 공통 저장/출력 검사만 별도 함수로 재사용한다.

## 독립 의미 검토와 남은 결함

원문 근거·모델 귀속·기능 대조·중복 불확실성·기획 제약·계획/실증 분리·최종 설명/저장 일치를 별도로 검토했다. saved completed·accepted=true·delivery_ready=true는 의미 인증이 아니며 semantic_status=unverified / acceptance_ready=false를 유지한다.

- Codex A01은 보류 근거와 실제 사용 코스/조건 한계를 구분했다. A02의 물리적 링 문제에서 지원 안내 문제로 연결하는 부분은 추가 근거가 필요한 가설이며 보류를 유지했다.
- Claude A01은 구버전의 전체 질문 누락, 발췌의 누락을 전체 원문 부재로 단정하는 문제, 안내 존재만으로 발견성 문제를 확정하는 문제를 피했다. A02는 형식 상한 초과 후보가 거절된 뒤 같은 turn에서 수정 1회로 저장했다. 자동 재실행과 구분한다.
- **Claude A03 최종 문구 귀속 문제:** 저장 factual_summary의 입구 폭·회전·안전 여유 비보증 한계를 공식 사양 아래 “함께 적혀 있다”고 표현했다. 공식 PDP의 직접 문구라는 증거는 확인하지 못했다. 저장 요약/AI 적용 한계로 구분해야 하며 의미 품질 전체 통과로 보고하지 않는다. 산술 해석 자체는 AI 해석으로 구분했고 들어간다고 확정하지 않았다.
- 독립 reviewer가 다시 확인한 [MWJ25E 공식 사양](https://www.lge.co.kr/product/microwaves-and-ovens/mwj25e?modelId=MD09144829&pdpType=PURCHASE)에는 내부 치수 축과 턴테이블 지원 정보가 있다. Claude A03의 “축 순서/턴테이블 유무 미확인”은 저장 발췌의 범위로 제한해야 한다. 공식 전체 페이지의 정보 부재로 설명해서는 안 된다.
- Claude A02의 원후기에는 일부러 건드리지 않으면 기능상 지장은 없다는 맥락도 있다. 초안은 고장·전체 사용자 문제로 단정하지 않았으나 이 맥락을 최종 근거 설명에 포함해야 한다. 또한 링 관련 접수 비율 감소만 성공 지표로 삼으면 적절한 조기 신고 증가를 실패로 볼 수 있다. 실제 결함 빈도·조기 발견·적절한 조치 완료와 생산 로트 차이를 함께 고려해야 한다. 효과는 미측정이다.
- **Claude 네 입력의 자체 시간 표시 오류:** 답변에는 각각 약80/165/53/105초라고 썼으나 실제 native 사용자 입력→최종 완료는 위 표의 110.145/205.444/119.328/136.689초다. 답변 추정값을 시간 성능 지표로 쓰지 않는다. 원본 답변은 수정하지 않고 오류를 보존했다.
- Claude A04에서 시간을 늘리면 자료를 확보할 수 있다는 취지는 검증되지 않았다. 실제 420초 timeout이 발생한 사례가 아니며 접근 실패를 시간 증가만으로 해결한다고 보장하지 않는다.

최신 Claude A01/A02에서는 native Tool 오류 각각 1건도 관측됐다. A02의 최초 저장 거절 1건은 후속 snapshot에 남은 동일 파일과 중복 계산하지 않는다. 최종 복구·전달 성공을 모든 중간 오류 0으로 바꾸지 않는다. A02의 실행시점 valid=true와 A03의 후속 의존성 변경에 따른 과거 turn 무효화 이력도 구분해 보존했다.

## 수정 전후의 관측과 사용량

v7.1 동일 A01 업무/자료/실행 prompt를 환경마다 1회 실행했다. Codex는 321.530초에 전달/저장 계약을 통과했다. Claude는 178.260초에 최종 전달·저장이 있었지만 원질문의 두 번째 문장을 저장하지 않아 **원질문 보존 검사 실패**다. 전체 원문 코스 정보 부재 단정과 발견성 문제 재정의도 결함이었다. 실패한 baseline을 성공으로 바꾸지 않는다. 별도 최초 Codex 준비 실패는 native 시작 전 directory 충돌이며 실제 baseline과 합산하지 않는다.

같은 환경의 최신 A01에서는 각각 232.380/110.145초를 관측했다. 환경당 1회이며 Codex의 추가 웹 조사, Claude Bash/PowerShell 제공 차이, 모델/도구 판단과 캐시 조건이 있다. 코드의 인과적 절감 효과·통계적 우위·모델 우열·절감률은 주장하지 않는다.

JSON에 요청별 실제 native 토큰 필드를 남겼다. Codex 입력에는 cache가 포함되고 output에는 reasoning이 포함된다. A03의 누적값을 A02와 다시 합산하지 않고 증가분을 사용했다. Claude는 main turn 내 고유 assistant message ID로 비캐시 입력·cache creation·cache read를 합산하고, 스트리밍/iterations/thinking을 이중 가산하지 않았다. 이 수치는 계정 전체 청구·미관측 backend/하위 호출 전체성이 아니다. 개발용 검토 Agent 사용량과 출품 native 관측은 별개이며 청구액은 null이다.

A01 baseline 입력/출력은 Codex 917,028/14,044, Claude 전체 입력 1,134,931/출력17,051이었다. 캐시 조건·도구·근거 차이가 있어 이 한 번의 변화로 토큰 절감률이나 실제 비용 우위를 주장하지 않는다. 최신 합계 cache read는 Codex 2,840,192 / Claude 3,001,033, Claude cache creation171,488·non-cache70이다. cache는 위 전체 입력에 포함되어 별도 가산하지 않는다. 업무 export의 recorded_calls=0 / usage unknown은 **실제 모델 호출 0이나 무료 실행을 뜻하지 않는다.** 별도 native 로그 관측과 export 보고값을 구분한다. 사용자 결정에 따라 사람 대비 절감효과 측정·팀원 대기·절감률 주장은 제외했다.

## 검사와 동결 경계

제품 180개·평가 128개 일반 코드 검사와 자산 검사는 actual exit0다. Claude trace 검사 11개와 빈 후보 양식 검사 6개를 포함한다. 독립 reviewer가 현재 지문·로그·task-bound receipt를 대조하고 후보 키 충돌의 최초 차단 결과를 보존한 뒤 수정 재검토를 completed로 반환했다. 개발 장부 claude-codex-codefix-20261011의 complete는 exit0 / errors=[]다.

native 8입력은 **키 충돌 수정 전 동결본**이다. 최종 양식 키 접미사 수정 및 설치 설명/metadata 변경을 native 8입력으로 검증했다고 확대하지 않는다. Agent SHA는 동결/최종 동일하다. payload 동결 SHA `1d699166e519d7ddc200baaaf1ddf288a747f1bb5c70becb538e9dace34f6013`, 최종 SHA `f74811c989b99e87d9cad7bd66903f5726ef5d2ad3922a52df708654f1ccd804`다. 최종 수정은 실제 세 번째 저장/소진 및 제품 코드 검사로 확인했다. 입력 상한을 늘려 통과할 때까지 AI를 재호출하지 않았다.

새 source ZIP은 69파일이며 manifest 바이트 대조·새 폴더 uv sync --locked·공통 Skill doctor·ZIP source만으로 Claude 사본 재설치가 exit0다. 설치 검사는 native 품질을 대신하지 않는다. 기본 catalog는 비어 있고 평가용 v4 자료·개발 역할·평가 질문·로그/DB/키는 제품 ZIP에서 제외했다.

Claude 실제 범위는 Windows Desktop Code 2.31226.1.0 / native CLI 2.1.295 / Opus5.5·Extra다. 독립 CLI auth status는 로그인되지 않았으며 Desktop 성공을 CLI 인증 성공으로 설명하지 않는다. 네 입력의 필요한 Skill/일반 Tool 사용을 확인했으나 별도 Claude 개발용 Agent 위임이나 모든 MCP/브라우저 플러그인·모든 권한 조합을 인수한 것은 아니다.

## 다음 작업

1. 위 Claude 공식 문구 귀속·자체 시간 표시·후기 맥락/검증 지표·외부 접근 복구 안내를 별도 한정 보완하고, 변경한 범위의 추가 인수 필요 여부를 정한다. 현재 릴리스는 이 한계를 공개한 시험판이다.
2. 미사용 업무·제품/외부 접근 실패·취소의 제한 인수는 별도이며 8개 성공률로 일반화하지 않는다.
3. 웹팀은 개발 중이라는 사용자 보고이며 원본/실행 연결 검토는 미수신이다. 웹 담당자의 소유 범위를 유지한다.
4. 별도 실제 관찰 화면·녹화·영상/발표·리허설 및 운영진 최종 규격/접수 확인은 남아 있다. 사람 비교와 Gemini는 다시 추가하지 않는다.
