## 구현과 전달

- 최종 답변은 현재 저장 결과의 `completion_summary`에서 투영한다. 새로운 사실을 마지막 요약에서 재작성하는 경로를 줄이고, 판단 메모·근거·검증 조건을 같은 버전으로 전달한다.
- 새 실제 후속 질문은 이전 turn을 가리키는 새 요청으로 처리한다. 기존 결과·시계·수정 이력은 보존하며, 같은 실패 업무의 예산 초기화와 구분한다.
- 취소한 업무의 수집/등록/저장 late-write를 차단하고, 잘못된 관측 자료형을 JSON 오류로 반환한다. 로컬 저장 차단과 실제 native 중지는 별도로 관측한다.
- 기획자 화면·별도 보고서 HTML은 같은 export와 현재 `web_result`의 session/turn/request/version/result/context/code/data/audit 지문 및 웹 파일 원 바이트를 대조한다. 오래되거나 미검토된 결과는 현재 결과로 적용하지 않는다.
- 선택 등록본문 전체와 결과에 인용한 근거를 구분해 전달한다. 모델/문서/자료 버전·위치·지문·검토/조사 이력도 보존한다. `duplicate:null`은 **미확인**이며, 기본 제약은 **저장된 실행 제약**으로 표시한다.
- HTML과 별도 관찰 화면은 일반 코드로 렌더링한다. 화면을 위한 추가 모델 호출은 **0회**다. 길웅의 디자인을 유지하고 연결에 필요한 최소 수정만 적용했다.

## 역할이 한 실제 일

출품 구조는 메인1·업무 Skill6·선택 역할3(공식자료 조사자·후기 조사자·근거 검토자)다. 개발 체계 역할/Skill 수와 다르며 항상 세 역할을 호출하지 않는다. 자식은 읽기 전용이고 부모가 최종 저장한다.

M1 Codex에서는 공식33개/후기23개 조사 반환과 검토자의 공개 반환을 실제 관측했다. 냉동 성능의 긍정 평가가 초기 온도 지연을 지우지 않는 점, 구매·배송 서비스와 구매 후 소음 A/S를 혼동한 점이 메인에 반영됐다. M2 Claude는 실제 background Agent3개가 생성됐고 native Handback 성공·완료 알림·메인 수신을 대조했다. 공식/후기/검토자의 ACK 이후 완료 알림은 각각76.627/80.490/124.602초로 자식180초 범위 안이었다.

Claude 검토자의 지적10개 중8개는 결과 필드의 직접 변경,2개는 부분 반영을 확인했다. 가격만으로 적합성을 묶던 문구의 범위, 기능의 모델 조건 각주, 모델 불명 설명서, 긍정 반례, 서비스 검증의 분모/정답/비저하 조건 등이 보완됐다. **설명서 읽기 권장의 불편 연결은 검토자 호출 전 초안에서 이미 빠져 있었다.** 그 제거를 검토자의 단독 효과로 귀속하지 않는다. 연구자의 반환 전체를 메인이 원문 그대로 받았다는 인증과 모든 자료의 의미 전량 독해 인증도 하지 않는다.

정상 부모 단독 대비 Claude 역할 실행은267.854초 더 걸렸다. Codex M1에서도240.594초 더 걸렸다. 역할은 구체적인 근거/조건 검토 기여를 보였으며, 이 한 쌍으로 일반 속도·토큰·정확도 향상률을 주장하지 않는다.

## 화면과 관찰 검수

실제 M2 Codex A, Claude F, Claude R의 현재 export/웹 JSON으로 기획자 화면·별도 보고서 HTML을 만들고 Chrome에서 검수했다. 각 냉장고 결과에 선택 등록본문56개·41,974자·97,846 UTF8바이트가 유지됐다. Claude R의 결과 인용37개·판단/기획 연결·미확인 중복·저장 제약 표기를 확인했다. 렌더링 통과는 앞서 남은 Claude A/F P2의 의미 통과를 대신하지 않는다.

별도 기획 사무실은 실제 Claude R 공개 trace를 일반 코드로 가져온 **기록 재생**이다.120개 사건과 main Tool49개 호출/반환, 정확3개 자식 ACK·Handback·완료 알림을 연결했다. 브라우저에서 두 조사자와 메인의 동시 활동 및 세 역할의 결과 반환을 확인했다. 원 질문/답변/명령/개인 경로/숨은 추론은 관찰 파일에 넣지 않았다. 화면의 `product v0.10.0 구조`는 역사적 구조 설명이며 이번 실행 소스는 M2다. Claude GUI hook의 새 native 실시간 연결은 이번에 검증하지 않았고 기록 가져오기와 구분한다.

## 시간·토큰과 증거 경계

M2 코드 검사443/443·웹105/105·업무 자산55개·개발 validate가 실제 exit0다. ZIP 설치/잠금 의존성/doctor 명령과 제품 snapshot도 별도 검사했다. 원격 CI는 계정 지출 한도로 미시작이며 로컬 통과로 원격 CI를 통과 처리하지 않는다.

고정자료 실행에는 모델의 HTML/PDF/DOCX/XLSX/이미지 생성을 제외했다. 계측한 M2 Codex A/F의 shell span은19.053/20.425초, Claude A/F는25.656/9.005초다. 나머지 벽시계 간격은 계획·읽기·생성·대기·환경 지연의 혼합이며 전부 순수 추론으로 귀속하지 않는다. Codex 후속 F의 사용량은 A 누적값의 차분으로, Claude는 해당 turn의 고유 assistant 메시지 ID 집계로 분리한다. parent 공개 usage와 cache 원필드를 보존하고 자식/backend 전체 청구·절감률·사람 공수 절감률은 계산하지 않았다.

원질문·자료·DB·native/child 원로그·인증·receipt는 Git 제외 격리 보관한다. 공개 기록에는 지문과 판정 범위만 남긴다. Claude 붙여넣기 wrapper, background 완료가 중간 end_turn 뒤에 전달되는 경우, GUI의 cached accessibility tree, 최초 취소 collector의 stale reason을 관측 보완 기록으로 보존했으며 raw 원본을 고치지 않았다. 모델의 모든 의미 오류·실물 효과·대표성·최종 영상/발표/접수 완료를 인증하는 기록은 아니다.

이번 단계 이후에는 길웅에게 같은 브랜치/제품 버전·사용법·검증 범위를 인계하고, 웹 실시간 hook과 실제 팀원 환경의 연결을 확인한다. 새 모델 입력은 이 단계 상한14회 이후 자동 시작하지 않는다.

## 마감 시점의 팀원 추가 변경

최종 원격 조회에서 PR10 head가 `34ec4a492e5d12cf4041bdfe60cde63ba39dcf27`로 이동했고, 이번 인수 head `1576a6c2a31d7a927bf73f02eaea4abf33202f80` 이후8개 커밋을 확인했다. 업무형5쪽 정리·접힌 상세/hover·짧은 애니메이션과 팀원의 새 웹 JSON 연결이 포함된다.17파일 추가/수정이며 이번 M2 고정 인수·ZIP에는 포함하지 않았다. PR11 head는 같았다. 이 차이를 최신 원격 전체 반영 완료로 설명하지 않는다.

팀원의 `64e12b18...` 웹 연결과 이번 엄격한 현재 binding 검사/전체 자료 전달이 같은 파일에서 겹친다. 이후 병합에서는 팀원 디자인을 유지하면서 현재 version/context/code/data/audit·파일 SHA·저장 검토 gate를 보존해야 한다. 고정 M2 배포를 수정하거나 새 원격 화면의 검사를 통과했다고 기록하지 않는다. 길웅 인계 메일에는 두 head와 겹치는 파일·후속 확인을 구분한다.
