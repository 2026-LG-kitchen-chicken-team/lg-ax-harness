## 현재 판단 가능한 병목과 개선 순서

1. **원문 전달과 문맥 증가:** 큰 HTML/원문은 파일로 온전히 보존하고 일반 코드로 구조 추출·중복 처리·목록 집계한다. 모델에는 필요한 원문 단위/주변 맥락·메타데이터·지문·누락 목록을 전달한다. 중요 후기·조건·반례를 버리는 문맥 절약은 금지한다. 0.92MB 출력이 실제 속도를 몇 초 늦췄는지는 대조 실험 전 미확인이다.
2. **등록 경로 오류와 반복 수선:** 일반 코드의 크기 내 batch·원문 모델 식별·명시적인 variant/alias 증거·retained/catalog 연결을 조사 후 자동 점검한다. 검증 실패를 AI가 새 스크립트로 계속 수선하기 전에 일괄 오류 위치를 반환한다. 접미부를 무조건 삭제하거나 다른 제품을 같은 모델로 합치지 않는다.
3. **전체 종료 예산:** workflow.finish 뒤에도 저장·보고서·최종 전달이 남을 수 있다. native 최종/exit를 기준으로300초 점검, 마지막 최소90초 전달 예약,600초 전체 종료를 일반 코드로 통제하는 제품 계약 보완이 필요하다. 현재는 평가 runner에서만600초를 적용했다. 조사 부족이면 한계를 남기고 정직한 보류를 전달해야 한다.
4. **모델 설정 비교:** 등록 경로가 안정된 뒤 충분한 동일 조사 자료로6.1 medium/low/high와 실제 인증된 Claude 후보를 반복 비교한다. 설정과 구조 변경을 동시에 하지 않는다. 실패·출처·품질·토큰도 함께 판정한다.
5. **선택적 위임:** [최소 설계](../plans/selective-product-agents-20261012.md)처럼 별도 근거 대조가 필요한 요청에만 독립 검토자를 시험한다. 현재 제품에 위임이 구현/인수됐다고 설명하지 않는다.

Tool 구간을 제외한536.924초는 모델 추론·생성, 전송, native 런타임, 미관측 작업을 포함한다. **전부 추론 시간으로 표시하지 않는다.** 웹 사건도 부모 CLI가 방출한 관측 구간이며 HTTP 서비스만의 순수 시간은 아니다. 현재 자료로 과거1800초 실패의 원인을 소급 확정하지 않는다.
