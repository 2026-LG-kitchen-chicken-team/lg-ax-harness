# AA 실행·의미 지침 보완과 발표 전용 토큰 위젯

2026-10-16. 제품 실행 보완과 발표용 관찰 도구를 구현했다. 웹팀 프론트 디자인·모델 기본값·메인1/업무 Skill6/선택 역할3 구성은 유지한다. 촬영은 하지 않았다. 모델/추론의 동일 자료 비교는 [별도 동결 계약](execution-quality-AA-method-20261016.md)을 따르며 코드 검사와 구분한다.

## 제품에서 바뀐 동작

1. `open_product_workflow`에 요청 범위·모델·문서 버전·제약·런타임을 `open_request`와 같은 계약으로 전달한다. 실제 후속은 `prior_scope:inherit`로 이어가고, 이전 기록만 참고하는 새 업무는 `reference_only`로 분리한다. 특정 제품명이나 질문을 하드코딩해 분기하지 않는다.
2. CLI `export_session`에서 자료 경로를 빠뜨리면 같은 세션의 최신 turn에 결속된 **정확한 자료 폴더와 지문**을 복구한다. 다른 세션의 최신 폴더나 과거 완료 turn을 고르지 않는다. 명시한 경로는 기존대로 사용하며, 변경·분실·외부 경로나 이전 형식 기록은 명시적 경로를 요구한다. 취소·만료·이전 코드의 결과를 되살리지 않으며 잘못된 빈 catalog의 export를 성공처럼 전달하지 않도록 보완했다.
3. 원문 조건·부정·시간 순서를 불편→기능 대조→남은 문제→기획→검토→현재 completion/최종 요약까지 보존하도록 업무 지침을 연결했다. 모호한 경우에만 `meaning-preservation.md`를 추가로 읽는다. 원문에 없는 행위·매체·시점을 덧붙이지 않으며, 타당한 조건부 기획은 유지한다.

제품 코드·계약은 [공통 도구](../contracts/common-tools.md), [워크플로](../contracts/product-workflow.md), `product-tools/product_tools/execution_context.py`에 있다. 이 변경은 모든 모델의 모든 의미 오류를 자동 제거했다는 선언이 아니다. 실제 결과는 모델별 원문 대조로 판정한다.

## 발표용 Token Lens

[사용법](../../presentation-tools/token-widget/README.md)과 별도 로컬 서버를 추가했다. 실제 Codex·Claude 로그와 native UUID를 명시 선택하고 입력·출력·캐시·관측 경과, 메인과 확인된 하위 로그를 구분해 표시한다. LIVE/REPLAY 표시를 유지한다. 미관측 값은 `—`이며 cache/추론의 포함 관계와 누적 snapshot을 중복 합산하지 않는다.

모델 호출·프롬프트 추가·외부 전송 없이 일반 코드로 관찰한다. 원문·답변·생각·명령·개인 경로·키를 화면 payload에 넣지 않는다. **제품 source ZIP·심사위원 ZIP·설치에는 포함하지 않는다.** 별도 발표 채팅에 이 범위와 사용법을 전달했다.

14개 위젯 검사와 실제 기존 Codex/Claude 로그 각1개 재생에서 사용량이 기존 독립 영수증과 일치했다. 추가 모델 입력0이다. 이 재생은 새 모델 비교·실제 청구 검증·화면 육안 검수·촬영을 대신하지 않는다.
