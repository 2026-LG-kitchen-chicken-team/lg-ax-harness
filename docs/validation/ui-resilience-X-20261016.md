## 바뀐 동작

| 영역 | 개선 |
|---|---|
| 로딩 | 첫 결과 대기·읽기 중·읽기 실패를 구분하고 필요한 행동만 안내한다. |
| 결과 갱신 | payload 전체 내용으로 변경을 판단한다. 실패 시 마지막 정상 결과를 유지하며 중복 읽기·timeout·늦은 응답·화면 종료 후 응답을 차단한다. |
| 잘못된 파일 | 화면 형식·빈 페이지·잘못된 주소 조각과 주요 block 구조를 검사한다. 정상 표의 chip 셀은 유지한다. raw parser 오류·내부 경로는 기본 오류 안내로 전달하지 않는다. |
| 보고서 | 같은 현재 turn의 사본을 유지한다. 새 결과가 생기면 최신 보고서로 전환할 수 있고, iframe의 실제 준비 신호를 frame·turn·nonce로 대조한다. 이미 표시된 보고서는 저장 작업 오류 때문에 사라지지 않는다. |
| 대시보드 | 실제 기록 대기가 기본이다. 예시·재생은 명시 선택한다. 마지막 사건 시각과 파일 읽기 성공 시각을 구분하고, 실패 시 관측·결과 링크를 보존한다. 3D만 실패해도 진행 목록·기록을 남긴다. |
| 제품군 | 세 제품은 표시용 별칭이며 허용 목록이 아니다. 다른 제품군을 자동으로 미지원 표시하지 않는다. |

## 세 제품과 열린 범위

기존 실제 AI 결과를 현재 코드로 다시 생성했다. 새 AI 조사·새 촬영 실행은 아니다.

| 제품군 | 실행기 | 선택 원문/사실 본문 | 웹→보고서 동일성·loader·변환 |
|---|---|---:|---|
| 냉장고 | Codex / Claude | 각각56 | 두 결과 모두 통과 |
| 전자레인지 | Codex / Claude | 각각82 | 두 결과 모두 통과 |
| 식기세척기 | Codex / Claude | 각각81 | 두 결과 모두 통과 |

같은 현재 결과·turn·binding·출처와 선택 본문 전체를 보존했다. 건수는 등록된 발췌/사실 단위이며 고유 고객 수·시장 대표성·전체 웹 문서 수가 아니다. 임의 제품군2개는 합성 자료로 요청→저장→웹·보고서→후속을 확인했고 자료 없는 제품군은 조사 단계로 진입했다. 다른 제품의 실제 조사 품질을 모두 검증한 것으로 확대하지 않는다.

## 남은 약점과 다음 작업

1. 로컬 화면 접근이 도구 정책으로 제한돼 **실제 브라우저 육안·키보드·GPU 검수는 남아 있다**. 데이터와 source 함수 검사를 실제 화면 확인으로 바꾸지 않는다.
2. 웹 사이트 차단·로그인·변경은 조사 폭과 시간을 흔들 수 있다. 화면 읽기 재시도는 조사 자체의 실패를 성공으로 바꾸지 않는다.
3. 다른 제품군의 구조적 확장 경로는 확인했지만 실제 새 제품 조사와 업무 품질은 사례별 평가가 필요하다.
4. [세 제품 필수 촬영 계획](../plans/three-product-shooting-20261016.md)에 따라 냉장고·식기세척기·전자레인지 모두 실제 질문→작업→웹→보고서를 촬영한다. 상세 제출판은 분량 제한 없이 A–Z를 담고, 현장판은 발표·영상575초+전환25초로 별도 편집·리허설한다. 현재 발표/영상 제작과 제출 접수는 완료하지 않았다.

## 수정판 이력

0.16.2의 강화된 자료 검사가 정상 표 셀을 오인한 문제를 실제 자료6건에서 발견했다. 공유 형식 검사로 수정한0.16.3을 사용한다. 제품별 답안·키워드·개별 run 예외는 추가하지 않았다. 잘못 배치한 새 회귀 assertion과 부모 설치 검사 경로 오류도 고친 뒤 새 receipt로 재실행했으며 이전 실패는 로그에 보존했다. 원문 실행 로그·개인 설정·자료 본문은 Git과 심사 ZIP에 넣지 않았다.
