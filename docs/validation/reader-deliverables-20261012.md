# 자료집과 보고서 출력 — 2026-10-12

사용자가 확정한 수정07 목업의 표현 기준을 반영했다. 원문 자료 종류·확보한 데이터·실제 요청에 맞춰 파일과 절을 구성하며 페이지 수·목차·파일 수는 고정하지 않는다. 목업의 가상 내용은 업무 기본 데이터에 넣지 않았다. 본 기록은 새 출력 기능의 검증이며 과거 v7.4 전체 품질 결과와 합산하지 않는다.

## 구현

- `product_tools.reporting`: 보고 계획의 구조·유한 수치·차트와 표 좌표·원문 연결·이미지 경로/파일을 검증하고 종류별 원문 XLSX와 최종 DOCX/PDF를 새 폴더에 원자적으로 제작한다. 실제 원문을 분할 셀에 보존하고 직접 출처·원문 셀을 연결한다. 공개 자료집에는 내부 source_id를 노출하지 않는다.
- 표 제목·회색 머리글·테두리·합계 선과 중요한 수치의 빨간색 강조, 차트 제목/단위·본체/축/눈금선·결과 설명을 구성한다. 복수 계열은 농도·선 종류·표식·대응 범례로 구분한다. 입력에 없는 통계를 자동 생성하지 않는다.
- `product_tools.delivery`: 검증된 원문과 저장 결과를 대조한다. 모델이 출처 원문이나 귀속을 바꾸면 거부한다. 공통 Skill은 원문 인용/저장 요약/AI 판단·분모·`/` 표기·가용 이미지 생성 도구 사용을 안내한다. 생성 이미지는 실제 파일과 생성 내역이 필요하다.
- `save_and_export`는 기존6필드를 유지한다. `report:true`를 명시한 제품 Skill이 독자용 파일 제작을 요청하며 하위 API 기본값은 false다. 내부 `report_plan_path`는 업무 JSON의64KiB 제한과 분리한다. 업무 저장과 보고서 실패를 별도 반환하며 현재 유효한 검토 결과만 전달한다.
- `deliver_result`는 동일 저장 버전에서 파일 생성만 복구한다. 멱등 캐시는 보고 계획과 이미지 내용·출력 파일 해시를 확인한다. 변한 파일은 보존하고 새 폴더에 제작한다. 취소·오래된 버전·검토 거절 결과는 전달하지 않는다. Windows 탐색기는 성공한 최초 제작 뒤에 연다.
- Codex/Claude가 공통 코드와6Skill을 사용한다. 의존성 잠금과 doctor를 보강했다. 전역 설정·인증은 변경하지 않았다.

## 실제 결함 발견과 수정

독립 검토로 보고서 DB 오류가 성공한 업무 저장 응답을 숨기던 문제, 이미지 변경을 놓친 캐시, 잘못된 계획 요소의 예외를 수정했다. 파일 제작 검토에서는 수식처럼 보이는 출처 제목의 문자열 보존,5개 이상 출처와 차트의 겹침, Excel 차트 설명 누락, 복수 계열 구분 및 설치 안내를 수정했다.

초기 실제 GPT-6.1 Sol 진단은119.62초/exit0였지만 보고서 생성은 실패했다. 정상적인 긴 PDF 제목의 줄바꿈을 누락으로 판정한 것이 원인이었다. 저장된 결과와 실패 내역은 보존했다. 제목의 공백·줄바꿈을 정규화한 검사는 정상 제목을 통과시키고 실제 제목 누락을 계속 거부한다. 수정 뒤 같은 실제 계획/원문5개 재생은 XLSX3개·DOCX1개·PDF4쪽·링크79개로 제작됐고 PDF 전 페이지를 확인했다.

독립 원문 의미 검토에서 Sol은 이 제한된 입력의 판독·귀속·보류 이유·최종 저장/출력을 통과했다. ## 설치와 파일 검수 범위

최종 제품229·평가128개 일반 코드 검사(합계357)는 CPython3.12.15의 잠금 의존성 환경에서 실제 exit0다. renderer11·delivery17·신규 설치3개는 별도 task-bound receipt로 연결했다. 설치3개 안에는 Codex와 Claude의 새 폴더 잠금 설치가 모두 포함된다. 자산·Claude 개발 Skill 동기화·diff 검사도 exit0다. 검사를 중복 실행한 횟수를 새로운 시험 사례 수로 합산하지 않는다.

### 최종 배포 원본의 Codex 재인수

Word 표 머리글과 첫 데이터 행을 함께 유지하고, 짧은 이미지 설명·생성 출처를 묶은 뒤 원요청 이행 대조 지침을 보강했다. 제품 원본 `018ee533cfd7e1bb5ab3da75a9b8f973f9702adb`의 GPT-6.1 Sol 같은 입력 재인수는95.39초/exit0였다. 현재 held/버전1, XLSX3·DOCX1·PDF1(4쪽/82링크), delivery_ready/report_ready=true다. 독립 검토로 원문5개·최종 버전/경로·원요청의 경험/선호/기대 분류를 확인했다. 보고서는 보류 분석이며 제안0개다. 실제 응답의 acceptance_ready와 reported_reasoning_consistent는 false를 유지한다. 이를 업무 완성이나 의미 전면 인증으로 바꾸지 않는다.

실제 native 입력197355 / 그중 캐시162944 / 출력4369 / 그중 추론250토큰이다. source manifest SHA256은 `b68147d14d3c534e5b6b21028e6956425352644c7d4211e456eb8502acc37dbf`, 설치 manifest는 `40278a3dd96a531e0ee80aae7771a72fca36a3f889fb477a49cc05c6afcf8bd5`다. 앞의 두 모델 비교는 이전 동결 원본이며 이 재인수와 성공 사례 수를 합산하지 않는다. Luna의 최신 지침 추가 후 AI 재인수는 미실행이다.

승인 목업의 가상 데이터를 검수용으로만 재구성한 예제는 합성 원문482개·자료7종·9절/34블록·새 도표5개·기존 생성 이미지2개다. 새 결과는 XLSX8·Word/PDF이며 PDF13쪽/85링크다. `180명 / 전체240명 /75.0%`를 보존했다. 가상 예제는 제품 기본 catalog·배포 ZIP에 포함하지 않는다. 별도의 최종 결과 폴더에 보존하며 실제 고객/시장/효과 근거로 사용하지 않는다.

최종 실물 파일은 Word COM·Poppler exit0로 보류 분석 Word5쪽/PDF4쪽과 가상 검수 Word17쪽/PDF13쪽, 합계39쪽을 전부 확인했다. 밀도 높은 표·이미지·생성 출처·표 머리글은 원본 크기로 추가 확인했다. 원본4파일 SHA256은 변하지 않았다. 이미지/설명/생성 출처와 표 머리글/첫 행은 함께 유지된다. 긴 표는 반복 머리글로 이어지고 출처 목록은 페이지를 넘길 수 있다. Word와 PDF의 페이지 수가 같다는 기준은 두지 않는다.

Codex와 Claude 새 폴더에 `uv sync --locked`를 실제 실행하고 모든 보고서 의존성을 import/버전 확인했다. 대표 PDF·Word 전4페이지와 Excel의 모든 시트를 확인했고, 실제 Word/Excel COM의 독립 hidden 인스턴스만 사용해 내보냈다. LibreOffice가 없어 `render_docx.py`는 실패했고 Word 대체 경로가 성공했다. 합성 검증용 수치와 원문은 실제 업무 성과로 세지 않는다.

Excel 원자료와 도표 데이터 셀은 편집 가능하다. XLSX/DOCX/PDF 그래프는 같은 렌더링 이미지이며 데이터나 디자인 변경은 보고 계획에서 재생성한다. 구조 검사와 수동 대표 검수는 자동 전체 시각 검수·의미 정확성 인증을 뜻하지 않는다. 실제 응답은 semantic_status=unverified와 visual_review=not_run을 보존한다.

새 보고서의 실제 Claude AI 인수는 최길웅 후속이다. 비Windows 한글 차트·최종 시연/영상/리허설·웹 원본 연결·공식 제출은 이번 완료 범위와 별도다. 과거 pointer/조사 timeout/Claude 문맥·귀속 제한을 이번 출력 기능으로 모두 해결했다고 하지 않는다. 최종 코드 검사와 배포/다운로드 근거는 [제품v0.8.0 기록](product-v0.8.0.md)에 남긴다.
