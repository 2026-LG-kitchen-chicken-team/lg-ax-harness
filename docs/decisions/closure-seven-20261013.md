# 남은 1–7번 실행 결정

최신 사용자 승인에 따라 답변 표현·완료 주장·자료 보강·웹 실패·시간/모델·선택적 역할·Codex/Claude 검증을 진행한다. HTML/프론트는 웹팀 소유이고 이번 범위에서 수정하지 않는다. 제품 배포와 영상/발표 실제 제작은 8–10번으로 별도다.

## 판단과 검증

- 사용자 답변은 자연스러운 결론·근거·중요한 한계다. 내부 status와 이력은 유지한다. 한계를 README에만 숨기지 않는다.
- 실제 화면 검수와 파일 생성·구조검사·caller 신고를 분리한다. 과거 B의 무관측 시각 검수 주장은 원본을 변경하지 않고 정정 기록을 붙인다.
- 자료의 양·제품 전반·긍정/불편/장기/조건/반례·원출처 폭을 유지한다. 접근 불가·모델 적용 미확인·대표성 부족을 수집 성공으로 보정하지 않는다. 등록 원문과 추가 context/개발 fixture를 구분한다.
- 시간 목표를 먼저 성공 조건으로 삼지 않는다. 충분한 동일 자료·입력·품질의 자연 완료시간과 실패 포함 usage를 비교한다. 기존 300/600초 결과는 역사적 조건이며, 중단 표본의 완료시간은 미측정이다.
- 새 비교의 외부 안전 상한은 최대1800초이며 이는 시간 성능 목표가 아니다. 신규 workflow도 필요할 때 명시1800초로 시작하며 기존 요청의 clock을 연장하지 않는다. 자식별 상한/전체 안전 상한과 의미 검토를 구분한다.
- 이전 A의 모델7개 설정은 각1회이며 최신 C의 반복과 소스가 다르다. 반복 확인/최신 회귀/역할 비교를 따로 보고한다. 실제 native child ID·반환·독해·반영·전체 usage를 기록하고 설치만으로 역할 실행을 주장하지 않는다.
- 이번 단계의 기존14개 부모 입력과 신규최대10개를 합쳐24개 상한을 유지한다. GUI 재시도·취소 후속도 새 입력으로 센다. 안전 상한에 도달하거나 접근이 막히면 실패/미실행과 차후 필요한 조건을 남긴다. 새 run 이름으로 한도를 초기화하지 않는다.

Codex는 CLI 계측, Claude는 기존 유료 Desktop Code GUI를 사용한다. 로그인/보안/신뢰창은 자동 조작하지 않는다. 원문/로그/DB/인증은 Git 제외 위치에 보존한다. 코드 검사와 native 의미 품질은 별개다.
