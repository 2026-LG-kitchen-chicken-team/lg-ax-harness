# Skill·서브에이전트·자료·검증·모델 권장 실행

2026-10-13 사용자 후속 지시: 남은1~5번을 진행한다. 관련 GUI는 오른쪽 모니터에 두고 왼쪽의 다른 과제 창을 조작하지 않는다. HTML/프론트는 웹팀 소유다.

## 범위와 우선순위

1. 중립 관측/확인된 불편·집계·절별 근거·기능 부재·검증 조건의 공통 Skill 지침을 보완한다. 특정 질문/모델의 정답 분기를 추가하지 않는다.
2. 공식자료/후기 조사자와 독립 근거 검토자의 실제 native 독해·반환·부모 반영·이점을 확인한다. 역할 수를 가산점으로 주장하지 않는다.
3. 보존한 설명서의 출판자 연결을 코드로 검증하고 실제 등록한다. 수집 폭을 줄이지 않고 observed/registered/delivered/reviewed와 의미/대표성을 구분한다.
4. 같은 동결 소스의 정상·후속·모호함·자료 부족·실제 웹 실패·취소 및 미사용 표현을 실제 Codex/Claude 환경에서 확인한다.
5. 충분한 같은 자료/품질 반복 후 실제 검증한 모델·effort 집합만 권장한다. 실측 사용량과 실패/한계를 함께 제시한다.

## 비교 단계와 상한

이전 closure-seven 단계의14+7=21부모 입력과 실패/partial은 보존한다. 원 단계의24상한을 새 이름으로 초기화하지 않는다. 새 사용자 실행 범위에 따른 추가 동결 검증은 별도24입력 이내로 계획하고 누적 최대45를 기록한다. 이전 단계 미발송 질문은 미실행으로 보존하며 두 단계 결과를 소스별로 구분한다. 재발송·후속·취소도 각각 실제 새 입력으로 센다. 모델 backend 호출 수는 부모 입력 수와 별도다.

최초 후보 선별은 과거 A 탐색과 C/F 반복의 제한을 따른다. 추가 비교 후보는 실제 접근 가능한 Codex gpt-6.1-sol low/medium 및 Claude GUI Sonnet5.5 medium이다. 세 제품군별 같은 질문·전체 원자료·출력 기준으로 각2회가 초기 비교 계획이며, 세 후보 모두가 권장될 것이라는 뜻은 아니다. 제공사별 운영 문구/모델 resolved 값·캐시/실패·실행 순서와 관측 범위를 기록한다. 신규 결함·접근 차단·불충분 반복이면 최종 권장을 보류한다. 무작정 전체 모델/effort 조합을 실행하지 않는다.

업무 성공 시간을 미리 고정하거나 자료를 줄여5~10분에 맞추지 않는다. 자연 native 최종 응답/프로세스 종료까지 측정하며 외부1800초는 오류·무한반복 방지 상한이다. 중단은 완료시간 미측정이다. 기존 요청의 시계를 연장하지 않는다. 자식별 안전 상한과 부모 최종 전달 예약도 유지한다. 같은 제공사의 비교 작업은 겹치지 않게 하고, 동시 실행이 생기면 해당 시간 표본의 환경 한계를 표시한다.

## 최신 제출 공지

사용자 제공 공지/캡처: 1차 핵심 주제와 해결 문제 방향을 유지하며 세부 시나리오·기능·구현 방식은 보완 가능하다. 2차 발표자료는 분량 제한이 없으며, 발표자료에 영상 삽입 시 별도 영상 제출을 생략할 수 있다. 캡처에서 현장 직접 시연 또는 영상 대체 허용을 확인했다. 핵심 주제 조항은 전달 텍스트이고 캡처 본문에서 확인한 조항으로 귀속하지 않는다. 발표10분/질의응답5분 변경 근거는 이번 공지에 없다.

원 제안서2~4쪽의 '제품군 교체 가능한 입력'과 고객 불편→정확 모델 기존 기능 대조→잔여 불편→근거 콘셉트/보류를 유지한다. 세 제품군 확장이 운영진의 최종 적격 승인을 받았다고 주장하지 않는다.

원문/로그/DB/개인 설정/인증은 Git 제외 위치에 둔다. 사람 대비 절감·Gemini·자체 모델 API·UI 중복 구현은 이번 범위에서 제외한다. 임의 key/turn·시간 연장·물리 Esc 안전 중단의 자동 우회는 하지 않는다.
