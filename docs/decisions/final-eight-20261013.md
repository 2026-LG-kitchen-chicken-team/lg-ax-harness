# 최종 1–8번 실행 범위와 선택 원칙

2026-10-13. 사용자가 승인한 출품 역할·계약·실제 자료·품질·병목·모델 비교·회귀·검토/배포 작업이다. HTML/프론트는 웹팀 소유로 변경하지 않는다. 사람 대비 절감 효과와 Gemini는 제외한다. 최종 접수·발표·영상 제작은 이번 완료 기준에 포함하지 않는다.

## 구조

공통 Agent·업무 Skill·일반 코드 Tool을 Codex와 Claude Code에 설치하는 기존 방식을 유지한다. 자체 LLM API 실행기를 추가하지 않는다. 개발 역할6/Skill9와 출품 메인1/Skill6/선택적 역할3을 구분한다.

출품의 선택적 역할은 공식 자료 조사자, 실사용 후기 조사·분석자, 독립 근거 검토자다. 단순 확인/설명 후속은 부모가 수행한다. 조사 역할의 필요성·실제 도구·자료·시간이 있을 때만 위임하며, 역할 수 자체의 가산점이나 품질 보장을 주장하지 않는다. 정의·설치·실제 발견·위임·원문 독해·반영·이점은 각각 별도 증거로 판정한다. [위임 계약](../contracts/product-research-agents.md)을 따른다.

두 조사 역할은 같은 scope와 base catalog에서 조회/분석만 한다. 부모가 원문 검증·직렬 등록·coverage·후보·저장·보고서를 작성한다. child summary/잘림/재서술은 원문 등록 불가이며 실제 artifact가 없으면 partial이다. source ID 신고로 전체 본문 전달 gate를 우회하지 않는다. reviewer는 불변 packet의 `candidate_copy`와 `candidate.result.evidence_refs`를 직접 읽는다.

연구 역할 각1회/180초·최대2명 동시, 시작에 외부420초 이상 필요, reviewer1회/90초·시작에210초 이상 필요, 마지막90초 전달 예약이다. 문구와 maxTurns가 실제 wall-time/원격 backend 중단을 강제한다는 뜻은 아니다. 실제 native ID·시계·반환·지원 중단을 부모가 관측한다.

## 자료·시간·모델

후기/조사 범위를 극소수로 줄여 시간 목표를 맞추지 않는다. 실제 평가 corpus의92후기+20사실은 격리 평가용이며 기본 출품 catalog는 empty다. 정확한 모델·시장·문서 버전, 긍정/불편/조건/반례/장기사용, 원문 접근/누락/중복/구매 확인을 기록한다. 건수는 대표성 인증이 아니다. 새 맥락 원문은 등록 전 적용 scope와 원문 관측 결속을 확인한다.

목표300초/외부600초는 최초 입력에서 최종 native 응답/end_turn/process exit까지다. workflow 완료나 파일 생성만으로 성공 처리하지 않는다. 코드 렌더링과 원문 일괄 전달을 사용하고, Tool 시간의 나머지를 전부 모델 추론 시간으로 해석하지 않는다.

동일 소스·자료·입력을 고정한 모델/effort 비교와 최신 지침 전체 업무 재인수, 빈 catalog 신규 온라인 조사, 선택적 위임의 비교는 분리한다. 실제 설정·resolved model·cache·재시도·실패·최종 전달·저장 정합·7축 의미 품질을 함께 기록한다. 실패 비용을0으로 처리하지 않고, 작은 표본의 빠른 설정을 통계적 최적이나 모든 제품군 권장으로 확대하지 않는다. 제공사별 평가 조건 문구의 차이도 보존한다.

이번 개발 장부의 더 엄격한 상한인 신규 부모 입력24회를 유지한다. 이전 단계24입력과 합산한 관측 상한은48이다. 프로토콜의 최대30은 허용 상한이며 이번 실제 장부24를 자동으로 늘리지 않는다. 재시도/취소 후속도 각각 입력으로 센다. 개발 리뷰와 일반 코드 재생은 출품 부모 입력으로 세지 않으며 별도 개발 사용량은 unknown이다.

## 검토·배포

같은 checkout의 tracked 코드/Git 작성자는 root 한 명이다. 읽기 전용 전문가가 diff·실제 receipt·원문/저장/최종 결과를 독립 검토한다. 실제 명령의 exit code·실패·timeout·미실행을 보존하며 설치/정적 검사를 native 품질 통과로 바꾸지 않는다.

변경·실측·제한을 기록한 뒤 제품 파일만 새 시험판에 배포한다. 원문/로그/DB/인증/개인 설정/평가 rubric/개발 체계는 제품 ZIP에서 제외한다. 기존 태그·팀원 코드·사용자의 별도 untracked 검토 문서는 보존한다. 원격 CI가 계정 결제/지출 제한으로 시작하지 못하면 로컬 통과와 구분하고 보호 규칙·청구·OAuth 범위를 자동 변경하지 않는다.

실제 결과는 [최종 검증 기록](../validation/final-eight-20261013.md)을 우선한다. 이 결정 문서 자체는 구현·실험·배포 완료 증명이 아니다.
