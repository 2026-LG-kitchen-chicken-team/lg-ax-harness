# 웹 연결을 준비하는 출품 하네스

2026-10-13 사용자 결정·실행 승인: 기획자가 클릭하며 작업하는 웹과 같은 결과를 읽는 보고서 HTML은 팀원이 구현한다. 이 작업은 하네스의 정형 결과·근거·조사/검토 이력 전달, 품질·위임·실행 검증을 맡는다. HTML/프론트는 수정하지 않는다.

## 출력과 시간

- 기본 업무는 현재 저장 버전의 정형 결과와 원문 근거를 일반 코드로 내보낸다. PDF/DOCX 자동 생성·렌더링·이미지 검수를 완료 필수 조건에서 제외한다. 기존 명시 report:true 파일 생성/복구 API는 호환 경로로 보존한다.
- 웹 전달 ready는 현재 결과와 지문·버전·실제 파일 결속의 코드 확인이다. 웹 연결·HTML 렌더링·시각 검수·원문 의미 승인을 인증하지 않는다. held/needs_input을 기획 해결 성공으로 바꾸지 않는다.
- 웹팀은 같은 정형 자료로 작업 화면·HTML 보고서를 만든다. 하네스는 자체 HTML UI·자체 모델 API·시각화용 모델 호출을 추가하지 않는다. 원문 자료의 PDF 독해와 출력용 PDF 생성은 구분한다.
- 조사·분석·검토의 폭을 줄여 시간을 맞추지 않는다. 새 업무 기본 안전 상한은 기존 허용 범위의 1800초로 정리하되 성능 목표로 쓰지 않는다. 과거 300/600초 목표는 이력이며 기존 요청의 시계는 변경하지 않는다. 실제 native 최종 답변/exit까지 자연 완료시간을 측정한다.

## 수행·증거

- 기본catalog는 empty. 실제 연구자료는 격리 평가에서만 사용하고 조사/등록/전달/신고 검토/의미/대표성을 구분한다.
- 메인1·업무Skill6·선택역할3. 부모만 업무 데이터를 작성하며 자식의 독립 조사/검토와 반영을 실제 native 결과로 확인한다. 역할 수·지침만으로 이점·OS 권한을 주장하지 않는다.
- G의 실행5건과 감사2건, 제공사 capacity 실패 및 미실행 prepared 질문을 보존한다. 변경 후 소스를 H로 구분하며 과거 PDF 경로 시간·점수를 옮기지 않는다.
- 기존 추가 입력 단계 상한24 중5사용/잔여19, 이전21 포함 누적45 이내를 유지한다. 새 단계로 카운터를 초기화하지 않는다. 새 source H의 입력도 같은 phase_counter에 기록하며 후속/취소/실패를 포함한다. 자동 재발송하지 않는다.
- 모델 권장은 동일 자료·품질·실제 최종 전달·반복 근거가 충분할 때만 확정한다. 불충분이면 검증한 범위와 남은 항목을 기록한다. Claude는 기존 유료 GUI 경로, 관련 창은 오른쪽이며 물리 Esc는 즉시 중단이다.

root가 primary checkout의 단일 작성자다. 읽기 전용 설계·독립 감사는 네이티브 위임하고 원본·소스 수정 권한과 기록 소유를 명시한다. 실제 명령/exit/receipt·독립 리뷰·제출 제한을 보존한다. 현재 계획은 구현·검증 완료 증거가 아니다.
