# 교수님 피드백 반영 방향 — HTML 보고서·시간 단축·실행 조건 고정

2026-10-12 KST. 사용자가 전달한 교수님 피드백과 “이 방향으로 나아가자”라는 승인을 기록한다. 교수님의 직접 녹취·메일을 받은 것은 아니며 **사용자 제공 피드백/새 개발 방향**이다. 공식 LG AX 요강을 변경하는 자료가 아니다.

## 사용자 전달 원문

> 1. 일단 프론트가 구리다고 함. 보고서에 들어가는 시각자료 사람들이 자주 쓰는 트렌디한 ui로 바꾸래.
> 2. 시간을 너무 오래 걸리는 요소들을 줄여야함
> 3. 굳이 글만 많은 보고서가 아니여도 좋으니, html 위주로 가독성 좋고 시각적으로 예쁘게 하라고 하심
> 4. 모델의 추론 수준도 하나로 고정해놓고, 모델 종류도 범위를 지정해놓고 해야함
> 5. html 예쁘게 꾸며서 시각적으로, 보고서 관련 UI 프론트 모두 다 참고해서 그걸로 반영
> 6. 시간이 오래 걸리는 요소들을 보완하거나 제거 해서, 시간을 줄이자. 우선 시간이 오래 걸리는 것들을 탐색부터 하고. 예를 들어 하네스에 웹(html)를 그려라라고 어떤 특정 skill 과 서브에이전트가 정의되어 있다면, 그거를 코드적으로 하던지 해. 코드적으로 하면 훨씬 줄어들잖아 시간이.

새 HTML 우선 방향은 과거 [독자용 전달 계약](../contracts/reader-deliverables.md)의 “HTML은 내부 경로, 최종 DOCX/PDF 기본”이라는 **향후 목표**를 갱신한다. 현재 v0.9.1의 API·파일 허용 목록·ready 검사는 여전히 과거 계약으로 동작한다. 문서에 방향을 기록한 것만으로 HTML 전달/설치 인수 완료라고 설명하지 않는다.

제품 구현·통합 PM 황대겸, 웹/Codex·Claude 연동 구현 최길웅, 발표/시연 정이량의 [소유 범위](team-ownership-20261012.md)는 유지한다. 이번 세션은 문서·코드 읽기·오프라인 진단이며 팀원 제품·웹 파일을 수정하거나 메일을 발송하지 않았다.

## UI 적용 기준과 후보

기본 화면은 다음 정보를 위에서부터 읽을 수 있게 만든다. 이것은 레이아웃 예시이며 특정 제품·질문 답안·기획 절 수를 고정하는 규칙이 아니다.

- 요청·대상 모델/시장·자료 시점·업무/검토 상태와 핵심 결론.
- 실제 자료가 뒷받침하는 핵심 불편/기회 카드와 기존 기능 대조.
- 제안 카드: 변경 내용·근거·기존 기능 중복 여부·실현/효과 미확인.
- 수치가 있는 경우만 단위/분모/조건이 보이는 비교표·차트.
- 펼쳐 읽는 원문·AI 요약/판단 구분, 출처 번호→정확 원문/자료집 셀.
- 관측 기록이 제공된 경우만 실행시간·Tool·usage. 저장 결과 재생과 실시간 관측을 구분한다.

외부 UI 후보의 역할은 디자인/렌더링이다. 어느 후보도 업무 추론이나 조사 정확도를 대신하지 않는다.

| 후보 | 공식 문서에서 확인한 기능 | 적용 조건·선택 기준 |
|---|---|---|
| [shadcn/ui Dashboard Blocks](https://ui.shadcn.com/blocks?category=dashboard) | React용 사이드바·카드·차트·표 화면의 공개 코드 | 웹팀이 React를 사용하면 직접 맞추기 쉽다. 기존 Python/정적 HTML 뷰어를 React로 전환해야 하는 필수 조건으로 채택하지 않는다 |
| [shadcn/ui Chart](https://ui.shadcn.com/docs/components/radix/chart) | Recharts 기반 구성, 공식 문서는 v3와 키보드/접근성 기능 설명 | 기존 React 화면의 차트 후보. 실제 데이터와 출처 연결은 별도로 구현해야 한다 |
| [Apache ECharts SVG SSR](https://echarts.apache.org/handbook/en/how-to/cross-platform/server/) | 일반 코드가 SVG 문자열을 렌더링해 파일로 저장 가능 | 복잡한 차트가 필요할 때 후보. Node 실행/번들·버전 고정이 추가되며 Python 설치 성공으로 가정하지 않는다 |
| 공통 HTML/CSS + 필요한 SVG | 현재 정적 뷰어와 연결 가능한 제안 | 가장 작은 의존성의 기본안. 검증된 저장 데이터로 렌더링하고 오프라인 동작·경로/링크·이스케이프·한글/인쇄를 검사한다 |

위 공식 문서는 2026-10-12에 열어 확인했다. 디자인 패턴 참고와 라이브러리 설치/채택을 구분한다. 이 작업에서 새 UI 라이브러리를 설치하거나 웹팀의 기술 스택을 교체하지 않았다.

기존 [PR #6](https://github.com/2026-LG-kitchen-chicken-team/lg-ax-harness/pull/6)의 정적 뷰어/훅과 [PR #7](https://github.com/2026-LG-kitchen-chicken-team/lg-ax-harness/pull/7)의 자료 관찰 화면을 먼저 대조한 뒤 하나의 공통 디자인 기준을 적용한다. 같은 내용을 다른 에이전트가 다시 기획하거나 다른 화면을 중복 제작하지 않는다.

## 모델·추론 수준 고정

- 출품 기준 실행은 Codex 한 가지로 우선 검증한다. 개발용 에이전트 모델 선택과 별개다.
- **첫 통제 검증 프로파일: `gpt-6.1-sol / high`.** 이번에 현재 로컬 사용자 설정의 두 필드만 읽어 이 값을 확인했다. 설치된 CLI는 `0.162.0`이다. 현재 환경과의 일치가 선택 근거이며 가장 빠르거나 최적이라는 입증은 아니다. 과거 실제 제품 두 실행(`0.162.1`)의 모델/추론 수준을 이 값으로 소급 확정하지 않는다.
- 모델·추론 수준은 테스트/시연 전체에서 같은 값으로 명시한다. 실행마다 제공사/모델/effort·CLI/제품/source 지문·Tool 접근 범위·사용량 기록 범위를 남긴다. 요청값과 실제 runtime 관측값을 구분하고 관측하지 못하면 unknown이다.
- 명시 실행 예: `codex exec --model gpt-6.1-sol -c 'model_reasoning_effort="high"' --json` 뒤에 실제 질문을 전달한다. 이 명령은 예시이며 이번 작업에서는 새 AI 업무 실행을 하지 않았다. `.codex/config.toml`의 개발 설정이나 사용자 전역 설정은 변경하지 않았다.
- 시간 측정 뒤 effort를 낮추는 것이 필요하다면 같은 모델·자료·업무로 별도 고정 후보를 검증하고 품질을 확인한 후 최종 프로파일을 한 번 변경한다. 한 시연/성공률 집계에서 서로 다른 설정을 섞거나 자동 모델 대체를 하지 않는다.
- Claude는 후순위 별도 환경 인수다. 실제 사용 가능한 정확 모델·고정 설정과 검증 버전을 확인하기 전 지원 완료로 추가하지 않는다. Gemini 제외 결정은 유지한다.

[OpenAI 설정 문서](https://developers.openai.com/codex/config-reference/)에서 `model`과 `model_reasoning_effort`를 확인했다. 지원 수준은 모델/클라이언트마다 달라질 수 있다. [Reasoning 문서](https://developers.openai.com/api/docs/guides/reasoning)는 낮은 effort가 속도·토큰에 유리한 일반 경향을 설명하며 특정 상품기획 결과의 품질/시간 개선을 보장하지 않는다.

## 구현·인수 순서

1. **병목 계측:** 같은 실제 실행의 시작→웹 검색/수집→등록/조회→기획/검토→저장→HTML 제작→추가 출력→최종 전달 시간을 나눈다. 겹친 병렬 span을 더하지 않고 호출·재시도·오류와 미측정 구간을 보존한다.
2. **반복 작업 제거:** 중복 조회·전체 원문 재출력·원문을 AI가 다시 복사한 보고서 계획·불필요한 이미지 생성·요청하지 않은 파일 형식을 우선 검토한다. 정확 모델/출처·검토·저장 무결성 검사는 유지한다.
3. **공통 HTML 렌더러:** 기존 저장 결과/검증된 원문/보고서 계획을 재사용하고 CSS·도표·출처 번호/목차는 코드로 생성한다. AI는 근거 판단·기획·필요한 설명을 맡는다. 특정 질문 정답은 템플릿에 넣지 않는다.
4. **동일 버전 연결 인수:** 기존 PR와 충돌 없이 전달 계약·Skill 설명·출력 허용 목록·패키징·오류 복구를 변경하고, 실제 일반명/모델명/후속/보류/수집 실패를 확인한다.
5. **고정 환경 촬영:** 결정한 모델/effort·제품/웹 버전을 고정해 실제 입력→저장/화면/원문 연결을 녹화한다. 빠르게 편집한 화면과 실측 시간·usage를 구분하고 측정하지 않은 절감률은 쓰지 않는다.

사람 비교는 제외하며 새로운 측정 회신을 요청하지 않는다. 이 기록의 방향/후속 인수 항목을 구현 완료·최종 제출 완료로 바꾸지 않는다.
