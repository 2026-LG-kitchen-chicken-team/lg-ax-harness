## 6. 시각·편집·표현 지침

- 실제 사용 흐름은 FocuSee로 녹화하고 원문·결론·클릭 위치에 필요한 확대·커서·spotlight·자막을 적용한다. 공식 가이드에서 해당 기능을 확인했다([FocuSee](https://focusee.imobie.com/guide/), 2026-10-16). 설치 버전·계정 기능은 제작 전에 확인한다.
- Higgsfield는 소개·사용 상황·장면 전환의 보조 연출에 사용한다. 실제 UI·출처·숫자·역할 반환 장면은 정확한 기록으로 제시한다([Higgsfield 편집 안내](https://higgsfield.ai/ai-video-editor), 2026-10-16). 구독 확인·새 영상 생성은 이번 작업에서 수행하지 않았다.
- 내레이션은 사용자 선택 음성 확정 뒤 제작한다. 장표는 한 결론·한 주요 화면 또는 차트를 중심으로 구성하고, 수치 조건은 화면에서 읽을 수 있는 각주로 제공한다. 사실·기대효과·검증 계획을 문맥에 맞게 표현한다.
- 모델 비교는 O CSV에서 직접 차트를 만든다. 자료수는 후기 발췌/사실을 색으로 구분하고, 역할은 실제 타임라인·반환·수정 반영을 연결한다. 설치시간을 AI 업무 속도 절감률로 쓰지 않는다.
- 웹·보고서·대시보드의 서체·상태색·제품명·결과 버전·출처 표기를 함께 검수한다. 진행 화면은 실제 단계/마지막 사건·대기 원인을 보여주며 근거 없는 진행률·완료 예정 시각을 만들지 않는다.

## 7. 제작 인수·접수 점검

1. **화면 마감:** W의 로딩/오류·동일 결과·원문/보고서·대시보드 전환 검수. 수정은 웹팀 소유 범위에서 반영하고 촬영 버전 동결.
2. **촬영:** 장면마다 실제 run·source/data·model/effort·원본 시각·클립 시각·대사·평가 연결을 기록. 기존 실행 기록 조회와 새 AI 실행을 구분.
3. **편집:** 실제 화면·자막·각주·음량·개인정보 가림·생성 연출의 용도를 점검. 핵심 원문과 결과가 확대/커서에 가리지 않는지 확인.
4. **발표:**26장 상세판·부록과 현장 선택 경로를 만든다. 옛 check-submission-preparation.py의20장/전체600초 강제를 상세판·현장판 분리 검사로 갱신한다. 현재 초안을 최종 자료로 덮어 쓰지 않는다.
5. **재생:** 삽입 영상·외부 링크·폰트·음성·클릭 이동을 실제 발표 환경에서 확인. 인터넷 없이 로컬 영상 재생이 가능한지 검사. 최소2회 리허설의 실제 총시간과 수정 내역 기록.
6. **접수:** 제출자·접수 경로·파일명·크기·코덱·미디어 삽입 조건을 확인하고, 상세 발표/삽입 영상/제품 및 소스 ZIP의 버전·SHA·권한을 대조.10/20 18시 전에 업로드·접수번호/완료 화면 확인. 공개 예약을 접수로 대신하지 않는다.
