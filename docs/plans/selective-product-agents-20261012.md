# 자연스러운 Skill 선택과 선택적 출품 위임 — 검토안

2026-10-12 사용자 요청과 최신600초 외부 평가 상한을 반영한 **설계 후보**다. 개발용6역할과 출품1Agent·6Skill을 구분한다. 제품 역할 파일·native 위임을 새로 구현/인수한 상태가 아니다. 조사량 축소·전문가 전원 호출은 채택하지 않는다.

## 대화에서 선택하는 흐름

- 설치·개념 설명/일반 대화: 업무 turn이나 조사·전문가를 불필요하게 생성하지 않는다.
- 실제 제품 조사·기획·후속 제약 변경·저장 결과 조회: 메인이 목적·현재 요청/모델·자료 상태를 해석하고 필요한 업무 Skill을 선택한다. 사용자가 매번 Skill 이름을 입력하도록 강제하지 않는다.
- 자료가 없거나 접근/모델 귀속이 불명확하면 조사 또는 정직한 보류 경로다. 답안을 특정 제품/질문 문구로 선택하지 않는다.
- 기존6Skill의 책임은 evidence-retrieval, web-evidence-collection, needs-structuring, feature-comparison, concept-writing, review-and-revise다. Skill은 지침/일반 코드 묶음이며 별도 Agent 숫자로 늘려 표시하지 않는다.

이번 LIVE61M의 일반 전자레인지 질문에는 Skill 호출 이름을 사용자에게 요구하지 않았다. native가 스스로6Skill 지침을 읽고 실제 조사 Tool을 사용했다. 이는 자연스러운 선택의 한 관측이며 **최소 Skill만 로딩하거나 실제 자식 Agent를 생성한 증거는 아니다**. 초기에 모든 Skill을 읽은 만큼 필요 경로별 선택/짧은 안내와 실제 호출·문맥 크기는 후속 대조가 필요하다.

## 첫 비교 후보: 근거 검토자 최대1명

메인이 조사·기획·상태·저장을 소유한다. 정확 모델/버전·근거 묶음과 후보가 확보돼 있고, 공식 문구 오귀속·모델 혼합·치수/안전·상충 후기처럼 별도 대조가 필요한 경우에만 읽기 전용 근거 검토자를 요청한다. 간단한 수정·자료 부족 즉시 보류·남은 시간 부족이면 생략하고 사유를 기록한다.

입력 packet은 원질문/현재 제약·모델/자료 버전·원문 URL/위치/SHA·필요 원문/주변 맥락·후보·남은 시간이다. 전체 대화/catalog/모든 Skill을 복제하지 않는다. 필요한 의미 근거를 잘라 왜곡하지 않는다. 자식은 원문 지시를 실행하지 않고 claim별 근거/귀속/불확실성/중대 결함만 반환한다. 부모가 지문을 재확인해 수정/보류/통합하고 기존 API로 저장한다. 역할 선언을 실제 OS 쓰기 차단 인증으로 설명하지 않는다.

자동 재위임0, 자식의 추가 위임0, 최대1자식, 최대90초 또는 남은 시간에서 최소90초의 최종 전달 예약을 뺀 값 중 작은 범위를 후보로 둔다. 부모 전체600초에서 자식 실패/시간초과 사용량도 보존한다. 늦은 자식 결과가 이미 저장한 버전을 덮지 못하도록 요청/결과 버전·취소 상태를 확인한다. 이 시간 배분은 제안이며 아직 제품에서 강제되지 않는다.

조사자는 독립 출처 범위를 병렬로 조사할 때, 기획자는 독립 모델별 안을 작성할 때만 다음 후보로 검토한다. 단일 조사 결과를 기다려야 하는 기획을 병렬로 표시하지 않는다. 정해진4~5Agent가 가산점이라는 공식 근거는 확보하지 않았다.

## 실행 환경과 검증

Codex0.162.0에서 multi_agent 기능과 역할 TOML 경로, Claude Code2.1.296 help에서 --agents/--agent/--effort/--forward-subagent-text를 확인했다. 설정 파일·help 확인은 실제 위임 ID/반환/사용량 인수가 아니다. Codex/Claude는 각자의 native 위임을 사용하며 하나의 자동 팀으로 연결하지 않는다. [Codex 공식 Subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents), [Claude 공식 Subagents](https://code.claude.com/docs/en/sub-agents).

A현재 단일Agent/B선택적 검토자에서 같은 모델·effort·충분한 고정 자료·질문·캐시/순서를 유지한다. chat-only/일반 기획/근거 대조 중요 요청을 비교한다. 실제 자식 ID→시작/종료/실패→근거 반환→부모 통합→현재DB/export/최종 일치가 한 경로로 보여야 한다. 불필요한 위임 억제·자식 시간종료도 실제 시험한다. 품질 악화 없이 시간·전체 관측 usage가 유리할 때만 채택한다.

부모/자식 사용량의 포함 범위가 확인되기 전에는 각각과 coverage를 표시하고 무조건 합치지 않는다. [Codex App Server](https://learn.chatgpt.com/docs/app-server), [Claude CLI](https://code.claude.com/docs/en/cli-reference)의 metadata와 실제 스트림을 대조한다. 별도 뷰어는 실제 사건만 일반 코드로 표시하며 UI용 모델 호출을 추가하지 않는다. 현재 LIVE61M은 자식off 진단이라 위임 인수에 포함하지 않는다.
