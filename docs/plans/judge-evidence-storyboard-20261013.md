# 평가항목을 증명하는 시연영상·발표 기획

**2026-10-16 갱신:** 현재 제작 원본은 [A–Z 전체 증거·제출 상세판·현장10분 계획](submission-master-20261016.md)이다. 아래 H/I의 모델 권장 보류·역할 반환 미관측·웹 연결 대기·초기 자료수는 당시 이력이며 O/S/U/설치기와 [W 현황](../validation/frontend-readiness-W-20261016.md)이 갱신한다. 실제 PPT/영상 제작 완료를 뜻하지 않는다.

2026-10-13 사용자 선택: 발표자료 안에 시연영상을 삽입하는 제출 구성을 사용한다. 냉장고를 대표 시연으로, 전자레인지·식기세척기를 확장 사례로 구성한다. 대표 제품·불편·기획안과 촬영 버전은 실제 검증 결과로 확정하며, 내레이션 방식은 아직 미정이다. 영상은 삽입 재생을 검수하고 편집용 원본·독립 출력본도 보존한다. 제출 규격 확인 후 영상 삽입 방식의 별도 영상 제출 생략 조건을 적용한다.

최신 [운영진 공지 전달](../consultation/2026-10-13-submission-notice.md)을 우선한다. 2차 제출용 발표·시연자료는 분량 제한이 없고, 발표자료 영상 삽입 시 별도 영상 제출을 생략할 수 있다. 본대회28일은 발표·시연 합계10분이며 실제 시연을 녹화 영상으로 대체할 수 있다. 아래5분 영상/18장 구성은 제작 초안이지 공식 분량 제한이 아니다. 제출용 상세 근거와 본대회10분 편집본을 같은 버전의 기능·근거로 준비한다.

2026-10-13 사용자 요구: 각 평가항목과 토큰 가산점에 대해 우리 구현의 무엇을 어떻게 했는지 직관적으로 보여준다. 영상은 편집·대사·자막·실제 화면으로, 발표는 결론·도표·근거 구성으로 같은 주장을 전달한다. FocuSee와 Higgsfield를 활용한다. 아래는 기획이며 촬영·제작·구독/설치 인수 완료가 아니다.

[확인한 제출 안내 C01–C09](../competition-requirements.md)를 기준으로 한다. 교수 피드백은 사용자 승인 방향, 외부 우승 전략은 미검증 참고자료다. 4~5 Agent 필수·무제한 반복·미측정 절감률을 추가 요구로 만들지 않는다. HTML/프론트는 웹팀 소유이며 새 화면을 중복 제작하지 않는다.

## 구성 원칙

각 어필은 `평가항목 → 한 문장 주장 → 실제 구현 → 같은 실행의 증거 → 화면/편집 → 대사 → 발표 장표`로 연결한다. 장면별로 원본 입력, 제품/웹/source/data/model/effort, 실제 run ID, 원문 위치, 로그 사건, 현재 저장·export·산출물을 묶는다. 자료가 없는 장면은 촬영 대기다. 아래 대사는 조건을 충족한 최종 결과로 다시 작성하는 초안이다.

심사위원이 처음 보더라도 문제·사용자 입력·판단 근거·수행·결과·활용을 따라갈 수 있게 한다. 평가항목을 나열하는 설명만으로 끝내지 않고 각 주장 옆에서 실제 화면을 보여준다. 공개 계획/decision_notes로 판단 이유를 설명하고, Agent·Skill·Tool을 서로 다른 대상으로 표시한다. 전체 원문/로그를 읽게 하기보다 핵심 구간을 확대하고 출처를 따라갈 수 있게 한다.

## FocuSee·Higgsfield와 시각자료의 역할

- FocuSee: 실제 화면 원본 녹화·핵심 영역 줌/커서 강조·spotlight·텍스트/화살표·자막·오디오/편집. 질문, 원문 출처, 근거 대조, 오류 상태, 최종 HTML/파일을 읽을 수 있게 만든다. 자동 줌은 원문 문맥이나 중요 상태를 가리지 않는지 사람이 확인한다. [공식 가이드](https://focusee.imobie.com/guide/), [annotation 기능](https://focusee.imobie.com/guide/annotations.htm).
- Higgsfield: 오프닝, 사용 상황 설명, 장면 전환, 필요한 카메라 움직임과 분위기 연출. 실제 UI·수치·원문·실행 결과는 정확한 녹화/일반 코드 자막으로 유지한다. 생성 장면은 실제 제품 기능·실물 효과·에이전트 실행 증거가 아니다. [공식 camera controls](https://higgsfield.ai/camera-controls), [video editor](https://higgsfield.ai/ai-video-editor).
- HTML/도표/모션 설명: 웹팀의 최종 화면과 검증한 데이터를 사용한다. 원문→판단→기획 연결, 실제 실행 timeline, 필요한 수치 차트, 핵심 결론 카드에 공통 색·서체·번호를 적용한다. 관찰/시각화는 일반 코드로 처리하며 시각화용 모델 호출·업무 문맥을 추가하지 않는다.
- 내레이션·음악·효과음·자막: 한국어의 직접적인 설명으로 기능을 이해시키고 핵심 문구를 화면과 동기화한다. 배경음은 말과 알림을 가리지 않게 조정한다. 모든 도구 기능을 넣기보다 해당 주장과 증거를 잘 이해시키는 요소를 활용한다.

2026-10-13 공식 제품 페이지/가이드의 기능 목록을 확인했다. 해당 Windows 설치 버전·사용자 구독·계정에서 기능이 제공되는지, 프로젝트 교환/최종 합성·한글 자막·출력 옵션은 실제 환경으로 인수한다. 라이브러리·플러그인·모델을 추가로 채택하거나 구독을 결제한 기록이 아니다.

## 발표자료 — 본문14장·검증 부록4장 제안

18장 초안이며 페이지 수 상한은 적용하지 않는다. 제출용은 필요한 상세 근거·검증 부록을 확장한다. 본대회 합계10분에서 영상 약5분+설명4분30초+전환30초를 초기 리허설안으로 삼고 실제 가독성과 설명 필요에 맞춰 조정한다. 발표와 영상의 같은 설명을 길게 반복하지 않는다.

1. 팀·제품명·한 문장 가치.
2. 실제 고객 문제와 상품기획 업무의 입력 부담.
3. 원문/사용 조건/기존 기능/남은 불편 대조.
4. 이번 기획 결과와 미확인 조건.
5. 메인·선택 역할·Skill·Tool·저장 구조.
6. 문맥에 따른 선택·권한·수정/실패/취소 계약.
7. 대표 업무 입력→실행→결과 및 시연영상 재생.
8. 핵심 조사·등록·전체 원문 전달 기능.
9. 원문·버전·현재 결과 검증과 같은 버전 복구.
10. 코드 처리·캐시·compact receipt의 토큰 가산점 근거.
11. 동등 품질의 모델/effort·완료시간·usage 비교와 한계.
12. 세 제품군 재실행·다른 업무 적용 조건.
13. 기대 효과의 검증 계획·지원/자료/의미/화면 한계.
14. 구현 결과·확인한 가치·제출물 연결.
15. 부록: 최종 실행 환경·모델·effort·source/data 지문.
16. 부록: 정상/후속/오류/취소 평가 결과와 미실행.
17. 부록: 정확 출처·원문/자료집·실제 검수 증거.
18. 부록: 실행/설치·소스/Skill·영상·요구 대응표.

각 장은 하나의 결론과 이를 뒷받침하는 화면/표/도표를 중심으로 구성한다. 긴 본문과 전체 로그는 부록·근거 파일로 연결한다. 사용자가 제공한 제안서 내용, 공식 요구, 새 기획, 실측을 구분한다.

## 제작 전 인수와 완료 검사

1. 최신 제품/웹/모델·effort/자료 범위를 동결하고 대표/후속/예외·타제품군의 실제 근거를 확보한다. 조사 역할은 native 위임/반영 이점 확인 뒤 해당 장면을 촬영한다.
2. 장면별 증거표를 채운다: 주장, 항목, status(confirmed/pending/unverified), 같은run ID, 원본 영상 timestamp, 로그/원문/export/파일, 제한, 대사, 발표번호.
3. 15초 오프닝+20초 실제 본편 샘플로 정보 가독성·한국어 자막·나레이션·음량·브랜딩을 확인하고 원본 연속 녹화/편집 프로젝트를 보존한다.
4. 웹 실패 시 같은 모델/시점/범위/충분성이 맞는 보존 원문으로 새 분석할 수 있는지 확인하고 사용 모드를 표시한다. 보존 자료에서도 부족하면 held를 전달한다. 자료 재사용과 지난 결과 화면 재생을 구분하며 원문 확보가 오프라인이어도 모델 통신이 불필요해지는 것은 아니다.
5. 편집/배속·합성·설명용 구조도·저장 재생을 표시한다. 개인 계정/키/경로는 가리고 핵심 원문·자료 부족·오류·실측 경계를 숨기지 않는다.
6. 최종 영상·발표·README·코드/Skill·ZIP이 같은 버전의 같은 기능을 설명하는지 대조한다. 실제 영상 규격/마감/제출 경로와 영상 삽입 재생을 확인하고 본대회 발표·시연 합계10분 리허설과 재현 검사를 완료한다. 질의응답5분은 기존 안내의 기록으로 유지한다.

현재는 기획표/대사 초안 단계다. 최신 근거는 [웹 전달 하네스 검증](../validation/web-ready-harness-20261013.md)을 따른다. H/I 실제 실행·현재 데이터 전달·선택 역할 관측을 확보했지만 모델권장·역할 이점·시장 대표성/실물 효과·토큰 절감률은 입증하지 않았다. 웹팀 실제 연결/HTML 가독성·영상 촬영/편집·슬라이드 제작/삽입 재생·합계10분 리허설·최종 접수는 미완료다. 각 평가항목을 설명할 근거가 있다는 것과 공식100점/가산점 충족 판정을 구분한다. 이 기획표를 제작 완료 증거로 사용하지 않는다.
