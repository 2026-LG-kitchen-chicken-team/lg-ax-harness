# 실제 업무 시연 준비 — 세 제품군

**2026-10-16 최신:** 실제 촬영·제출 구성은 [새 전체 제작 계획](../docs/plans/submission-master-20261016.md)과 [현재 웹·보고서·진행 화면 점검](../docs/validation/frontend-readiness-W-20261016.md)을 따른다. 냉장고 대표·나머지 두 제품군 확장, 자연어/명시 Skill·실제 역할 반환·웹/보고서·원라인·OS별 경로·모델/추론 비교를 포함한다. 제출 상세판은 분량 상한 없이 현장 발표·시연만600초 이내로 제작한다. 아래 초기 자료수·대기·설치·과거 수치는 당시 이력이다. 현재 실제 발표는12장 초안/영상0이며 새 촬영본이 아니다.

2026-10-11 현재 [12쪽 발표 초안](presentation/kitchen-planning.pptx)·[독립 HTML](presentation/presentation.html)·[525초 구성](demo-plan.json)을 준비했다. 실제 시연 영상과 시간 리허설은 미완료다. 이번4입력의 첫 업무 실행은249.09–341.62초, 후속189.55초였다.10분 발표에 세 업무 모두 실시간 완료를 약속하지 않는다.

## 준비와 핵심 장면

검증한 제품ZIP을 레포 밖 새 폴더에 추출한다. `uv sync --locked`, `uv run python product-doctor.py` 후 실행자 자신의 로그인된 Codex로 질문한다. 기존 DB/결과/로그를 덮어쓰지 않는다. 권한·모델 접근과 파일 설치 검사는 별개다. [Codex 검증](../docs/validation/codex-product.md)의 실제 전체 접근 모드/Windows 준비 실패 한계를 유지한다.

정상 핵심은 MWJ25E의 실제 후기→공식 기능→새 부품 없는 조건부 개선기획이다. 질문 예: `MWJ25E의 실제 불편을 찾아 기존 기능과 비교한 개선안을 한 개 기획해줘. 새 부품 없이 적용할 구현 단계와 효과 검증 방법, 사업 가치와 한계를 포함해줘.` 사용자에게 상세 불편·내부 ID 입력을 강제하지 않는다.

1. 실제 사용자 입력·정확 모델·자료 버전을 보여준다.
2. 동일 실행의 Skill 지침 읽기와 `open_request_bundle`/Tool 실행, source_id·짧은 원문·URL/위치를 연결한다.
3. 자기 수령품 사례와 기존 조작 기능을 대조한다. 불편의 원인·전체 제품 결함·현재 미해소는 확정하지 않는다. 현재 점검과 중복/실행 가능성은 검증 대상이다.
4. 구현 단계·동일 완료 품질의 기준선/지표/방법/채택 기준·사업 가치 가설을 보여준다. `planned_not_measured`를 실측 효과로 바꾸지 않는다.
5. 검토·저장의 accepted/status/version과 최종 receipt/export 일치를 보여준다. 코드 승인과 원문 의미·실물 효과 검증을 분리한다.
6. 원문 한 건 이상을 모델·위치·날짜/귀속/표현 범위와 대조한다. 같은 작성자의 두 모델 후기를 독립 고객2명으로 세지 않는다.

## 부족 정보와 후속

MWJ25E 내부 공식 W×H×D322×228×335mm는 입구·회전판·안전 여유·재질을 뜻하지 않는다.260×210×160mm 용기에 대해 회전/가열 안전을 승인하지 않는 실제 K02를 보여준다. 냉장고의 외형을 내부 치수로 변환하거나 식기세척기 내부 치수를 만들어 넣지 않는다.

DUBJ2EA K03→K04는 같은 native/session·prior_turn을 유지한다. 재배치·부품 분리 금지를 후속으로 추가하면 이전 결과의 현재 유효성을 무효화하고 새 제약에 맞는 안내/기록 초안을 별도 turn에 남긴다. 이전 후보·검토·출처를 삭제하지 않는다. 단종·설명서/중복 미확인·미측정 효과를 함께 표시한다. 부족 시 안을 채우지 않는 held와 모델 모호 needs_input은 기존 실제 인수 기록을 이용한다.

의도한 오류/공격/취소 시험은 합성 계약시험으로 표시한다. 고객 시장 근거로 쓰지 않는다. 실패/timeout·거절 후보는 보존하고 녹화 문제로 업무를 자동 재실행하지 않는다.

## 두 창과 편집

기존 Codex 화면 약60%, 별도 관찰 프로그램 약40%를 함께 녹화할 계획이다. [관찰 연결](../docs/validation/observer-langfuse.md)·[장애/재생 인수](../docs/validation/closure-progress-20261011.md)와 실제 화면 녹화 검증을 구분한다. 관찰은 일반 코드이며 설명용 모델 호출이나 로그 문맥을 추가하지 않는다. 구조 정의·실행 사건·저장 기록 재생을 구분하며 Skill을 Agent로 늘리지 않는다.

같은 실행 ID·갱신 시각·관측 범위·상태·저장/최종 전달을 표시한다. 입력과 캐시/비캐시, 출력과 그중 reasoning의 포함관계를 유지한다. 미관측 중간 토큰은 미측정이다. token_count 사건이나 명령 수를 모델 호출 수로 세지 않는다. 계정·인증·개인 경로를 가린다.

먼저30초 두 창 시험으로 한국어·글자 가독성·cursor/zoom·음성·MP4·가림을 확인한다. 현재 native Windows 컴퓨터 제어/녹화 도구 연결을 이번 환경에서 실행하지 못했으므로 실제 녹화 완료를 기록하지 않는다. 배속/대기 생략은 실제 경과 시간과 편집 사실을 표시한다. 보존 trace/export를 보여주면 `실행 기록 조회/재생`으로 표시한다. 준비한 결과만 출력하는 영상을 전체 과정 시연으로 제출하지 않는다.

## 발표의 고정 주장

- 메인 Agent1개·업무5Skill+조건부 조사1Skill. 개발6역할/9Skill과 별도다.
- 세 제품군5모델·후기8발췌·공식 사실26개. 새로운 두 가전은 같은 개인 작성자, 구매/협찬/대표성 미확인. 단종 모델 기존 사용자 지원 가설이다.
- 실제4입력은 새 자료에 대한 비맹검 진단이며 일반 심사 성공률/수백 질문 대비 성능을 뜻하지 않는다. 최종 manual family 경계는 native 동결 뒤 코드 검사 범위다.
- 토큰은 v5.4 R01 각2회에서 일반 대비 입력3.01배·비캐시11.22%증가·출력27.59%감소·AI시간25.40%감소다. 전체 비용/사람 공수 우위를 입증하지 않는다. 새4입력은 baseline 없음. 오래된 유리한 비교만 선택하지 않는다.
- 기대효과/사업 가치는 지표와 확인 계획을 제시한다. 사람 시간·청소 효과·시장/제조·전체 청구는 미측정이다.
- Claude 파일 설치 검사와 native 업무 지원은 별개다. 최길웅 검증은 하네스 완료 후 요청한다. Gemini 지원은 철회했다. 웹팀 개발 중/원본 인수 전 상태를 유지한다.

운영진 최신 영상 길이·코덱·해상도·크기·실제 파일 마감·경로·파일명·변경 공지·가산점 방식을 확인한다. 공개10월21일 심사일을 제출 마감으로 바꾸지 않는다. 실제 발표10분/질의응답5분·영상 삽입 시간을 리허설로 확정한다.
