# 실제 업무 시연 준비

발표·영상의 준비 원본이다. 아직 발표 파일·영상·실제 시간 리허설을 완료하지 않았다. [14쪽 구성](demo-plan.json)은 570초 계획이며 실제 실행 시간을 측정한 기록이 아니다. 사용자 선택에 따라 Codex 업무 폴더에서 실행하고, 별도 관찰 화면은 구현 전이므로 시연 항목에 넣지 않는다.

## 새 환경 준비

개발 레포에서 README의 설치기를 실행해 레포 밖의 새 Codex 업무 폴더를 만든다. 설치 폴더에서 `uv sync --locked`, `uv run python product-doctor.py`를 실행하고 실행자 계정으로 Codex를 연다. 기존 설치 폴더·DB·로그를 덮어쓰지 않는다. 준비 검사와 모델 계정·권한·업무 품질은 별도로 확인한다. 현재 Windows workspace-write 명령 실행 준비 실패와 실제 전체 접근 모드 인수 한계는 [Codex 검증](../docs/validation/codex-product.md)을 따른다.

녹화에는 실제 질문, Skill 선택/본문 읽기와 Tool 명령, 원문, 결과 저장·export, 최종 답변이 같은 실행에 속한다는 사실을 포함한다. 계정 정보·개인 경로·인증 값을 가린다. 화면을 가리기 위해 모델에게 별도 설명이나 로그 요약을 생성시키지 않는다.

## 정상 업무 입력

> B502S33을 쓰는 2인 가구가 장보기 후 냉동 식재료를 정리하려고 해. 새 부품을 추가하지 않는 개선안 2개 이내를 기획해줘. 현재 불편, 기존 기능, 근거와 미확인 사항을 함께 설명해줘.

확인할 장면:

1. 실제 사용자 입력과 정확한 모델 선택. 상세 불편·내부 식별자를 사용자에게 요구하지 않는다.
2. `open_request_bundle`의 모델 scope, 자료 버전과 원문 refs. 실제 후기 중 상충 의견을 함께 읽는다.
3. 원문에 연결한 불편, 같은 모델의 기존 기능, 남은 문제와 기획 가설. AI의 supported 보고만으로 의미가 증명됐다고 설명하지 않는다.
4. `save_reviewed_result`의 accepted·status·version. 실패나 수정이 생기면 이력에 포함한다.
5. `export_session`의 경로·SHA·건수와 최종 답변의 저장 일치. export 전체를 모델 문맥으로 재전송하지 않는다.
6. 인용 원문 한 건 이상을 URL·위치·모델과 대조한다. 후기 발췌는 고객 발생률·시장 규모를 입증하지 않는다.

기존 S05 R01 개선 실행은 316.70초였다. 구성의 140초를 라이브 완료 시간으로 약속하지 않는다. 새 실행의 전 과정을 녹화하고 대기 구간을 편집하면 화면에 실제 경과 시간·편집 사실을 표시한다. 보존 trace·export를 보여주는 장면은 **실행 기록 재생**으로 표시한다. 준비한 최종 결과만 출력하는 영상은 실제 과정 시연을 대신하지 않는다.

## 보류·후속 입력

T876MQQ012의 외형 치수만으로 내부 용기 배치를 확정하라는 입력에서는 내부 치수 부족과 보류 사유를 보여준다. 정확한 내부 폭·선반 간격을 임의로 만들어 넣지 않는다. [실제 질문](../evals/judge/s05-cases.json)의 R04를 그대로 사용한다.

R06은 첫 질문 뒤 같은 native 대화에서 변경 조건을 입력한다. 업무 session·prior_turn을 유지한 새 사용자 turn, 이전 결과의 현재 유효성 변경과 불변 후보 이력을 보여준다. 같은 turn의 실패를 새 키로 바꿔 수정 횟수를 초기화한 것과 구분한다.

원문 지시문·의도한 오류·취소 시험은 **합성 계약/오류 시험**으로 별도 표시한다. 이 시험을 실제 고객 불편·시장의 근거로 사용하지 않는다. 로컬 취소 상태와 실제 CLI/원격 모델 중단을 구분한다.

## 발표에서 유지할 사실

- 업무는 메인 Agent1개·Skill6개다. 개발 역할6개·개발 Skill9개를 출품 Agent 수로 설명하지 않는다.
- 전후 두 사례에서 관측 입력42.58% 감소와 실행별 시간 합계2.09% 증가를 함께 제시한다. 강한 일반 프롬프트의 토큰·시간이 더 적었으며 baseline 대비 품질·비용 우위는 미입증이다.
- Codex 실증 범위와 Claude/Gemini 파일 준비 검사를 구분한다. 새 코드의 일반 회귀나 합성 시험을 과거 실제 제품 평가 전체의 재통과로 바꾸지 않는다.
- 사람 공수·전체 청구·물리 개선 효과는 미측정이다. 청소 불편·내부 유효 치수는 미확인이다.
- AI 직접 입력 평가는 업무 질문이며 발표자 질의응답5분과 별개다. 발표 Q&A는 검증 범위·일반 프롬프트 대비 가치·자료 부족 대응을 현재 근거로 답한다.

최종 영상 길이·코덱·해상도·크기·실제 파일 마감·제출 경로·파일명은 운영진 최신 안내로 확인한다. 팀 제안서의 10월20일·5분 시연 계획을 공식 조건으로 사용하지 않는다.
