# 조건·순서·부정의 의미 대조

공통 규칙은 main과 해당 Skill에 있다. 이 문서는 표현이 애매할 때만 읽는 일반 반례다. 실제 제품·사용자 답안이나 새 실행 단계가 아니며 모든 문구를 복제할 필요가 없다.

## 일반 반례

| 구분 | 가상의 원문 | 허용되는 압축 | 의미를 바꾸는 압축 |
| --- | --- | --- | --- |
| 사건 순서 | 상담 전에는 기록을 읽지 않았다. 상담 중 기록을 읽고 설명했다. 현장 확인은 하지 않았다. | 상담 중 기록 확인 후 설명했으나 현장 확인은 없었다. | 기록을 읽지 않고 설명했다. |
| 적용 조건 | 모드 A를 사용하며 설정이 기준보다 낮으면 값을 조정한다. 다른 모드에는 이 조치를 적용하지 않는다. | 모드 A에서 설정이 기준 미만인 경우 조정하는 안내다. | 값을 올리면 해결된다. |
| 부정의 대상 | 자료 검토는 했지만 장비 시험은 하지 않았다. | 자료 검토와 미실시 장비 시험을 구분한다. | 아무 확인도 하지 않았다. |
| 판단과 검증 | 담당자는 허용 범위라고 설명했다. 효과는 아직 측정하지 않았다. | 담당자의 설명이며 효과는 미측정이다. | 안전성과 효과가 검증됐다. |
| 섹션 간 조건 | 기능 설명은 환경 B에서만 적용된다고 명시한다. 제안 가정에는 B가 적혀 있다. | 기존 기능 요약에도 환경 B 적용 범위를 남긴다. | 기존 기능은 모든 환경에서 적용된다고 요약하고 가정의 B로 이를 보완한다. |
| 불명확과 부재 | 보유 발췌에서 특정 기능의 설명을 찾지 못했다. | 보유 발췌 범위에서 기능 유무는 미확인이다. | 기능이 없다. |

같은 사건을 시간순으로 다시 읽고 각 부정이 어느 주체·행동·시점·조건에 적용되는지 대조한다. 전후 관계가 인과의 근거는 아니다. 설명자의 직함만으로 발언을 승인하거나 반대로 실제 부정 경험을 지우지 않는다. 조건 확인이 안 된 부분은 unknown/uncertain 또는 기획 가정으로 남긴다.

## 저장·최종 전달 대조 기준

1. 연결 원문의 주체·행동·대상·시점/순서·부정 대상·적용 조건·확인 상태를 확인한다. 의미 판단에 필요 없는 원문 전량 복제나 새 필드를 요구하지 않는다.
2. 요약, pains, existing_features, remaining_pains, concepts, requirements/assumptions, decision_notes를 각각 읽는다. 관련 주장을 담은 문장 자체가 필수 조건을 유지하는지 확인한다. 별도 한계 섹션은 앞선 단정을 복구하지 않는다.
3. 축약/수정 후 원문과 다시 대조한다. 현재 저장 버전과 completion_summary.text, 실제 최종 답변도 같은 범위여야 한다. 최종 답변만 고쳐 저장 오류를 가리지 않는다.
4. 잘못된 순서·부정 확장·조건 삭제가 불편/기능 해소/필요성의 결론을 바꾸면 해당 주장과 그 제안을 수정하거나 보류한다. 남은 근거로 지지되는 안, 조건부 기획·향후 시험 자체는 실패로 세지 않는다.

instruction 검사 통과는 실제 본문 전달·설치·분량의 확인이다. source_id/SHA·검토 신고·구조 필드는 의미 보존을 인증하지 않는다. 새 native 평가에서는 입력→원문→각 저장 섹션→현재 completion→최종 답변을 같은 업무/버전에서 독립 대조하고, 실패/수정 전 결과와 미검토 범위를 따로 남긴다. 이 문서의 예시를 통과한 사실로 실제 업무 전체 품질을 주장하지 않는다.
