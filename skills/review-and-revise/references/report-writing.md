# 독자용 자료집과 보고서

2026-10-13 전달 원칙: 기본 코드 구성으로 먼저 생성하고, 별도 구성에만 title/summary/sections와 sources:[]를 사용한다. 원문·URL·버전·상업성 metadata는 코드가 원본에서 채우므로 모델이 다시 직렬화하지 않는다. 제공한 source metadata와 원문이 충돌하면 오류를 유지하고 원본을 대조한다. sources:[]는 자료를 제외하거나 block.source_ids를 없애라는 뜻이 아니다. 렌더링/파일 SHA 검사는 실제 페이지 이미지 검수와 별개다.

자료집·보고서를 작성할 때 적용한다. 공개 작성 계약은 프로젝트 루트 `docs/contracts/reader-deliverables.md`다. 합성 목업 검수로 하네스를 완료 처리하지 않는다. 실제 제품의 새 조사·분석·검토·저장·보고서 전달을 확인한다. 가상 원문과 수치를 업무 근거로 복사하지 않는다.

## 요청과 근거

실제 요청과 수행한 조사 범위에 맞춰 절·문단·표·도표를 구성한다. 페이지·목차·파일 수를 고정하거나 빈 종류별 자료집을 만들지 않는다. 확보한 자료 종류별 원문은 XLSX에, 연결된 설명이 필요한 조사는 DOCX에, 최종 보고서는 편집 가능한 DOCX와 PDF에 담는다. 자료명·모델·문서 버전·관측일·원문 위치와 클릭 가능한 URL 또는 원문 셀 링크를 제공한다. 내부 source_id·snapshot_id·receipt·JSON·검수 기록은 독자용 폴더 밖에 보관한다.

원문 직접 인용, 저장 요약, AI 해석·제안을 구별한다. 인용은 실제 확보한 연속 구간 그대로 쓰며 원문 말투·맞춤법은 교정하지 않는다. 사용 조건·긍정/상충 의견·중복 여부와 모델 귀속의 한계를 보존한다. 일부 후기의 언급을 독립 고객 수나 전체 발생률로 바꾸지 않는다. 모델·도구·사용량은 실제 관측한 범위로만 귀속한다. 파일 생성과 내용 검수는 AI 의미 품질·실물 시험·효과 측정의 인증이 아니다.

요청했지만 수행하지 못한 내용만 `unfulfilled_requests`의 실제 request/reason으로 연결한다. 요청하지 않은 미확인 목록·추가 질문·조사·효과 실적을 채워 넣지 않는다. 필요한 조건은 해당 문장이나 숫자 옆에 구체적으로 표시한다.

## 글·표·차트

구체적인 제목과 읽을 수 있는 문장으로 사실을 설명하고 필요한 해석·판단을 잇는다. 긴 설명을 슬래시로 연결하지 않는다. 인원/비율처럼 병렬 수치는 `151명 / 62.9%`로 쓸 수 있으며 원문 수치를 바꾸지 않는다. 문법·어절·띄어쓰기·조사와 문장 순서를 확인한다.

흰 본문·검정 글자·회색 보조선을 기본으로 한다. 중요한 숫자와 그 숫자의 막대·점·부채꼴은 `#B42318`로 강조한다. 표에는 제목, 옅은 회색 머리글, 외곽/내부 선, 합계 윗선을 통일한다. 같은 표의 합계 대상·분자·분모·포함/제외 기준을 밝혀 숫자를 대조한다. 한 후기를 복수 분류했다면 언급 합계를 고객 비율로 바꾸지 않는다. 엑셀은 여백·열 폭·행 높이·정렬·줄바꿈·인쇄 범위를, Word는 표 머리글 반복·행 유지·여백·출처 연결을 설정한다.

보고서에 컨셉·시연 이미지를 생성하거나 삽입하지 않는다. 개선안은 문장과 표로 설명하고, 실제 수치를 확보한 경우에만 데이터 도표를 쓴다. 제목·소제목·본문은 글자 크기·굵기·문단 간격으로 구별한다. summary와 paragraph에는 중요한 결론·숫자에 한해 `**굵게**`, 보조 강조에는 `*강조*`를 쓸 수 있다. 실제 원문 인용 문단은 `style:"quote"`로 구별하며 인용 표현을 바꾸지 않는다. 원문 XLSX와 출처 목록의 리터럴 문자열에는 본문 서식 해석을 적용하지 않는다.

실제 숫자 관계에 맞춰 bar/line/pie/donut/scatter를 선택한다. 수치 없는 자료의 그래프와 임의 통계는 만들지 않는다. 원형/도넛은 겹치지 않는 부분과 전체가 확인될 때만 쓴다. 차트마다 제목/단위, 본체/축/옅은 눈금선, 핵심 결과 캡션을 구획으로 나누고 필요한 범례와 출처를 제공한다. 기간·단위·분모가 다른 지표는 비교 이유를 설명하며 %와 %p를 구별한다.

## 출처 표시

본문 문단·표·차트 아래에는 `출처 [1], [2]`처럼 짧은 번호만 표시하고, 문서 끝의 `출처 목록`에 자료명·정확 원문 위치·모델/문서/관측 정보·웹 원문·자료집 셀 링크를 모은다. 같은 정보가 자료명에 포함돼 있으면 원문 위치를 다시 반복하지 않는다. 상세 수집 메타데이터와 전체 원문은 자료집에 그대로 보존한다.

번호는 렌더러가 보고서 전체의 첫 인용 순서로 부여한다. 같은 source_id는 같은 번호를 재사용하며, 같은 URL의 다른 절·사실·후기 발췌를 하나로 합치지 않는다. 작성자는 번호를 본문에 직접 입력하거나 출처를 삭제해 길이를 줄이지 않는다. 각 block의 source_ids 연결을 유지한다. DOCX/PDF 번호에서 해당 출처 항목으로, 출처 항목에서 정확한 웹 URL·자료집 파일/시트/셀로 이동하는지 확인한다.

## 저장과 전달

저장 전에 원요청의 각 작업을 실제 보고서의 문단·표·도표 또는 수행 불가 사유와 대조한다. 내부 검수에는 요청 구문 / 판단 근거 / 본문 위치를 기록한다. 요청한 분류나 비교를 조용히 생략하지 않는다. 예를 들어 실사용 경험·선호·기대를 구분하라는 요청이면 각 유형의 확인 결과를 본문에 명시하고, 해당 발췌가 없는 유형은 자료에서 확인하지 못했다고 쓴다. 같은 페이지의 여러 사실 항목은 독립 문서 수로 세지 않는다. held와 제작 성공을 따로 판단하며, 전달 가능한 파일이 있어도 요청 일부가 남거나 검토 지적이 남으면 해당 제한을 최종 답변에 밝힌다.

`report_plan`의 title/summary/sources/sections와 선택 unfulfilled_requests를 내부 JSON 파일로 작성한다. sources에는 검증된 전달 원문만 넣고 존재하지 않는 원문·통계를 추가하지 않는다. 원문 그대로인 sources와 근거를 연결한 blocks는 작성 계약의 스키마를 따른다. 전체 보고서를 업무 저장 JSON의 256KiB 제한에 맞춰 잘라 넣지 않는다.

시장 통계와 경쟁 문서는 대상 모델의 product_fact로 위장하지 않는다. 같은 요청으로 capture한 실제 snapshot을 `report_sources_path`로 연결하고 자료 대상·적용 범위·원문 위치를 명시한다. 상세 입력은 reader-deliverables.md의 시장·경쟁 맥락 계약을 따른다. 이 출처는 보고서 설명·자료집을 보강하며 대상 모델 ProductResult 근거를 대신하지 않는다. 가격·성능시험의 기간·조건·측정모델을 보존하고 전국 통계를 특정 제품 수요·불편 발생률로 바꾸지 않는다.

최종 저장의 기존 6필드를 유지하며 `save_and_export`에 `report:true`, 선택 `report_plan_path`(runtime-data 내부 작성 파일), `open_folder`를 전달한다. API 기본 report는 하위 호환을 위해 false다. 제품 Skill의 최종 출력에서는 true를 명시해 파일 제작을 함께 요청한다. open_folder는 보고서 요청 시 기본 true이며 사용자가 원하지 않으면 false로 둔다. JSON·감사 export는 내부에 유지한다.

업무 저장의 accepted/valid/현재 version과 delivery_ready, 보고서의 실제 ready/files를 각각 확인한다. 제작 실패는 저장 성공·수정 이력을 취소하지 않는다. 같은 session_id/turn_id/expected_result_version의 `deliver_result`에 선택 report_plan_path/report_sources_path/open_folder를 넣어 복구하고 새 업무 turn이나 기획 수정으로 세지 않는다. 재생 시 이미 제작된 결과를 중복 생성·열기 하지 않는다. 실제 ready 응답에서 확인한 결과 폴더와 파일을 짧게 전달한다. 의존성·제작 실패가 남으면 저장된 결과와 미완료 형식을 정확히 알린다.

본문·표·그래프의 숫자·단위·기간·분모, 원문 인용과 링크를 대조한다. 실제 Word/PDF 페이지와 Excel을 확인해 잘림·겹침·글자 깨짐·줄바꿈을 고친다. 미확인 레이아웃을 검수 완료로 쓰지 않는다. 파일 검수가 성공한 뒤 Windows 탐색기로 폴더를 열며 다른 OS에서는 경로를 전달한다.
